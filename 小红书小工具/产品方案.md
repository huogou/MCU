## 1. 产品定位

基于 MCU Atlas 数据体系打造的小红书**离线**漫威探索工具（小红书小工具载体，纯本地 Web 应用）。面向小红书泛漫威兴趣用户，提供轻量探索与可分享内容产出。

**事实**：小红书是以图文 / 短视频为主的社区；小红书小工具是 App 内沙箱 Web 容器，纯本地运行、不联网。
**观点**：漫威 IP 在小红书有稳定内容需求，但缺「结构化探索 + 一键出卡」工具，存在细分空白。
**概率判断**：需求成立度「中」，建议阶段3 后用小规模内容验证（不确定度较高）。

## 2. 用户画像

| 画像 | 特征 | 核心诉求 |
|---|---|---|
| 漫威新手 | 想入坑不知从哪看 | F1 观影顺序、F3 随机入门 |
| 老粉整理党 | 追过但记不清关系 | F2 宇宙节点、F1 时间线 |
| 内容创作者 | 做漫威相关笔记 | F4 分享卡片、F2 节点素材 |

## 3. 核心功能模块拆解

### F1 漫威观影顺序
- 输入：维度选择（官方释出顺序 / 故事时间线 / 推荐入门路径）
- 输出：有序作品列表（标题、年份、阶段、关联节点）
- 数据：MCU_CONTENT + routes（离线 `data.js`）

### F2 宇宙节点探索
- 输入：节点类型（角色 / 事件 / 阶段）或关键词
- 输出：节点卡片 + 关系网（relations）
- 数据：MCU_CONTENT + relations

### F3 随机漫威探索
- 输入：可选过滤（阶段 / 类型）
- 输出：单条随机推荐 + 一句话看点
- 数据：MCU_CONTENT 全集随机抽取

### F4 生成漫威分享卡片（机制已澄清 D-20260928-04）
- 输入：F1/F2/F3 的探索结果
- 处理：客户端 **Canvas 2D** 渲染卡片位图 → `writeTempFile`（base64→filePath）
- 输出（二选一）：
  - `saveImageToPhotosAlbum` 存系统相册；或
  - `postNote` 唤起笔记发布页（图文，title≤20 字、content≤1000 字、图片 1–18 张）
- 视觉模板：设计规范 §3（设计 AI 阶段3 提供可 Canvas 渲染的布局规格）

## 4. MVP 范围（V1）

- 必含：F1–F4 基础形态，单载体（小红书小工具）。
- 暂不含：账号体系、收藏同步、社区互动、服务端。

## 5. 用户主流程

```
进入小工具 → 选择探索方式(F1/F2/F3) → 浏览结果 → [可选] 生成卡片(F4) → 存相册 / 发笔记
```
