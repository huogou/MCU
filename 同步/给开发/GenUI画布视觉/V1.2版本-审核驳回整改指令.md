# 给开发 AI · 审核驳回整改指令 V1.2（P0 紧急）

> **出具方**：设计 AI ｜ **日期**：2026-10-26 ｜ **优先级**：**P0 紧急（阻塞重新提审）**
> **触发**：百度 GenUI 分发审核驳回，理由两条——「视觉规范问题」「交互体验不佳」
> **依据**：`scratch/visual-f1-360.png`、`visual-f3-360.png`、`visual-b-360.png` 三张 360px 实拍截图逐帧分析
> **目标**：一次整改覆盖全部驳回点，避免二次驳回（平台限制：提审后需等审核通过才能再次发布）

---

## 0. 驳回根因总览

设计 AI 对三张 360px 截图的审核视角复盘，定位出 **4 个视觉规范问题 + 3 个交互体验问题**。按审核员观感严重度排序：

| # | 视图 | 问题 | 驳回理由归属 | 严重度 |
|---|---|---|---|---|
| V1 | F1 | 当前项推荐理由文字被滚动边缘**硬切一半**，切口紧贴金色推荐条 | 视觉规范 | ★★★ |
| V2 | B | 档案卡信息区**大片空白**，底部孤立黄色小块被裁切 | 视觉规范 | ★★★ |
| V3 | F3 | 无海报影片的程序化卡 = 灰渐变 + 极淡罗马数字，**像图片加载失败** | 视觉规范 | ★★★ |
| V4 | 全部 | 画布下部 30-40% 高度**空置**，内容集中在上半部 | 视觉规范 | ★★ |
| I1 | F3 | 「换一部继续探索」浅灰文字，**无任何可点击暗示** | 交互体验 | ★★★ |
| I2 | B | 档案卡空白区**无操作引导**，点击无反馈区 | 交互体验 | ★★ |
| I3 | F1 | 时间轴节点可点击切换推荐，但**零视觉提示** | 交互体验 | ★★ |

> **核心判断**：V1.1 做"减法"时把呼吸感做成了"空置感"，把层级弱化做成了"可发现性消失"。审核员不是设计师，看到"空 + 素 + 灰"三个信号叠加，直接判定为半成品。

## 1. 视觉规范问题整改

### V1｜F1 时间轴文字被硬切（最严重）

**截图证据**（visual-f1-360.png）：「整个MCU的起点，它确立了这个宇宙的基调」一行文字下半截被金色「当前推荐」条直接切断，切痕锐利。

**根因**：`.mcu-timeline`（`flex:1; overflow-y:auto`）的可用高度只够显示当前项的部分内容，当前项 `.mcu-tl-note`（2 行）渲染到容器边缘被 `overflow` 裁切。金色 footer 紧贴裁切线，形成"文字被盖住"的观感。

**整改指令**：

1. `.mcu-timeline` 底部增加渐隐遮罩，让裁切线变成柔和过渡，消除"硬切"观感：

```css
.mcu-canvas {
  --mcu-fade-h: 14px;
}
.mcu-timeline {
  position: relative;
  /* 原: padding: 4px 16px 14px 16px; */
  padding: 4px 16px calc(14px + var(--mcu-fade-h)) 16px;
  mask-image: linear-gradient(to bottom, #000 0, #000 calc(100% - var(--mcu-fade-h)), transparent 100%);
  -webkit-mask-image: linear-gradient(to bottom, #000 0, #000 calc(100% - var(--mcu-fade-h)), transparent 100%);
}
```

> 注意：mask 加在滚动内容上会让滚动到底部时最后一项也被渐隐。**更稳的方案**是改用容器外层伪元素覆盖（不参与滚动）：
> 在 `.mcu-route-list-wrap`（若无需新增包裹层，则用 `.mcu-canvas::after` 定位到 footer 上方）加一条 14px 高、从透明到卡片底色的渐变条，`pointer-events:none`。

2. **当前项必须完整可见**：初始化及点击切换后，将当前项 `scrollIntoView({ block: 'nearest' })`，保证 `.mcu-tl-note` 两行完整出现在视口内，而不是半截。

3. 若 324px 高度下当前项（节点 + 名称 + 年份 + 阶段标签 + 2 行理由 ≈ 92px）确实放不下，**降级方案**：当前项理由从 2 行减为 1 行（`.mcu-tl-item.current .mcu-tl-note { -webkit-line-clamp: 1; }`），但**绝不允许出现半行截切**——完整的 1 行好过被切掉的 2 行。

**验收**：任意滚动位置，视口内不得出现被水平切断的文字行。

### V2｜B 档案卡空白区 + 孤立色块

**截图证据**（visual-b-360.png）：YEAR 2008 / PHASE 第一阶段 之下是约 60px 的纯空白，卡片底部一条浅黄色小块（约 8px 高）悬空，疑似被裁切的进度条或推荐理由区。

**根因**：`.mcu-archive` 用 `flex:1` 撑满剩余高度，但信息内容只占 2 行；底部黄色块是某个被压缩到只剩边的元素（疑似 `.mcu-archive-progress` 或理由区）。"大片空白 + 残块"是审核视角下的典型"渲染不完整"。

**整改指令**：

1. **先定位残块**：检查 B 卡渲染模板（约 L1449 起）`.mcu-archive` 内最后一个子元素是什么，确认那个黄色小块的类名。若是进度条，要么给足高度（≥4px 完整显示 + 两侧留白），要么整条移除——不允许"剩一条边"。

2. **空白区注入内容**，将「推荐理由」填充到 YEAR/PHASE 行下方：

```html
<div class="mcu-archive-meta">YEAR 2008 · PHASE 第一阶段</div>
<div class="mcu-archive-reason">
  <span class="mcu-archive-reason-label">★ 为什么看这部</span>
  <p>整个MCU的起点，它确立了这个宇宙的基调。</p>
</div>
```

```css
.mcu-archive-reason {
  margin-top: 10px;
  padding-top: 10px;
  border-top: 1px dashed var(--mcu-line);  /* 与 V1.1 F3 的虚线语言一致 */
}
.mcu-archive-reason-label {
  display: block;
  font-size: 11px;
  color: var(--mcu-archive-gold);
  font-weight: 600;
  margin-bottom: 4px;
}
.mcu-archive-reason p {
  margin: 0;
  font-size: 12.5px;
  line-height: 19px;          /* ≥1.4 倍行距，沿用 V1.1 验收指标 #6 */
  color: var(--cos-color-text-minor);
  display: -webkit-box;
  -webkit-line-clamp: 3;
  -webkit-box-orient: vertical;
  overflow: hidden;
}
```

3. 若填充后 324px 仍有多余空白，压缩 `.mcu-archive-visual` 高度上限（`max-height: 120px → 108px`），把空间让给理由区，而不是留白。

**验收**：B 卡内不允许出现连续 >24px 的无内容空白区；卡片底边不留残块。

### V3｜F3 程序化卡"像加载失败"

**截图证据**（visual-f3-360.png，奇异博士2）：灰色渐变 hero 区 + 极淡的罗马数字水印，无任何其他视觉锚点。审核员第一眼 = 图片没加载出来。

**根因**：无海报影片走程序化卡路径（L1513 `.mcu-discover-hero-roman`），但程序化视觉只有「灰渐变 + 淡字」，信息密度和色彩记忆点都不足以传达"这是有意设计"。

**整改指令**（保持零外部资源，纯 CSS 强化程序化卡的"设计感"）：

1. **渐变改为阶段色系**：无海报 hero 的底色从灰黑渐变改为当前影片所属阶段的阶段色深色渐变（阶段色 token 已存在于设计系统），让色相本身传达"这是第四阶段"：

```css
.mcu-discover-hero.prog {
  /* 示例：阶段色由 JS 按 m.phase 注入 CSS 变量 */
  background:
    linear-gradient(135deg,
      color-mix(in srgb, var(--mcu-phase-color) 88%, #000) 0%,
      color-mix(in srgb, var(--mcu-phase-color) 45%, #1a1d23) 100%);
}
```
> 兼容性兜底：若 GenUI 容器不支持 `color-mix`，由 JS 直接计算混色后的 hex 写入行内 style，不依赖运行时 CSS 函数。

2. **罗马数字加"底纹纹理"**：淡字之外叠加同心圆弧或胶片孔纹理（`repeating-linear-gradient`），密度提升后"故意设计的图形"感立现：

```css
.mcu-discover-hero-roman {
  /* 原: 极低对比度大字 */
  opacity: 0.16;
  text-shadow: 0 2px 12px rgba(0,0,0,0.35);
}
.mcu-discover-hero.prog::after {
  content: "";
  position: absolute; inset: 0;
  background: repeating-linear-gradient(90deg,
    transparent 0 10px, rgba(255,255,255,0.045) 10px 12px);
  pointer-events: none;
}
```

3. **程序化卡角落加「ARCHIVE」小标签**（与 B 卡的 FILM ARCHIVE 语言呼应），明示"这是档案视觉，不是加载失败"：

```html
<span class="mcu-hero-badge">MCU 档案</span>
```
```css
.mcu-hero-badge {
  position: absolute; top: 8px; right: 8px;
  font-size: 9px; letter-spacing: 1px;
  color: rgba(255,255,255,0.75);
  border: 1px solid rgba(255,255,255,0.35);
  padding: 2px 6px; border-radius: 3px;
}
```

**验收**：无海报影片的 hero 区，凭截图能看出"设计过的图形卡"，与真实海报卡并排不违和。

### V4｜画布下部空置

**截图证据**：三个视图的 1:1 卡片内，内容集中在上 60-70%，底部空置。

**根因**：V1.1 减法后内容总高度收缩，但画布容器仍是固定 1:1，剩余空间全部变成空白。

**整改指令**：

1. 允许信息区 `flex:1` 自然伸展 + 内容垂直居中（对 B 卡、F3 卡的 body 区），让留白均匀分布在元素间而不是堆在底部：

```css
.mcu-discover-body, .mcu-film-card { justify-content: space-between; }
```

2. **优先落实 V2 的理由区填充**——B 卡空白被内容占掉后，此问题自然缓解大半。F3 卡可将「换一部」提示条下方增加一行档案编号进度（如「今日已探索 3 / 38 部」），既填充又强化工具感。

**验收**：1:1 卡片底部无 >40px 连续空白。

## 2. 交互体验问题整改

### I1｜「换一部继续探索」可发现性为零（最严重）

**截图证据**（visual-f3-360.png）：底部提示条整行浅灰 11px 文字，无按钮形态、无箭头、无色彩强调。V1.1 把它从蓝色实心按钮降级成"脚注"，审核员视为**没有操作入口**。

**整改指令**（保留 V1.1 的"入口在卡片内"结构，但恢复可点击感知）：

```html
<div class="mcu-discover-foot" id="mcu-discover-foot" role="button" tabindex="0" aria-label="换一部影片">
  <span class="mcu-discover-foot-btn">
    <span class="mcu-discover-foot-icon">↻</span> 换一部
  </span>
  <span class="mcu-discover-foot-right">MCU-028</span>
</div>
```

```css
.mcu-discover-foot-btn {
  display: inline-flex; align-items: center; gap: 5px;
  font-size: 12px; font-weight: 600;
  color: var(--mcu-archive-gold);            /* 金色主强调，权重对齐 Tab 选中态 */
  background: var(--mcu-archive-gold-bg);    /* 金色浅底胶囊 */
  border: 1px solid var(--mcu-archive-gold-line);
  padding: 6px 14px;
  border-radius: 999px;
}
.mcu-discover-foot:active .mcu-discover-foot-btn {
  background: var(--mcu-archive-gold-line);  /* 按压反馈 */
}
```

**验收**：截图灰度测试——把截图转灰度后，「换一部」胶囊仍是画面上第 2 明显的可点元素（第 1 是 Tab 选中态）。

---

### I2｜B 档案卡空白区无引导

随 V2 整改自动解决：理由区填充后，空白区消失；同时给 `.mcu-archive` 整卡加按压态，暗示"这是当前推荐影片的完整档案"：

```css
.mcu-archive { transition: box-shadow 0.15s ease; }
.mcu-archive:active { box-shadow: 0 2px 8px rgba(0,0,0,0.10); }
```

若 B 卡有二级动作（如"查看所在路线"），在理由区底部加文字链；若无，不加，避免制造死链接。

---

### I3｜F1 时间轴可点击性无提示

**整改指令**：

1. 当前项节点已有金色高亮，补充**非当前项的点击暗示**：节点 hover/active 态 + 首屏首次渲染 3s 后当前项节点做一次 2 次脉冲动画（`box-shadow` 扩散），提示"节点可点"：

```css
@keyframes mcu-node-pulse {
  0%   { box-shadow: 0 0 0 0 var(--mcu-archive-gold-bg); }
  70%  { box-shadow: 0 0 0 8px transparent; }
  100% { box-shadow: 0 0 0 0 transparent; }
}
.mcu-tl-item.current .mcu-tl-node { animation: mcu-node-pulse 1.2s ease-out 2; }
```

2. 时间轴列表头部加一行 10px 灰色辅助文案：「点击节点切换推荐 · 点底部提示条看档案」，仅 F1 首屏显示一次，帮助审核员理解交互。
