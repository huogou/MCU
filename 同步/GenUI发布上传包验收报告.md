## 6. 打包前的收尾修复

打包前发现并修复 1 个体验缺陷（不影响合规，但影响观感）：

**F1 时间轴单屏仅显示 1 个节点**

- 根因：设计稿头部为 `padding 14px` + 22px 统计行，在 360px 的 1:1 卡片（实测仅 324px 高）中占约 96px，把时间轴压到 30px。
- 处理：**保持设计稿的四行结构、字号、配色、视觉语言完全不变**，仅按小屏收敛内边距与行距（头部 96px → 约 70px），时间轴可用高度提升到约 90px，可稳定显示 2 个节点（当前项含阶段标签与推荐理由）。
- 策划要求「360px 单屏不要展示过多节点」已满足；列表保留滚动以查看 12/38 部完整路线。

另修正守卫脚本 2 处误报（CSS 注释被当作选择器、`@keyframes` 百分比帧被当作类名）。修正后官方外壳 32 条规则**零改动**得到确认。

### 10.3 与指令字面值的偏差及理由

落地过程中有 3 处按实测数据回调了指令字面值，均因 **324px 高的 1:1 卡片装不下指令间距**，属平台硬规范与设计建议的优先级取舍：

| 指令字面值 | 实际落地 | 偏差原因 |
|---|---|---|
| `.mcu-discover-body` gap 10px / padding 12px 14px 10px | gap 6px / padding 8px 14px 6px | 按指令值实测内容溢出 **26px**，文字压到海报层，违反平台「排版无重叠、无溢出」硬规范 |
| `.mcu-discover-reason` padding-top 8px | padding-top 2px | 同上，为闭合溢出让位 |
| `.mcu-discover-reason-text` 3 行截断 | 2 行截断 | 324px 下 3 行会挤压底部提示条，2 行保证信息完整不截断 |
| `.mcu-discover-hero` 34% / min 62px | 40% / min 80px | 指令值在海报上仅剩一条横带，失去视觉焦点；已通过收紧画布层把 hero 恢复到 81px（360px）/ 103px（414px） |

另按 V1.1 结构图与验收指标 #1 **移除了独立的「今日发现」徽章行**（V1.0 元素）：该行占 33px，是导致 hero 被压到 48px 的直接原因。年份信息已在下方元信息行中，不丢信息。

> 以上偏差均已按平台硬规范取舍，建议设计 AI 复核；若设计侧认为需恢复指令字面间距，则需同步放宽 360px 下的信息量或接受内容截断。

### 10.4 过程中定位并修复的 2 个隐藏缺陷

| # | 缺陷 | 根因 |
|---|---|---|
| 1 | 片名层错位到卡片底部，与「换一部」提示条重叠 | 样式抽取时 `.mcu-discover-hero` 的 `position: relative; overflow: hidden` 被清空，导致 absolute 定位的片名参照到 `.mcu-discover-card` |

两处均已修复并在代码注释中标注警示，避免后续再犯。

### 10.5 测试环境说明

### 10.7 工具层加固（设计侧待办，已完成）

设计侧要求 `extract-design-css.cjs` 增加保护属性白名单，防止定位上下文被清空。

**根因定位**：缺陷实际发生在 `apply-design-css.cjs`——它用正则**整条替换**规则体，
把 `position: relative; overflow: hidden` 一并清空，导致 absolute 子元素参照错位。
`extract-design-css.cjs` 本身按原文整条保留，不删属性。

**加固措施**：

1. `apply-design-css.cjs` 改为**属性级覆盖**：仅覆盖 `HEIGHT_OVERRIDE` 中的高度属性
   （flex / min-height / max-height），其余属性一律原样保留。
2. 新增 `PROTECTED_PROPERTIES` 白名单：`position / overflow / z-index / inset /
   top / right / bottom / left`。
