## 2. 与现有「小红书小工具」的载体对比（策划决策关键）

两者**同属「纯本地、不联网、资源全打包」沙箱范式**，因此产品层可复用；但工程层差异大，必须分开排期。

| 维度 | 小红书小工具（现有） | GenUI（百度） |
|---|---|---|
| 技术范式 | 纯本地沙箱、不联网 | **同** |
| 注入 API | `window.xhs.miniTool` | `window.genui.sendLog({area})` |
| 视觉体系 | 项目自有 `设计规范.md` | **强制 cosui token + 照搬 layout.html / components** |
| 形态要求 | 平台沙箱，形态较自由 | **强制 1:1 正方形卡片、45px 表头「小工具·名称」** |
| 控件限制 | 相对自由 | **Tabs 限 1 次、滑动条 ≤4、底部按钮 ≤2、表头 icon ≤3** |
| 存储 | `localStorage` 等**可用** | **全禁，每次打开都是初始态** |
| 分享能力 | `saveImageToPhotosAlbum` / `postNote` | **无分享 API**（禁 `window.open`/外链/`postMessage` 出域） |
| 包体积上限 | 官方未明示（待核实） | **解压后 ≤ 8MB（明确）** |
| 分发场 | 小红书 App 内 | 百度搜索结果页 |
| 发布链路 | 小红书提审 | `genui publish` → 百度审核 |

### 2.1 复用与不可复用（避免重复劳动）

- ✅ **可直接复用**：F1 观影顺序 / F2 宇宙节点 / F3 随机探索 的产品定义与交互逻辑；数据单一可信源 `h5/data/*.js` 的构建期内置快照方案。
- ❌ **不可复用**：小红书 F4 分享卡片（GenUI 无分享 API）；现有视觉规范与自有组件（GenUI 强制 cosui 体系）。
- ⚠️ **需改造**：小红书侧依赖 `localStorage` 的状态持久化逻辑，GenUI 须全部改为内存变量。

## 3. 平台硬约束（红线，不可协商）

### 3.1 运行时（违反即被拦截或阻断）

- **完全自包含、不联网**：禁 `fetch`/`XHR` 产物外请求、`WebSocket`、`sendBeacon`、外链 `<script src>`、CDN、外链图片/字体/样式、`@import` 外部、`dns-prefetch`。
- **无存储**：禁 `localStorage`/`sessionStorage`/`indexedDB`/Cookie/Cache API；**每次打开都是初始态**。
- **禁运行时生成代码**：`eval`、`new Function`、字符串 `setTimeout`、`document.write`、`innerHTML` 插脚本、行内 `onclick`、`javascript:` URI。
- **禁越出展示区**：`iframe`、`window.open`、外部跳转、`target="_top"`、`postMessage` 出域、`alert/confirm/prompt`、`fullscreen`、Worker/ServiceWorker、Worklet、WebAssembly。
- **例外仅一处**：可调用 `window.genui.sendLog({area})`（`area` 取 `operation` / `custom`），调用前须判空。

### 3.2 产物结构

- 入口 `index.html` 必须在根目录、全小写、有且仅有一个；声明 `<!DOCTYPE html>` + `<meta charset="utf-8">` + viewport。
- 除 `index.html` 外**全部平铺 `static/`**；全部路径相对化。
- 后缀白名单：`.html .css .js .png .jpg .jpeg .gif .webp .svg .woff .woff2 .json`。
- **解压后总体积 ≤ 8MB**（按解压计，非 ZIP 压缩体积）。

### 3.3 视觉（与项目现有资产冲突最剧烈的一节）

- 1:1 正方形响应式，`padding-top:100%` + `absolute inset:0`，最小适配 360px，容器内无滚动条。
- 表头固定 **45px**，内容为「小工具 · 项目名称」，项目名 ≤10 字；右侧仅 icon 按钮（≤3 个，18×18，间距 18）。
- **形态 A**（画布+操作区）：骨架 1:1 照搬 `assets/layout.html`，画布占比 ≥50%。
- **形态 B**（整屏画布）：参考 layout，表头改为浮层，配色按画布明度二选一。
- 颜色一律用 `var(--cos-*)` token，**禁止**写死 hex、**禁止**在产物内重定义 `--cos-*`、**禁止**自行加 `prefers-color-scheme` 覆盖。
- 已提供的控件（按钮/滑动条/复选框/单选框/下拉/Tabs/开关/步骤条/气泡/图例）**必须照搬样式，不得自造替代**。

### 3.4 发布参数（五项，新增应用必填）

| 参数 | 限制 |
|---|---|
| `--name` 名称 | ≤10 字 |
| `--logo` | **256×256**、≤5MB、本地图片 |
| `--brief` 简介 | ≤15 字 |
| `--description` 摘要 | ≤50 字 |
| `--project-path` | 本地 HTML 或 ZIP |

流程：`genui preview`（必须，禁直接开 HTML 判断效果）→ `genui check` → `genui publish --dry-run` → 人工确认「确认发布吗」→ `genui publish --yes` 提交审核。**一旦发布需等审核通过后才能再次发布。**

## 4. 项目侧体积实测（关键风险，已实测）

> 实测环境：`D:\SEO\发挥余热\漫威电影宇宙导航`，2026-10-13。

| 项目 | 实测值 | 对 8MB 红线的影响 |
|---|---|---|
| `h5/data/*.js`（全部数据，单一可信源） | **0.19 MB** | ✅ 无压力，可全量内联 |
| `h5/assets/posters/`（38 张海报，2:3 ≥600×900） | **7.60 MB** | ⚠️ 单独已逼近红线 |
| `h5/assets/stills/`（38 张剧照） | **3.59 MB** | ⚠️ 超限 |
| `h5/assets/` 合计 | **12.49 MB**（124 文件） | ❌ **超 8MB 上限 56%** |

### 4.1 结论

- **数据层零障碍**：MCU 结构化数据仅 0.19MB，全量打包无压力。
- **图片层是唯一真实瓶颈**：海报单张均约 200KB。若全量打包 posters + stills = 11.19MB，**必然被 8MB 拦截**。
- 现有海报规格（≥600×900、单张 ≤500KB）是为 H5 站点设计，**不适用于 GenUI 的 8MB 预算**。

### 4.2 三条可选技术路径（供策划选）

| 路径 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| A · 精选打包 | 只收 V1 功能实际引用的海报（如 12–16 张），压缩至长边 480–600px | 改动最小、质量可控 | 覆盖面收窄，需策划定"哪几部" |
| B · 程序化生成 | 复用项目已有 `MCU.ui.posterFallback()`（阶段色+符号视觉卡）思路，Canvas 绘制 | 体积近零、无版权风险、与项目资产复用 | 视觉吸引力弱于真实海报 |
| C · 混合 | 主视觉用精选真实海报（路径 A），其余用程序化兜底 | 体验与体积平衡 | 需设计 AI 出规格，工作量中等 |

> 开发侧倾向 **C**，但**选哪条属产品决策，需策划拍板**（见 5.1）。
