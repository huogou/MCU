日期：2026-09-14
范围：douyin/ 当前工作区代码（V1.3.x，未改动）
方法：从审核员视角，对包内 UI 文本、数据字段、视觉素材做信号归类
结论置信度：高（基于源码实测；控制台填写的简介/关键词、提审截图属外部输入，无法从代码验证）

----------------------------------------------------------------
一、结论先行
----------------------------------------------------------------
1. 抖音审核的判类不是只看你"后台提交的类目"，而是：
      声明类目（控制台） ＋ 内容/图像识别（截图＋包内文本＋海报视觉）
   当"内容识别"结果与企业专属类目冲突时，会以内容识别为准并驳回。
2. 当前包内"文娱资讯"信号远强于"工具"信号 → 被识别为「文娱-资讯」
   （该类目仅对企业开发者开放）→ 驳回。
3. 关键利好：V1.2.0 曾通过「工具-实用工具-信息查询」资质审核，而该类目
   名称本身含"信息查询"，与本产品（查 MCU 作品信息＋观影顺序）天然吻合。
   所以"工具"类目是存在且被认可过的，问题大概率出在【声明类目选错】或
   【内容识别覆盖】，而非产品本质不可逆。

----------------------------------------------------------------
四、为什么审核识别成文娱而不是工具
----------------------------------------------------------------
- 产品的"实质"是：漫威影视资料库 ＋ 编辑体解读（简介/理由/角色小传）
  ＋ 海报视觉；查询/规划/进度只是套在这之上的"外壳"功能。
- 审核依据是截图＋包内文本＋图像，不是代码注释。海报墙＋作品简介＋
  推荐理由这三样组合起来，画像就是"影视资讯/导览"，而非"工具"。
- 你声明"工具"被内容识别覆盖，最终落到企业专属的「文娱-资讯」→ 驳回。
- 提醒：douyin/app.json 里没有 description / keywords 字段，这两项是
  在抖音控制台单独填的，同样是判类输入（源码看不到，需你自行核对是否
  也写了"资讯/影视/攻略"类措辞）。

五、V1.2 通过 vs V1.3 失败 的可能差异（待你确认）
----------------------------------------------------------------
假设A（最可能）：本次控制台"声明类目"实际是「文娱-资讯」而非「工具」，
              或被系统按内容自动带成了文娱。改回「工具-实用工具-信息查询」
              即可（该类目 V1.2 已通过资质，内容一致应通过）。
假设B：V1.3 相比 V1.2 新增了编辑体内容（如 characters.js 24 条角色解读、
              recommend 理由、synopsis），拉高了内容识别阈值。
假设C：抖音内容识别模型升级，对影视类更敏感（外部环境变化）。

=> 先验证假设A（零成本、最可能是根因）：打开抖音开放平台看该类目当前值。

----------------------------------------------------------------
六、下一步建议（本批不改代码，仅分析）
----------------------------------------------------------------
1. 【你操作】抖音开放平台 → 该小程序 → 类目设置，确认声明类目：
   若是「文娱-资讯」→ 改为「工具-实用工具-信息查询」→ 重新提审。
   （这是 V1.2 已通过资质的类目，内容未大改应通过）
2. 若改回工具后仍被内容识别覆盖：下一轮降"编辑体"密度——
   · synopsis 改为纯事实字段（年份/阶段/时长/导演），去掉串联解读
   · recommend.reason 改为中性提示（"按上映顺序下一部"），去掉安利体
   · characters.js 角色解读移出包或仅保留姓名（不渲染 note）
   此项需策划拍板，且会削弱产品"陪你探索宇宙"的调性，属权衡。
3. 企业开发者注册＝最后手段。且 MCU 是迪士尼版权内容，企业号同样需
   授权/版权证明，个人主体做迪士尼衍生内容本就高风险，不推荐。
4. 旁注：影视 IP 衍生内容还可能单独触发版权审核，与类目无关，需留意。
