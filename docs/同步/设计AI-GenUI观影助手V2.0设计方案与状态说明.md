## 一、方案要点摘要

**产品形态**：由 V1.0「观影顺序速查列表」重构为「**观影理由链**」——每条路线 = 1 页路线介绍（适合谁 / 为什么 / 怎么排 / 看完获得）+ N 页作品（每页 1 部，含推荐级别徽章 + 推荐理由 + 剧情作用 + 信息增量 + 后续关联）。

**页面结构**（自上而下）：官方 Header（冻结）→ 画布：页头（kicker + 片名/路线名 + 徽章）→ 字段区 → 页码条（◀ 当前/总页数 ▶）→ 官方 Tabs（3 路线入口，操作区）。

**关键结构决策**：
1. **每页 1 部作品**：4 个文字字段 + 1 个推荐级别徽章在 12px 可读行距（16px 行高）下，360 内容区 227px 内仅此方案可行；多部/页必然压成单行、破 12px 底线或砍字段，同时违反任务书三条硬约束。翻页成本由快速滑动 + 300ms busy 锁消解。
2. **介绍页作为第 1 页**：页码语义统一为「1/N」，总页数 = 1 + 作品数（新手入门 13 / 主线精选 19 / 复联5补课 9）；重置目标可描述为「新手入门 1/13」。
3. **transform 翻页而非滚动容器**：无滚动上下文、无惯性回弹，从机制上满足"页面禁止滚动、无横向溢出"，也不会触发浏览器手势干扰 Tabs。
4. **零省略号预算制**：字段字数上限由 build-data 构建期长度断言拦截，UI 永不 truncate——唯一能对"文字截断"硬约束做机制性保证的做法。
5. **两档同构**：360/414 共用字号/行高/行数预算，文案单一来源；414 每行 24 字（360 为 19），行数只减不增，验收口径一致。
6. **手势隔离**：滑动仅绑定画布轨道 + `touch-action:none` 物理隔离；Tabs 只响应 tap/键盘——滑动永不触发路线切换。

**视觉**：深色档案馆（画布 `#080B12`）+ 金色强调 `#F2B233`（母项目统一金，废弃 V1.0 档案金 `#b8860b`）；徽章三级形态（实心金=必看 / 描边金=推荐 / 中性面=补充）；字段标签 = 52px 金字小标签（视觉区分承载点），不堆装饰。

**V2.0-R1 修订摘要**（详见 §十）：① 分页进度感知增强——kicker 作品序号/总数（ITEM 02/12）+ 页码条内嵌 2px 金色作品进度条 + 跳转入口列为条件功能；② 12px 字体可读性实测复核（模拟手机视口，结论：360 最小口径下为合理下限）；③ 后续关联文案审查——建立关联类型/路线内下一站/措辞分级规则，修正 3 组示例措辞；④ 尺寸口径统一——冻结区合计 99px（表头 45 + 间隙 10 + 操作区 44）唯一口径；⑤ 复联5 表述全文统一为「禁止写入任何未经官方确认的未上映剧情」；⑥ 9 项待拍板全部转为已确认决策记录（§十三）。

**V2.0-R2 修订摘要**（ChatGPT 最终验收修订，详见 §十）：① 黑豹后续关联措辞收紧——「下一部《复仇者联盟3：无限战争》」统一为「关联《复仇者联盟3：无限战争》」（world 关联非剧情承接，即使路线内相邻亦不用"下一部"），措辞分级规则同步收紧（仅 sequel/prereq 可用"下一部/承接"）；② 字段数量术语全文统一为「4 个文字字段 + 1 个推荐级别徽章」（清除"5 字段"等笼统表述）；③ 复联5补课路线介绍修正——删"四环"（core 8 项无法与四环准确映射）改"按补课链条顺序"、删"8 部 = 最短路线"（无工具内比较证据）改"8 部精简补课路线"、"暴露于人"自然化为「为世人所知」、kw 标签去除"第 X 环"序号；④ 全文一致性复核通过（黑豹措辞/字段术语/补课阶段描述/360-414 尺寸口径/复联5 表述边界/测试边界）。

## 二、数据可得性与派生（技术顾问逐条核验结论）

- 三条路线去重后 **24 个唯一 id（25 个渲染条目，含洛基 S1/S2）**；全部条目均具备 `role` / `sf` / 推荐级别源（mainline / starter / importance）/ 后续关联源（next 或 relations 或 kw）。**无字段缺失级缺口**。
- 4 个文字字段 + 1 个推荐级别徽章 + 介绍页 4 块中 **≈90% 可由构建期自动派生**；需设计侧新撰的最小集合：新手入门「怎么排」1 条、主线精选「看完获得」1 条、黑豹/死侍金刚狼/美队4/雷霆特攻队等"路线要求看但非主线"条目的推荐理由覆盖规则（3–4 条短句）、brand-new-day 后续关联兜底（取 role"片尾直接连向《复联5：毁灭之日》"）、洛基 S1/S2 差异化各 1 句。
- data.js 体积估算：10.2KB → 23–28KB（ZIP 仍 <0.1MB，远低于平台 8MB 上限）。
- 冻结件：guard-frozen.cjs **预计零改动全部通过**（V2.0 只动 `.mcu-*` 自由区）；红线 = 保留 `onTabChange / resetDemo / sendLog / showTipsTooltip / adjustTipsTooltipPosition` 函数名与外壳结构。
- e2e-visual.cjs 需**改 3 项旧断言**（"列表可上下滑动"/"主线精选可滚动"/"切换后列表位置重置"→ 分页口径）+ **新增约 9 项**（无垂直滚动、页码正确、翻页正确、滑动不切路线、字段无截断、徽章三态、末页禁用、重置回默认、切路线页码重置）。

## 四、设计取舍记录（含冲突调和）

1. **每页 1 部 vs 每页多部**：产品经理早期稿曾建议"每页 3–4 卡"，经交互设计复核——4 个文字字段 + 1 个推荐级别徽章在 227px 内多卡必破坏可读性（单字段仅 ~20px = 1 行且字号破底）。**裁定：每页 1 部**（交互设计 §② 预算为证），产品经理 §2.3 的"每页 3–4 卡"表述作废，以本稿 §5.3 为准。
2. **金色取值**：V1.0 档案金 `#b8860b`（浅底）→ V2.0 深底改母项目统一金 `#F2B233`（对比度优 + 三端 Token 一致）。
3. **用户侧标签**：任务字段「推荐理由/剧情作用/信息增量/后续关联」→ 界面标签「为什么看它 / 它的作用 / 看完你会懂 / 后续关联」（大白话口径，与任务字段一一对应）。
4. **字段不对称行数预算**：剧情作用 3 行（数据密度最高、role 原文 30–54 字可直接容纳）、信息增量 2 行（短句式足够承载"新收获"语义）——按信息价值排序分配，非平均分配。
