■ 六、★ 本轮待你交付：H5 资讯模块 UI（这是新的设计任务）

背景：H5 将新增「最新漫威资讯」模块，产品规则已封版至 V2.2。
开发侧**只做实现、不做设计**，以下内容需要你先出视觉规格。

需交付（建议按第 2 点拆两页 + 1 入口）：
1. 【首页资讯入口】形态与位置
   - 建议方式：首页新增一个 section（同 community 的既有模式），而非改动全站顶部 NAV
   - 需明确：放第几位、卡片/列表形态、是否复用既有 v2- 组件
2. 【资讯列表页 news.html】视觉规格
   - 卡片结构、列表密度、是否分页或加载更多、空状态
   - 卡片须能承载：状态徽章 / 标题 / 摘要 / 报道方 / 日期 / 关联 MCU 节点
3. 【资讯详情页 news-detail.html】视觉规格
   - 信息块顺序：状态 → 摘要 → 相关报道列表 → 官方确认情况 → 原始来源 →
     状态变更记录 → 查看原文
   - 需专门设计两种特殊形态：①来源冲突时的并列展示 ②发生更正/官方否认时的显著标注
4. 【★ 8 态状态徽章】视觉定义（本次设计的重点）
   - 状态清单（文案由规范给定，你只需定视觉，不要改写文案）：
     官方已确认 / 多家媒体报道 / 单一来源报道 / 传闻·爆料 / 信息待核实 /
     信息存在冲突 / 官方已否认 / 来源已更正
   - 请给出配色与形态，并**优先复用既有 Token**（success / error / gold / 文字三级），
     不建议为资讯模块新增 Token
5. 【响应式三档】沿用 H5 既有 ≤375 / 376-390 / ≥411；PC（≥1024）是否单独排布请一并说明
6. 【前缀契约】建议 `v4-`（延续 v2-/v3f- 顺序）或另定，请明确后开发按此实现

必须遵守的边界（产品规范硬性要求，非设计偏好）：
- **禁止出现真实性/可信度百分比**（如「真实性 87%」），不得制造虚假精确感
- **禁止绝对化措辞与实时性暗示**：官方确认也不能写成「永不变化」；不得用「刚刚」「N 分钟前」
- 官方确认的语义是「截至当前已获得的来源层级」，视觉上不应呈现为「终局裁定」
- 第一阶段**不使用任何第三方媒体封面图**，统一使用占位图（素材形态请一并给出）
- 本模块定位是「可信度可追溯的信息卡」，**不要做成普通新闻门户**；
  用户应能快速看懂：这条来自哪里 / 有几个独立来源 / 有没有官方确认 / 是否存在争议

三个必答问题（本文件第 8 条铁律要求）：
① 影响哪几端 → 仅 H5（第一阶段；微信/抖音本期不做资讯）
② 是否触碰审核红线 → 不触碰（不涉及小程序端，无新增动效与流媒体观感）
③ 是否涉及 Token 变更 → 期望不涉及（复用既有 Token）
