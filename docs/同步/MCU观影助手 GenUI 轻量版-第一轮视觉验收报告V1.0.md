## 三、问题清单（P0–P3）

### P0：页面结构或核心视觉严重错误
**无。**

### P1：明显偏离设计稿
**无。**

### P2：细节问题（可选调整）

**P2-1 · 列表滚动 affordance 偏弱（唯一实质建议）**
1. 对应截图：`route1/2/3-360px` 与 `-414px`（列表区域）
2. 具体位置：列表区（`.mcu-order-list`）末行下缘
3. 当前表现：滚动条隐藏（`scrollbar-width:none`）、底部无渐隐遮罩（`mask: none`）；仅靠"第 6 行半行裁切（360 视口露出约 6px）"与文字提示传递可滚动信息
4. 设计稿要求：设计稿未强制渐隐（实现与设计稿一致，此项属体验优化而非偏差）；设计稿提示行文案「列表可上下滑动」已提供文字层面的指引
5. 偏差原因：设计稿原稿以"结构示意"呈现列表，未规定滚动视觉反馈
6. 修改建议（可选）：`.mcu-order-list` 增加底部 8–10px 渐隐（`-webkit-mask-image: linear-gradient(to bottom,#000 calc(100% - 8px), transparent)`）并同步 `padding-bottom: 10px`，保证最后一行滚到底时不被渐隐吞没；成本约 3 行 CSS

### P3：主观优化 / 文档一致性建议

**P3-1 · 设计稿账单口径差（仅文档，不涉及界面）**
设计稿按保守估算写明"内容区 227px（360）"，实现实测为 **261px（360）/ 315px（414）**，列表可视 **5.5 行 / 7.19 行**（设计稿预算 4.4 / 6.1 行）。原因是设计稿按操作区 56px 估算、实现为 44px。方向为正（显示更多条目），**建议后续更新设计稿账单数字以保持一致，无需任何界面改动**。

**P3-2 · 「剧」标签与年份间距 8px（记录，不建议改）**
与行内其他间距（gap 8px）完全一致，视觉协调；截图分析曾疑其"过近"，经实测为统一间距，判定无需调整。

## 五、可以接受、不需要修改的项目

1. **裸页面容器无圆角/背景/边框**：`--cos-*` token 由平台注入，真实环境正常，非缺陷
2. **截图画面下方空白**：截图环境（无平台容器页面）所致，产品卡片自身 1:1 紧凑，非缺陷
3. **阶段色点跨路线颜色不同**（第四阶段紫、第五阶段绿等）：设计意图——六色对应六个 MCU 阶段，非"不统一"
4. **洛基 S2 年份 2023**：设计稿明确指定；开发报告已标注数据口径来源与回退方案，属数据口径决策
5. **列表末行半行裁切**：滚动 affordance 的自然表达，且与文字提示互补
6. **「剧」标签使部分行片名容器变窄**：flex 自适应实现正确，年份/阶段列坐标不受影响
