# MCU 观影导航 H5 · 后续论坛扩展方案

> 目标：V2.1 阶段只保留「入口 + 静态话题预览」，真实论坛功能延至 V3.0。本方案为 V3.0 立项时参考，避免技术债。

## 1. 演进路线（建议三阶段）

| 阶段 | 形态 | 用户能力 | 数据形态 |
|---|---|---|---|
| V2.1 | 静态入口 + 策划话题 | 仅浏览 4 张话题卡，点击提示筹备中 | `h5/data/community.js` 静态数组 |
| V3.0-MVP | 半静态社区 | 浏览官方/ curated 话题、点赞、简单评论 | 后端只读话题表 + 轻量点赞/评论表 |
| V3.5+ | 轻 UGC 社区 | 用户发帖、回复、投票、举报 | 完整话题/帖子/回复/投票/审核表 |

## 2. 数据模型（V3.0-MVP 建议）

```
topics          话题表
  id, title, tag, desc, coverUrl, createdAt, sortOrder, status

topic_stats     话题统计（避免实时 count）
  topicId, viewCount, likeCount, replyCount, updatedAt

replies         一级评论
  id, topicId, userOpenId, content, createdAt, status

likes           点赞（用户 + 话题 或 用户 + 回复）
  id, userOpenId, targetType(topic|reply), targetId, createdAt

user_fav_topics 用户关注的话题（可复用 V2.1 的 want_to_watch，迁移到此表）
  userOpenId, topicId, createdAt
```

说明：
- V2.1 的 `want_to_watch` 字段可直接迁移为 `user_fav_topics` 的初始数据。
- 不引入「关注用户」「私信」「粉丝」等重社交能力，保持工具/图鉴定位。

## 3. 接口设计（供后端参考）

- `GET /api/community/topics` — 话题列表（分页）
- `GET /api/community/topics/:id` — 话题详情 + 评论列表
- `POST /api/community/topics/:id/like` — 点赞/取消点赞（幂等）
- `POST /api/community/topics/:id/reply` — 发表评论
- `GET /api/community/trending` — 热门话题（替换 V2.1 的静态数组入口）

## 4. 前端改造点

1. `h5/data/community.js` 改为：优先尝试 API，失败回退到本地静态数组。
2. `components.js` 新增 `topicList()` / `topicDetail()` / `replyCard()`，保持 `v2-` 前缀。
3. `index.html` 社区区入口：点击话题不再 toast，而是跳转到 `community/topic.html?id=xxx`。
4. 小程序端（微信/抖音）按同一数据契约各自实现话题列表/详情页。

## 5. 合规与审核

- 个人主体小程序无 UGC 类目资质，因此 V3.0 真实评论/发帖必须在 H5 端承载；小程序端保持只读话题列表。
- H5 端如开放评论，必须接入：
  - 文本敏感词过滤
  - 用户举报入口
  - 评论先审后发 或 关键词自动屏蔽
- 继续规避「视频播放/直播/流媒体」视觉风格，防止小程序侧再次误判。

## 6. 与本项目原则的对齐

- 单一数据源：shared/data/*.js 的 MCU 内容数据不变；社区数据单独成层，不与作品内容耦合。
- 无 CMS 让用户改 MCU 内容：社区后台只管理话题/评论，不碰 movies/routes/relations。
- 设计先行：V3.0 社区页由设计 AI 出方案，开发 AI 执行，策划 AI 验收，继续走三通道同步文件。
