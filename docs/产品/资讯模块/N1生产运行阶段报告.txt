§1 策划裁定落地结论（D1 / D2）
----------------------------------------------------------------
【D1｜dry-run 是否写 run-history】
- 裁定：dry-run 是纯模拟，不写 run-history、不落任何生产持久化数据、无持久化副作用。
- 落地：run-modes.requiresRunHistory(m) = isProduction(m)；orchestrator 仅在 !isDry 时调用 RH.record。
- 验证：验收 1（dry-run）runHistoryRecorded=false、run_id=null、run-history 数量不增加、不产生任何文件（含 scratch）。PASS。

【D2｜生产业务数据持久化开关】
- 裁定：production-* 默认不持久化业务数据；仅显式 --persist 才正式落盘；run-history 属运行审计记录，
  与业务持久化解耦，production-* 必写；dry-run+--persist 语义冲突必须拒绝。
- 落地：run-modes.checkPersistConflict 在 dry-run+persist 时抛 PARAM_CONFLICT；
  orchestrator 仅在 persist=true 时调用 CS.appendCaptures / CandS.appendCandidates / 写 deliveries 预览。
- 行为矩阵（代码实现，与裁定一致）：
    dry-run                         → 业务落盘 NO  / run-history NO
    production-capture              → 业务落盘 NO  / run-history YES
    production-capture  + --persist → 业务落盘 YES / run-history YES
    production-review               → 业务落盘 NO  / run-history YES
    production-review   + --persist → 业务落盘 YES / run-history YES
    production-delivery-preview     → 业务落盘 NO  / run-history YES
    production-delivery-preview+--persist → 业务落盘 YES / run-history YES
- 验证：验收 2–8 全 PASS（含 dry-run+--persist 拒绝、production-* 写 run-history、--persist 才落盘）。
