# 三、必须修复的 5 处

## P1｜脚本清单不完整 —— 必须修

### 问题

此前规范中部分位置只列出了：

- movies
- series
- special
- short
- content
- news

但实际资讯页面需要与现有标准页面一致，完整加载 MCU 数据脚本。

如果缺少：

- `characters.js`

则 `related_characters` 渲染时可能出现 `MCU_CHARACTERS` 未定义。

如果缺少：

- `posters.js`
- `stills.js`
- `visuals.js`

则相关数据访问/组件取图函数存在运行风险。

### 正确最终顺序

`news.html` 和 `news-detail.html` 均使用：

```html
<script src="data/movies.js"></script>
<script src="data/upcoming.js"></script>
<script src="data/relations.js"></script>
<script src="data/routes.js"></script>
<script src="data/characters.js"></script>
<script src="data/series.js"></script>
<script src="data/special.js"></script>
<script src="data/short.js"></script>
<script src="data/content.js"></script>
<script src="data/posters.js"></script>
<script src="data/stills.js"></script>
<script src="data/visuals.js"></script>
<script src="data/news.js"></script>
<script src="assets/js/app.js"></script>
<script src="assets/js/components.js"></script>
```

### 要求

- 两个资讯页面都核对
- 顺序保持一致
- `news.js` 必须在上述 MCU 数据脚本之后
- `app.js` / `components.js` 保持现有初始化顺序
- 不引入 `community.js`
- 不增加其他无关数据脚本

# 四、P2｜related_characters 跳转参数错误 —— 必须修

## 错误

旧规则：

```text
map.html?char={char_id}
```

## 正确

```text
map.html?focus={char_id}
```

### 原因

现有：

- `map.html`
- `next.html`

实际读取的是：

```text
?focus=
```

不是：

```text
?char=
```

### 要求

资讯详情页所有 `related_characters`：

```text
map.html?focus={char_id}
```

必须确保：

- 不再生成 `map.html?char=`
- 不残留旧写法
- 实际点击能够进入现有地图页面并聚焦对应角色

---

# 五、P3｜related_phases 不存在可用深链 —— 最终采用 A

## 最终产品决定

### A：阶段卡纯信息展示，不可点击

这是最终执行口径。

不要：

```text
routes.html?phase=x
```

也不要新增：

```text
index.html?phase=x
```

也不要为了资讯模块给现有首页资料库增加新的 URL 深链机制。

### 正确行为

阶段节点：

- 可以显示
- 可以展示 `Phase N`
- 不产生 href
- 不响应点击
- 不跳转
- 不出现手型点击暗示

推荐结构：

```html
<span class="v2n-related-node v2n-related-node--static">
```

### 要求

全局检查：

- 不得出现 `routes.html?phase=`
- 不得出现 `index.html?phase=`
- 不得出现资讯模块自造 phase 路由
- 不修改现有资料库筛选机制
