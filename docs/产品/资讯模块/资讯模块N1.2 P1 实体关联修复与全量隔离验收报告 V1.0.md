## 2. 修复前后的实体加载统计

### 2.1 核查方法
- 在服务器用 `vm` 运行 `h5/data/{movies,series,special,short,content,characters}.js`，枚举所有数组型全局实体 ID；同时调用 `id-space.cjs` 的 `loadIdSpace()` 获取实际加载集合，逐项比对。

### 2.2 数据源实体数量（H5 正式数据）
| 数据源文件 | 导出的全局 | 实体数 | 被 idSpace 覆盖 |
|---|---|---|---|
| movies.js | `MCU_MOVIES` | 38 | 38（全部进入 content 集） |
| series.js | `MCU_SERIES` | 14 | 14（全部进入 content 集） |
| special.js | `MCU_SPECIAL` | 2 | 2（全部进入 content 集） |
| short.js | `MCU_SHORT` | 5 | 5（全部进入 content 集） |
| content.js | `MCU_CONTENT` | 59 | 59（聚合集，含上表 38+14+2+5） |
| characters.js | `MCU_CHARACTERS` | 24 | 24（全部进入 character 集） |

### 2.3 idSpace 实际加载
- `content` 集 = 59（= movies+series+special+short 聚合，与 `MCU_CONTENT` 完全一致）
- `character` 集 = 24
- `phases` = 1..6
- **缺失 ID / 重复 ID / 无效 ID**：**0**（数据文件定义、但未进入 idSpace 的实体 = `{}`）

### 2.4 修复前后对比
- **未发现 idSpace 加载遗漏**：`idSpace` 已完整加载 H5 全部正式实体（修复前=修复后，无差异）。
- 因此 P1 的“修复”对象是**可观测性缺口**（丢弃动作不可见），而非加载逻辑缺陷。统计数字修复前后一致。
