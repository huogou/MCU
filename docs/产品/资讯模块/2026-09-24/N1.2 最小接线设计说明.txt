§2 接线链路图（数据流）
----------------------------------------------------------------
  L0 RawCapture（采集层产出，G5.2）
        │  （既有链路：toCaptureInput → RC.create）
        ▼
  L1 CandidateItem（35字段，既有）
        │  input = { candidate, source }
        ▼
  ┌─────────────────────────────────────────────┐
  │ ai-provider/runner.cjs · runAiProviderStage  │  ← 新增（薄编排）
  │   1) provider = registry.get(providerName)   │
  │   2) seven  = await runAdapter(provider,     │  ← N1.1 adapter.cjs
  │                 candidate)                   │
  │   3) enriched = bridgeAiModel(seven, meta)   │  ← 新增桥接（补 ai_model）
  │   4) return enriched  (8字段：7 + ai_model)  │
  └─────────────────────────────────────────────┘
        │  enriched（含 ai_model）
        ▼
  ai-normalizer.normalize(candidate, enriched)   ← G5.5，契约不变
        │
        ▼
  后续 pipeline（signature → event → gate → delivery → 人工确认 → news.js）

  关键性质：runAdapter 只产出「标准 7 字段」（经 contract-validator 校验）；
  ai_model 由 bridge 在适配器之外注入，保证 Provider 原始输出不含 ai_model（符合「Provider 输出不得泄漏业务字段」）。

§4 ai_model 桥接设计（闭合 D1 缺口）
----------------------------------------------------------------
【问题回顾】N1.1 的 7字段契约不含 ai_model；G5.5 ai-normalizer.normalize(candidate, ai) 强制要求 ai 含 7字段 + ai_model（AI_ALLOWED_FIELDS 含 ai_model，缺则 MISSING_FIELD）。若直接把 7 字段结果交给 normalizer，会 FAIL。
【方案】在 adapter 与 normalizer 之间插入 bridge：
  1) Provider 注册时声明元数据：createProvider(name, impl, meta)，meta={provider, model}；或为 registry 设默认 meta。
  2) runner 在 runAdapter 拿到 7 字段后，调 injectAiModel(seven, meta) 得到 8 字段（7 + ai_model）。
  3) 8 字段交给 ai-normalizer.normalize（契约对齐，不再 FAIL）。
【为何不放进 contract-validator】保持「Provider 输出契约 = 纯 7 字段」这一冻结边界；ai_model 是桥接产物而非 Provider 原始输出，避免污染 7 字段封闭集与 FORBIDDEN_FIELD 语义。
【置信度】高（代码级确认断点 + 桥接为纯透传注入，无语义冲突）。

§6 测试策略（8 类 + fixture 回归）
----------------------------------------------------------------
【8 类 mock provider 测试】（落 ai-provider/tests/test-n1.2-wire.cjs）
  1) 正常：mock provide 返回合法 7 字段 → runAdapter 通过 → bridge 补 ai_model → normalizer 接收 OK。
  2) 缺字段：mock 缺 category → FORBIDDEN/MISSING（视缺哪个）向上抛。
  3) 空字符串：title='' → MISSING_FIELD 向上抛。
  4) 类型错：related_movies='x'（非 array）→ TYPE_ERROR 向上抛。
  5) 未知字段：mock 多返回 ai_model（越权）→ FORBIDDEN_FIELD（校验器拦截，Provider 不得自带 ai_model）。
  6) provider 抛错：provide 抛异常 → 包装为 PROVIDER_ERROR，cause 保留，向上传。
  7) validator 抛错：校验器抛错 → 原样向上传，不进 normalizer。
  8) 下游 normalizer 接收：enriched 8 字段喂 ai-normalizer.normalize → 断言通过且 ai_model 生效（被 G5.5 记录）。
【fixture 回归保留】沿用 ai-normalizer/output/20260923.json 作基线；mock provider 喂相同候选，断言输出与 fixture 同构（或 diff 受控）。同时保留 D1/D2 42 PASS 与 N1.1 32 PASS 回归不退化。
【不吞错】任何阶段失败均向上抛明确错误码；无 try/catch 静默吞；无「失败当成功」分支。
