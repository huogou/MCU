§1 决策项清单（最小集合）
----------------------------------------------------------------
【D-P1 供应商选型】
  候选（仅列举，不定）：
    - 国际：OpenAI（GPT 系列）、Anthropic（Claude，若走代理）
    - 国内云：阿里通义（qwen）、腾讯混元（hunyuan）、字节豆包（doubao）、智谱（glm）
    - 本地：Ollama / llama.cpp 自托管（数据不出域）
  推荐基线：国内云优先（合规 + 延迟 + 计费可控）；备选本地兜底。
  待拍板：选哪家 / 是否多供应商冗余。

【D-P2 模型粒度】
  候选：各厂商的「mini/轻量」档（如 gpt-4o-mini / qwen-turbo / hunyuan-standard）即可满足 7 字段抽取。
  推荐：轻量档（成本与延迟最优；7 字段结构化抽取对大模型能力要求不高）。
  待拍板：具体 model 字符串（将作为 bridge 注入的 ai_model 值）。

【D-P3 API 形态】
  候选：官方 REST / 官方 SDK（node）/ OpenAI 兼容端点。
  推荐：OpenAI 兼容端点（便于供应商切换，adapter.provide 内部实现可换）。
  待拍板：走 SDK 还是 REST；是否统一兼容层。

【D-P4 API Key 保管】
  候选：环境变量 / 密钥管理服务 / 配置文件（gitignore）。
  红线（强约束）：API Key 严禁入仓库、严禁写进 news.js / 任何交付物 / 日志。
  推荐：环境变量 + .env（gitignore）+ 运行时注入 provider meta。
  待拍板：密钥来源与轮换策略。

【D-P5 调用成本策略】
  候选：单条限额 / 日限额 / 失败不计费重试 / 结果缓存（同 content_hash 复用）。
  推荐：先 dry-run + 小批真实验证，设日限额；与 G5.3 的 content_hash 幂等去重复用，降低重复调用。
  待拍板：限额数值、是否启用缓存复用。

【D-P6 失败与降级】
  候选：超时 / 限流 429 / 内容超长截断 / 模型不可用降级到本地。
  推荐：超时≤15s、限流指数退避≤2 次（与 G5.2 http-transport 一致）；模型不可用降级到本地兜底或人工通道。
  待拍板：是否启用本地兜底、降级触发阈值。

【D-P7 数据合规（出域）】
  事实：Provider 输入为候选原文（含 title/summary/抓取文本），可能含第三方新闻内容。
  待拍板：是否允许原文出域到云端模型；若否 → 仅本地模型（D-P1 本地项）。
  影响：决定 D-P1 是否只能选本地。

【D-P8 触发与频率】
  候选：手动 CLI / scheduler（见 Decision Gate §二 S002）。
  红线：默认不自动生产；真实 provider 调用须在你批准启用后。
  待拍板：与 S002 调度决策联动。

【D-P9 输出稳定性】
  候选：JSON mode / function calling / 低 temperature / 后处理兜底解析。
  推荐：要求 JSON 结构化输出 + temperature 低；contract-validator 已兜底校验，畸形输出走 FORBIDDEN/MISSING/TYPE 明确失败而非静默。
  待拍板：是否强制 JSON mode。
