## 一、自动采集测试

### 1.1 cron 配置存在性

```
/etc/cron.d/mcu-atlas-capture（644 root:root，713 字节）
SHELL=/bin/bash
PATH=/opt/node24/bin:/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
0 8 * * * root . /etc/mcu-atlas/dashscope.env && export DASHSCOPE_API_KEY && cd /www/wwwroot/mcu-atlas-news/workspace/news/pipeline && flock -n /tmp/mcu-atlas-capture.lock /opt/node24/bin/node runner/run-n1.cjs --mode production-capture --sources S002,S004,S006 --date $(date +\%Y\%m\%d) --persist >> /var/log/mcu-atlas-capture.log 2>&1
```

设计要点：
- **显式加载 DASHSCOPE_API_KEY**（source `/etc/mcu-atlas/dashscope.env`，非交互 shell 不读 profile.d）
- **显式 PATH**（node24 在 `/opt/node24/bin`）
- `flock -n` 防重叠运行（上一次未结束则本次跳过，**失败/阻塞不影响下一次运行**；cron 每次独立进程，天然互不影响）
- `%` 已按 cron 语法转义（`\%Y\%m\%d`）
- 输出重定向至日志文件

## 二、审核流程测试（服务器实跑）

测试对象：`candidates/20260923.json` 的 133 条 pending 候选（副本目录，**正式归档零污染**）。

| 测试项 | 命令 | 结果 |
|---|---|---|
| 查看待审核 | `list pending --date 20260923 --dir <副本>` | ✅ 显示 candidate_id / source / conf / verification / title；计数 pending 133 |
| 审核通过 | `approve cand-29d5341c-001 --operator 验收测试` | ✅ `approved`，review_id `rev-20260923-001`，**G6 复核 PASS**，留痕 review-history.json |
| 审核驳回 | `reject cand-c1a960c4-002 --reason "验收测试：信息不足" --operator 验收测试` | ✅ `rejected`，review_id `rev-20260923-002`，G6 复核 PASS |
| 重复审核防护 | 对已 approved 候选再次 approve | ✅ 拒绝：`ALREADY_DECIDED`（exit 1） |
| 驳回缺原因 | reject 不带 --reason | ✅ 拒绝：`REASON_REQUIRED`（exit 2，fail closed） |
| 未知候选 | approve 不存在的 id | ✅ 拒绝：`CANDIDATE_NOT_FOUND` |
| pipeline 外写防护 | --dir 指向 pipeline 外 | ✅ 被现有守卫拒绝：`WRITE_OUTSIDE_PIPELINE` |

CLI 架构合规性：
- 决策一律经 `review/review-actions.cjs`（applyDecision，operator 必填）；
- 结果一律经 `gate/gate.cjs`（GATE.review 复核，approved 桶校验）——**未绕过 G6**；
- 归档写回为原子写（tmp + rename），review-history.json 追加式留痕；
- 本工具**无任何自动批准逻辑**，纯人工指令驱动。
