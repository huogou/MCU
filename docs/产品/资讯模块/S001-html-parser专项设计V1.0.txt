【1】HTML 入口（实测事实 + 入口设计）
────────────────────────────────────────────────────────────────────
1.1 登记表现行口径（source-registry.json S001）
  · feed_url = https://www.marvel.com/news（html-parse，无 RSS）
  · allowed_paths = /news/、/articles/movies/、/articles/tv-shows/、/articles/live-events/
  · excluded_paths = /articles/comics/、/articles/games/、/articles/culture-lifestyle/
  · note：列表约 75% 为 comics/games/live-events，必须做影视类过滤

1.2 实测：访问可达性（2026-09-23，UA 对照探针，只记状态码）
  · MCUAtlasBot/1.0（自报机器人 UA）→ /news 与 /robots.txt 均 **HTTP 403**
    （CloudFront「Request blocked」919 字节错误页）
  · 浏览器 UA → /news **302**（重定向，落点待核）→ robots.txt **200**
  · 结论：**封锁发生在 CDN 层按 UA 过滤**，与 robots 协议无关（见 1.3）。
    现行 http-transport 的「自报 UA」纪律与 S001 自动可达**互斥**。

1.3 实测：marvel.com 真实 robots.txt（浏览器 UA 下取得，557 字节）
  User-agent: *
  Disallow: /image* /comics/unlimited/home /comics/unlimited/membercard
            /my_account/personalinfo */partials/comic* /responder* /unlimited/thanks/*
  Sitemap: https://www.marvel.com/sitemap-news.xml（另有 sitemap.xml 等 4 份）
  User-agent: AhrefsBot  Disallow: /
  User-agent: GPTBot     Disallow: /
  解读：
  · 通配组对 **/news 与 /articles/* 无任何禁止** → robots 协议层面允许抓取；
  · **GPTBot 被全站禁止** → 站方对「AI 用途抓取」有明确拒绝信号，
    属于立场证据，不因 MCUAtlasBot 未被具名而消解；
  · ★ 新事实：**存在 sitemap-news.xml**，与登记表 note「禁止以 sitemap 作
    新闻发现通道」冲突 → 是否修订该规则，列入待拍板（§6 D-2）。

1.4 入口设计（三通道，按合规优先级排序）
  通道 A（默认推荐）：**人工投放 + 本地解析**
    · 人工用浏览器访问 /news 及需核验的文章页，将 HTML 另存到
      workspace\news\pipeline\captures\inbox\（目录随本专项实施时创建）；
    · 解析器从本地文件读 HTML → 产出 L0（feed_type=html-parse），
      走既有 normalizer → capture-store 链路，**零新增网络代码**；
    · 合规最优（网络行为由人完成，解析器只处理已取得的公开页面副本），
      且与 G5 管道「取数通道可注入（opts.transport）」的既有设计完全兼容
      （注入一个 local-file transport 即可）。
  通道 B（待拍板）：**UA 更换为浏览器串**
    · 技术上立即可用，robots 通配组允许 /news 与 /articles/；
    · 但①违反 http-transport「可识别机器人 UA」纪律（须改 UA 常量并留痕）
      ②与站方禁 GPTBot 的立场信号相悖；③CloudFront 可能升级为行为指纹拦截。
    · 如拍板启用：须同步修订登记表 S001 crawl_policy 与 note，并过 G2 校验器。
  通道 C（备选）：**sitemap-news.xml 发现 + 文章页定点核验**
    · 仅在 D-2 拍板「解禁 sitemap」后作为发现通道；文章页核验仍受 1.2 的
      UA 封锁约束，故 C 不能单独成立，须与 A 或 B 组合。

【2】JSON-LD 解析设计（字段映射 → L0 入参）
────────────────────────────────────────────────────────────────────
2.1 取证现状
  · 因 1.2 的 UA 封锁，/news 列表页 HTML **尚未取得**，JSON-LD 形态
    **未实测**（诚实声明：本节为标准形态设计，实施首日以人工投放样本校准）。
2.2 双通道解析设计
  · 主通道 JSON-LD：抽取全部 <script type="application/ld+json">，
    取 @type ∈ {NewsArticle, Article, ReportageNewsArticle} 的对象；
  · 兜底通道 DOM：列表页按 <a href="/articles/…"> 抽取链接与卡片文本；
  · 两通道产出统一进入字段映射表（2.3），映射结果再过 normalizer 纪律
    （title_raw 不改写、时间 ISO8601 归一、excerpt ≤200 字）。
2.3 字段映射表（JSON-LD → L0 入参，预期形态）
  headline              → title_raw（原样，仅 trim）
  datePublished         → published_at_raw（normalizeIso 归一）
  url                   → source_url（须落 allowed_paths 交集，见 §3）
  description/articleBody → excerpt 来源（去标签+压空白+截 200）
  articleSection        → 影视类过滤的辅助信号（弱信号，不得单独定类）
  ★ L0 不产出 category / 实体 / 状态字段——那是 L1 的职责。
2.4 解析失败语义（对齐管道既有 fail-closed 风格）
  · 无 JSON-LD 且无 /articles/ 链接 → PARSE_EMPTY（计 rejected，不中断）；
  · 条目缺时间 → 允许（published_at=null，L0 已有该语义）；
  · HTML 过大（>2MB）→ 截断并留痕（与 http-transport 上限一致）。

【3】官方证据抽取（official_confirmed 证据链的补全设计）
────────────────────────────────────────────────────────────────────
3.1 定位：S001 是「官方确认」的**唯一自动入口**（T1 级、owner_group=
    Disney/Marvel）；本专项落地后，official_confirmed 的自动证据链才可用。
3.2 证据链设计（四步，全部复用冻结件，不新建规则）
  ① 入口过滤：条目 source_url 必须命中 allowed_paths 交集；
    命中 excluded_paths 一律丢弃；/articles/live-events/ 是目录页
    （url_level 会被判 article），按 G8 既有结论由人工审核识别。
  ② G3 校验：official-source-validator 六项检查（domain/path/黑名单/
    registry_match 等）——本专项**不改 G3**，只保证喂入的
    registry_entry 来自登记表。
  ③ L0 落盘：feed_type=html-parse、url_level 按 classifyUrlLevel 派生
    （列表页=section、文章页=article），capture-store 追加归档。
  ④ 状态判定：**不在本专项内做**——official_confirmed 由 G1 判定器
    按 R8.3 重算；本专项只提供「官方 URL 证据」，I9 标记仍由人工/AI
    整理层传入。
3.3 与 G8 的衔接：S001 证据链可用后，001/009/013 的官方 URL 修正
    （G8 清单第 2 项）可获得实测校准材料。

【4】风险点
────────────────────────────────────────────────────────────────────
  R1【硬阻塞】CDN UA 级封锁：自报 UA 永远 403 → 自动抓取不可行，
     必须先拍板通道 A/B（§1.4）。本风险不解除，§2/§3 无法自动化。
  R2【内容】列表 ~75% 为 comics/games/live-events → 过滤器漏放会造成
     候选层噪音；建议「allowed_paths 交集 + articleSection 弱信号 +
     人工抽检」三层过滤，漏放率纳入质量报告观察项。
  R3【形态未知】JSON-LD 实际形态未取证（§2.1），首轮解析器实现
     可能因形态偏差返工——以人工投放样本先行校准再写码。
  R4【改版】Marvel 页面结构变更无通知 → 解析器可能静默产出空结果；
     建议按既有 fail-closed 风格：PARSE_EMPTY 连续出现即报警留痕。
  R5【重定向】/news 返回 302，落点未知 → 须核对落点是否仍在
     allowed_domains/allowed_paths 内，防止重定向后越权抓取。
  R6【立场】站方禁 GPTBot 表明对 AI 抓取反感；通道 B 存在声誉/ToS
     灰度，不建议默认启用。

────────────────────────────────────────────────────────────────────
【5】合规边界（本专项的不可越界清单）
────────────────────────────────────────────────────────────────────
  · robots 实测边界：通配组允许 /news 与 /articles/*，但 GPTBot/
    AhrefsBot 被全站禁止——本项目以「通用机器人自报身份」运行时，
    不得伪装成被具名禁止的机器人，亦不得在未拍板前默认更换 UA。
  · 登记表现行规则「禁止 sitemap 作新闻发现通道」在 D-2 拍板前继续有效。
  · 解析器只处理「已合法取得的页面副本」（通道 A）或「拍板后通道」；
    不得引入 Cookie 池、代理池、无头浏览器指纹伪装等规避手段。
  · 任何通道变更 = 修订登记表 crawl_policy/note（G2 冻结件维护，
    须过 22 条校验规则 + 负责人批准），不得在采集层私自放行。
  · 产出物仍受管道四条硬约束：不进 h5、不进 33 字段、不产状态字段、
    不产交付物 id。
