# 第二阶段：生产化方案

## A. 推荐更新模式

| 维度 | 方案1 完全人工 | 方案2 RSS采集+AI+人工审核 | 方案3 全自动 |
|---|---|---|---|
| 人力成本 | 高（每条人工找/写/改） | 中（审核约 5 分钟/日） | 低 |
| 时效 | 差 | 好（T+1） | 最好 |
| 版权/错误风险 | 低 | **低（人工终审）** | **高（自动转述第三方报道）** |
| 剧透风险 | 可控 | 可控（审核把关） | 不可控 |
| AI 幻觉风险 | 无 | 低（契约+人工双保险） | 高（无人工兜底） |
| API 成本 | 0 | 极低（见 C） | 中 |
| 与已建管线关系 | 管线闲置 | **完全复用** | 违反冻结护栏 |
| 合规 | — | — | **违反 `autoProduction` 恒 false 的产品护栏** |

### 推荐：**方案 2**

**理由**：
1. **架构已就绪，零重建成本**：白名单采集 → L0 追加落盘 → 语义去重 → AI 7 字段契约 → G6 人工审核 → 33 字段 delivery preview → 人工授权 append-only 写 news.js，每一环都已实现并通过回归测试（P1-A~P1-D 全绿 + 服务器 U1 43/43）。
2. **风险结构最健康**：版权（只存 AI 转述摘要 + source_url 引用，不存全文）、错误新闻（八态可信度 + 多源证据组计数）、AI 幻觉（7 字段封闭契约 + related_* 受真实 idSpace 约束 + confidence/recommend 过滤）、剧透（人工审核时把关）——全部由**人工审核闸门**兜底，这是全自动方案给不了的。
3. **成本可控**：每日 1 次采集 + 人工触发 AI 整理，月 API 成本预计 < ¥3。
4. **护栏不破**：`autoProduction` 恒 false 不变，Cron 只跑 capture 模式，production 永远人工触发。

## B. 技术实施计划（方案 2）

```
新闻源 (source-registry: S001-S012, 6 enabled)
  ↓ Cron 每日 1 次（capture-only, --persist）
RSS/API 采集 (http-transport: UA/限速/robots/白名单)
  ↓
L0 captures/<date>.captures.json（追加式/幂等/原子写）
  ↓
去重过滤 (content_hash + candidate-store 语义去重 + G4 事件归并诊断)
  ↓
人工触发 review（production-review，需临时 productionAllowed=true）
  ↓
AI 摘要生成 (dashscope qwen3.8-flash，7 字段契约 + contract-validator)
  ↓
人工审核 (G6 gate: pending → approved/rejected)
  ↓
Delivery Preview (deliveries/<runId>.delivery-preview.json，33 字段)
  ↓ 人工授权 run-g9-write（append-only，幂等守卫+双备份+vm 校验）
news.js 更新（软链已指向 /www/wwwroot/mcu-h5/data/news.js）
  ↓
H5 展示（静态站点即读即展，写入即生效，无需部署动作）
```

### 数据结构

- **不变**：news.js 33 字段封闭集、八态 verification_status、item-status 5 字段 + dedup_hints + analysis（P1-B 冻结 schema）、L0/L1/L2 分层——全部保持冻结，本方案不新增任何字段。

### 定时策略

- **采集**：每日 08:00 一次（低峰、低风险、capture-only）
- **AI 整理（review）**：人工触发（成本与质量双控；候选量 > 20 条/日时再评估自动）
- **发布**：人工授权（run-g9-write），永不自动

### 发布方式

`run-g9-write.cjs`：基线 SHA 校验（防重复/防覆盖）→ 双备份 → append-only 插入（旧条目字节不变）→ vm 重载校验 → 完成。线上即时生效（静态站点直接读 news.js）。

## C. 风险控制

| 风险 | 控制措施 |
|---|---|
| **MCU 新闻版权** | ① 只存 AI 生成的**转述摘要**（summary）+ source_url 引用，**不存原文全文**；② 白名单源（12 登记 / 6 启用，S007-S012 合规禁用）；③ robots.txt 审计 + UA 声明 bot 身份；④ 人工审核把关转述准确性 |
| **错误新闻** | ① 八态可信度体系（官方确认 > 多源 > 单源 > 传闻 > 未核实）；② `independent_group_count` 按 owner_group 去重（防单一媒体集团刷量，测试断言冻结）；③ `corrected` / `officially_denied` 态 + supersedes 机制纠错；④ G6 审核不自动批准 |
| **剧透风险** | category 分类 + related_* 结构化字段；**建议审核 SOP 增加剧透分级打标**（产品决策，待确认）；未打标内容不进 H5 |
| **AI 幻觉** | ① 7 字段封闭契约（未知字段→FORBIDDEN_FIELD 拒绝）；② `related_*` 必须命中 MCU_CONTENT/MCU_CHARACTERS 真实 id（未命中即丢弃，test-n1.3-dryrun 断言）；③ `confidence` 低 / `recommend=false` 的候选自动排除；④ **人工审核终审**兜底 |
| **API 成本** | ① 低成本档模型 qwen3.8-flash；② 采集（capture）不调用 AI，仅 review 调用；③ 估算：日新增候选 ≤10 条 × 单次 <¥0.01 → **月成本 < ¥3**；④ 去重后再调 AI（content_hash 命中即跳过，不重复付费） |
