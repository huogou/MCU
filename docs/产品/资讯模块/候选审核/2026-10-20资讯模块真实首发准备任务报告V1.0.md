## 二、核查结果

### 1. 审核人白名单条件

- **现状**：`pipeline/review/trusted-reviewers.json` **不存在**（发布侧 `DEFAULT_ALLOWLIST` 指向该路径；缺失时 `loadApprovedIds` 返回 fail closed，拒绝发布）。
- **格式要求（已用代码 `loadPublishAllowlist` 确认）**：
  - 接受三种形态之一：纯数组 `["名1","名2"]`；`{ "reviewers": [...] }`；`{ "entries": [...] }`（entries 为名称字符串数组）。
  - 名称级信任锚（**非密码学身份**）：审核记录里的 `reviewer` 必须**精确匹配**（区分大小写、trim）白名单中的某一名字。
  - 审核人名**不得**以 `simulated` / `ai` / `rule` / `system` / `auto` 开头（导出工具 `isGenuineHuman` 会将其排除）。
- **结论**：白名单缺失 → 待负责人建立（含真实获授权审核人 + 授权确认）。本任务**不代建**。

### 2. 真实审核记录

- `review-history.json` 结构：`{ "schema_version", "entries": [...] }`。
- 当前 `entries` 共 **12 条**，`operator` 全部 = `simulated-g7-reviewer`（模拟演练记录）。
- **真实人工审核记录 = 0**；**无任何可用于真实首发的批准记录**。
- 每条真实审核记录须满足（导出/发布门禁实际校验）：`operator` 为真实人（非模拟/AI/规则/系统）+ `action=approve` + `reviewed_at`（ISO）+ `source`（非空）+ 经 map 解析出的 `news_id` + 该 `news_id` 存在于待发布数据源。
- **重要区分**：候选文件中的 `gate_status`（approved/rejected/pending）是 AI/门禁**建议**状态，**不是**人工审核，绝不能当作批准证据；真实审核须经 `gate-review.cjs` 产生真实 `operator` 的 `review-history` 条目。

- 硬规则（代码已确认）：
