## 4. 数据回滚与 nginx 配置回滚的操作差异

| 维度 | 资讯数据文件回滚（news.js） | nginx 配置回滚（缓存规则） |
|---|---|---|
| 触发场景 | `--publish` 失败/误发布后恢复数据 | 撤销 2026-10-19 实施的 `/data/news.js` 禁用缓存规则 |
| 备份路径 | `/www/wwwroot/mcu-h5/data/news.js.bak-pub-<ISO时间戳>`（由脚本发布时自动生成） | 三个 `.bak-pub-2026-10-19T05-33-35-*` 文件（见第 3.3 节） |
| 恢复命令 | `cp` 备份 → 目标 | `cp` 备份 → 对应 `.conf` |
| 是否需要 reload | **否**（缓存已对 news.js 设 no-cache，浏览器刷新即取新值） | **是**，且必须 **先 `nginx -t` 通过再 `nginx -s reload`**（严禁 restart） |
| 回滚后验证 | 记录数+ID 集合比对 + 三页面读取 | `curl -ksI` 确认 `Cache-Control` 恢复为 `max-age=604800`（7 天） |
| 脚本保障 | 失败自动 `rollback()` + `verifyTarget()` 校验一致性（行 151-154、203-209） | 无自动；须人工按 RUNBOOK 第 6.2 节执行 |

**核心差异**：数据回滚是纯文件复制 + 内容校验，不影响 nginx；配置回滚必须 reload 才生效且须先语法检查。两者严禁混淆。
