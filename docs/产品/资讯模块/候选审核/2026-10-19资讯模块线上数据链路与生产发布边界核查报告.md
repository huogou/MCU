# MCU Atlas｜资讯模块线上数据链路与生产发布边界核查报告

> 执行角色：CodeBuddy（开发 AI）。性质：**只读核查生产数据链路，不实施、不写入、不发布、不部署**。
> 本轮依据：服务器真实目录与 nginx 配置、H5 页面脚本引用、G9 写入器与交付转换器源码、工作区与线上两份 `news.js` 实际内容比对。
> **重要更正**：此前 V2 报告默认 `mcu-atlas-news/h5/data/news.js` 即线上数据源、且"线上部署不在本工作区范畴"。本轮核查证实：**线上 docroot 是 `/www/wwwroot/mcu-h5`，与 `mcu-atlas-news` 物理分离**，下面据此修订。

---

## 1. 线上实际资讯数据源及证据

- **线上数据源（唯一）**：`/www/wwwroot/mcu-h5/data/news.js`（设置 `window.MCU_NEWS = [...]`）。
- 证据链：
  - nginx vhost `/www/server/panel/vhost/nginx/mcu.yaokaixin.top.conf`、`mcu.yaoqiang.xin.conf`、`mcuatlas.xyz.conf` 中 `root /www/wwwroot/mcu-h5`（第 34/65/25/37/59/105 行等），`server_name` 为对外域名（`mcu.yaokaixin.top` / `mcu.yaoqiang.xin` / `mcuatlas.xyz`）。
  - 线上页面 `mcu-h5/index.html:182` `<script src="data/news.js"></script>`；`mcu-h5/news.html:55`、`mcu-h5/news-detail.html:49` 同款引用；`mcu-h5/assets/js/components.js:377` 注释"数据：window.MCU_NEWS（h5/data/news.js）"，`:801` 用 `(global.MCU_NEWS||[]).forEach(...)` 渲染。
  - 实读 `mcu-h5/data/news.js`：52 条记录、`stage:'mock'`、含 `window.MCU_NEWS_META` 与 `window.MCU_NEWS`（与 workspace 副本逐字一致）。

> 结论：线上 H5 **直接以 `<script>` 方式加载 `mcu-h5/data/news.js`**，无构建步骤、无运行时 API 拉取、无独立真实数据文件。当前线上用户看到的就是这 52 条 mock 记录。

## 2. staging 与 production 目录关系

| 目录 | 角色 | 证据 |
|---|---|---|
| `/www/wwwroot/mcu-atlas-news/` | **工作区/项目根**：含 `h5/`（前端源）+ `workspace/news/pipeline`（采集/审核/转换/G9 流水线） | `ls` 顶层仅 `h5`、`workspace`；`run-g9-write.cjs:35` 写入 `mcu-atlas-news/h5/data/news.js` |
| `/www/wwwroot/mcu-h5/` | **生产 docroot（线上）**：被 nginx 直接服务 | nginx vhost `root /www/wwwroot/mcu-h5`；`readlink` 确认**非软链**；顶层文件结构与 `mcu-atlas-news/h5` 完全镜像 |

- 两者**物理分离、内容镜像**（当前 `news.js` 均为 52 条 mock 且逐字一致），说明曾有一次（或多次）**手工/历史复制**把 `mcu-atlas-news/h5` 搬到了 `mcu-h5`，但**可读证据中不存在自动同步机制**（见 §4、§6）。

## 3. mock 数据使用范围

- `stage:'mock'` 仅作为 `MCU_NEWS_META` 内的元数据标识（`h5/data/news.js` 头部注释亦称"权威源/唯一权威源"）。
- **mock 未被隔离**：`mcu-h5/data/news.js` 同样为 `stage:'mock'` 且被线上页面直接引用 → **mock 数据已通过 `mcu-h5` 副本进入生产展示**。即当前对外网站呈现的是模拟资讯，而非真实采集资讯。
- 不存在 `mock/production` 环境切换：全仓检索 `BUILD_FILES=[]`（无 `package.json`/`vite`/`webpack`/`build.sh`/`deploy.sh`/`.env.*`）；`ENV_SWITCH_FILES` 仅因 `news.js` 注释含 `stage`、页面含 `route-detail` 而命中，无真实切换逻辑。
- 无独立"真实资讯数据文件"：`OTHER_NEWS_JS=[]`（除 `news.js` 本身及其 `.bak-*` 备份外，无其他 news 数据文件）。

| 目标 | 路径 | 来源 |

| **G9 写入目标** | `/www/wwwroot/mcu-atlas-news/h5/data/news.js` | `run-g9-write.cjs:35` `NEWS_JS = path.join(ROOT,'h5','data','news.js')`（ROOT=mcu-atlas-news） |

## 5. 真实采集到线上展示的完整链路图

```
采集(source-fetcher) → captures/<date>.json
  → 候选生成(captures-to-candidates → CI.fromRawCapture, L1 软过滤)
  → 人工审核(gate-review → GATE.review, 按 gate_status)
  → 交付转换(delivery-converter.toDeliveries, 输出 pipeline/deliveries/*.json，33字段, 不写h5)
  → G9 写入(run-g9-write → mcu-atlas-news/h5/data/news.js)   ← 到此为止（仅工作区）
  → 【断点：工作区 → 线上同步】   ← 缺失/未确认（无自动脚本）
  → 线上 H5 读取(mcu-h5/data/news.js → window.MCU_NEWS)
  → 用户展示(assets/js/components.js 渲染)
  → 浏览器/CDN 缓存(news.js expires 7d)                     ← 风险点
```

## 7. 正式发布前必须补齐的最小工作项

1. **建立工作区→线上同步**：新增或将"复制 `mcu-atlas-news/h5` → `mcu-h5`"纳入明确流程（rsync/面板部署/脚本）。当前 G9 只写到工作区，不自动上线。
2. **去 mock / 灌入真实资讯**：决定 `stage:'mock'` 52 条是保留、替换还是迁移；真实发布须经 §6 链路生成 `news.js` 后再同步。
3. **缓存失效策略**：`news.js`（`.js`）被 nginx 强制 `expires 7d`，发布新资讯后必须（a）给 `news.js` 加版本查询串/文件名哈希做 cache-bust，或（b）主动 purge nginx/CDN 缓存；否则用户最长 7 天看到旧资讯。
4. **确认线上数据源唯一性**：确保线上仅有 `mcu-h5/data/news.js` 一个源，避免 `mcu-atlas-news/h5` 与工作区其它副本造成混淆（当前两者内容一致，但物理分离）。
5. **（可选）环境隔离**：若后续需区分 staging/prod，应引入明确的环境标识与独立目录，而非当前"同构两份目录 + 手工复制"的隐式关系。

> 以上均超出本轮"只读核查"边界；仅列出供策划决策，本轮不执行。
