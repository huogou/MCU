## 一、实际修改文件及关键变更

**唯一修改文件**：`pipeline/tools/news-append-writer.cjs`（服务器已部署，语法检查 `node --check` 通过）。

关键变更（均为新增/最小改，未触及既有备份/`--expect-sha`/幂等/VM 逻辑）：

1. **复用门禁逻辑（不复制规则）**：顶部 `const pub = require('./publish-news.cjs');`，调用其已存在的 `loadApprovedIds()`。该模块有 `require.main === module` 守卫，`require` 不会触发其 CLI（已核实）。
2. **新增参数**：
   - `--manifest <approved-manifest.json>`（**必填**）；
   - `--allowlist <trusted-reviewers.json>`（可选，默认 `pipeline/review/trusted-reviewers.json`）；
   - `--news-js <path>`（可选，默认生产路径，仅供隔离测试）。
3. **门禁（写盘前、备份前执行）**：
   - 缺 `--manifest` → `ARG_MISSING`（退出码 2）；
   - `loadApprovedIds` 返回非 ok（清单不存在/解析失败/`reviewer_trust≠allowlist`/白名单缺失/缺审核人·时间·来源/审核人不在白名单/纯 id 列表）→ `APPROVAL_REQUIRED`（退出码 1）。
   - 逐条 reconcile：预览每个 `item.id` 必须命中批准集合，任一未批准 → `APPROVAL_ID_MISSING`（整批拒绝，不允许部分写入）。
4. **未改动**：`publish-news.cjs` 的结构校验与门禁逻辑保持原样（仅作为门禁逻辑库被复用）；`--expect-sha`、双备份、幂等守卫、VM 结构校验全部保留；未删除任何旧工具、未启用冻结 `run-g9-write.cjs`、未改 H5 页面或数据结构。
