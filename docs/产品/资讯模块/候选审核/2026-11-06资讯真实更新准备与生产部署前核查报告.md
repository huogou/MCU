## 二、生产环境发布门禁核查（七问）

### 2.1 `review/trusted-reviewers.json` 缺失原因及所需结构

- **原因**：文件从未创建（`ls` 明确 `No such file or directory`）。P2-B1.1 把它设计为「带外维护的信任锚」，10-20《真实首发准备任务报告 V1.0》明确「本任务不代建」，此后负责人未提供真实获授权审核人名单，故一直缺失。不是文件丢失。
- **默认路径**：`export-approval-manifest.cjs:402` 与 `publish-news.cjs:24` 均指向 `pipeline/review/trusted-reviewers.json`。
- **所需结构**（`loadPublishAllowlist` / `loadAllowlist` 接受三选一，元素必须是**名称字符串**）：

```json
{"reviewers": ["真实审核人A", "真实审核人B"]}
```

或纯数组 `["A","B"]` / `{"entries":["A","B"]}`。

- **硬规则**：审核人须与 `gate-review --operator` 的值 `trim()` 后**精确匹配**；`isGenuineHuman` 排除以 `simulated` / `ai-` / `ai_` / `rule-` / `rule_` / `system` / `auto` 开头，以及含 `g7-reviewer` / `simulated` 的名称；白名单缺失或为空 → `missing=true` → **fail closed 拒绝发布**。

### 2.2 真实人工审核记录：生成方式、字段、入口

- **唯一入口**：`tools/gate-review.cjs approve <candidate_id> --operator <真实审核人> --date <YYYYMMDD>`。决策必经 `review/review-actions.cjs applyDecision`，结果必经 `gate/gate.cjs GATE.review` 复核（fail closed），**工具本身不做任何自动判断**。
- **写入**：原子写回 `candidates/<date>.json`（`gate_status: pending → approved`），并追加 `candidates/review-history.json`（`rev-YYYYMMDD-NNN`）。
- **记录字段**（实测 `review-actions.cjs:97-108`）：
  `review_id, event_id, candidate_id, operator, action, before, after, modifications, reason, created_at`。
- **字段映射**（`export-approval-manifest.cjs collectFromHistory:168-184`）：`operator → reviewer`、`created_at → reviewed_at`、自动补 `source: "review-history.json:<review_id>"`、`record_version: review_id`。因此字段层面可与发布门禁衔接。
- **当前现状（重要更正）**：真实审核记录**并非 0 条**。
  - `candidates/review-history.json`：**54 条**，`产品负责人` 19 / `产品审核(2026-10-14)` 20 / `planner` 12 / `owner-u2` 3，均为 10 月批次；最新 `rev-20261016-019`（2026-10-16）。
  - `review/review-history.json`：**12 条**，全部 `simulated-g7-reviewer`（9 月演练），是 `publish-news.cjs` 的 `DEFAULT_MANIFEST` 与 `export-approval-manifest.cjs` 默认 `--history` 指向的文件。
  - 两份文件**路径分裂**：`gate-review` 写 `candidates/`，导出/发布默认读 `review/`。
  - **20261106 新候选尚无任何真实审核记录**（20 条全 `pending`）。

### 2.3 负责人发布授权的记录方式与完整性

- **现有机制**：`news-append-writer.cjs --operator <授权人>` 写入 `tools/state/news-write-state.json`，字段含 `run_id, operator, sha_before, sha_after, old_count, added_count, new_count, preview_file, written_at`。实测已有 4 次写入，最后一次 `run-20261015-endgame-001 / 项目负责人人工授权上线 / 49→50 / 2026-10-15T06:31:31Z`。
- `approved-manifest.json` 的 `note` 明确「批准清单导出≠发布授权」。
- **不完整之处**：没有独立的事前授权凭证/双人复核文件（`review/` 下无 author/approv/trust 类文件）；`--operator` 是任意字符串，发布侧不校验其是否为负责人、不在白名单核验范围内；授权只在命令执行时以署名形式体现，缺线下授权留痕。
- **最小补强（不改代码）**：发布前由负责人写一份带外授权记录，并在 `--operator` 中使用同一署名（命令见 §5.6 第 0 步）。

### 2.4 候选实体关联的校验规则，哪些候选因缺少实体无法通过

- **规则链**：
  1. AI 输出自然语言实体名 → `candidate-item.cjs intersect()` 与 `h5/data` 的真实 idSpace（`content` 62 / `character` 25）**精确匹配**；未命中**只丢弃 `related_*` 关联，不丢弃候选条目**。
  2. `delivery-converter.cjs:204-207` 原样复制 `related_*`；只校验 33 字段封闭集与管道字段禁入，**不要求非空、不校验 id 归属**。
  3. `publish-news.cjs validateStructure` 只要求 `related_movies/series/characters` 为数组（允许 `[]`）、`related_phases` 为 1–6 整数。
  4. `news-append-writer.cjs` 只校验每个 preview item 恰 33 字段。
- **结论**：**当前没有任何候选会因「缺少实体」被发布门禁拦下**。真正会被 Gate 拦下的是 `gate_status !== 'approved'` 的条目（20261106 的 20 条目前全部 `pending`）。
- **但存在质量缺口**：`candidates/20261106.json` 20 条 `related_movies/series/characters` **全为 `[]`**；原因是 prompt 未提供合法项目 id（`dashscope.cjs:55` 只要求「字符串数组」），而非实体库缺失——`doomsday`、`visionquest`、`daredevil-born-again`、`thanos`、`vision`、`tony`、`sam` 均在库；真正库中缺的角色是 `doctor-doom`（末日博士）与 `jim-hammond`（初代霹雳火）。另 001 的 `related_phases=[3,6]` 混入 Phase 3，与《末日》不符。发布后这些资讯在 H5 无法关联影视条目，须人工决定是否先做别名映射/实体增补再发布。

### 2.5 `gate-review` 的全部阻塞条件及解除条件

| 阻塞码 | 触发 | 解除 |
|---|---|---|
| `ARG_MISSING` | 缺 `candidate_id` | 传 ID |
| `OPERATOR_REQUIRED` | 缺 `--operator` | 传真实审核人 |
| `REASON_REQUIRED` | `reject` 缺 `--reason` | 补原因 |
| `ARCHIVE_NOT_FOUND` | 当日候选归档不存在 | 先生成候选；或指定正确 `--date` |
| `WRITE_OUTSIDE_PIPELINE` | `--dir` 指向 pipeline 外（守卫来自 `candidate-store.readArchive → capture-store.assertInsidePipeline`） | 使用默认 `candidates/` 目录，**不要传 `--dir`** |
| `HISTORY_CORRUPT` | `review-history.json` 无法解析 | 不要覆盖，从备份恢复 |
| `CANDIDATE_NOT_FOUND` | ID 不在归档 | 以 `list pending` 实际输出为准 |
| `ALREADY_DECIDED` | 候选已是 approved/rejected | 不可重复审核；需回滚须由负责人依留痕处理 |
| `GATE_REJECTED` | `GATE.review` 未把结果放入 approved 桶（L1 35 字段校验失败 / 状态非法） | 修复候选数据后重新审核 |
| `RESULT_INVALID` / `UNKNOWN_ACTION` 等 | `applyDecision` 内部校验 | 依错误信息修正 |

> 注：`gate-review` 服务器版的 `writeArchive` / `appendHistory` 自身直接写 fs，越界防护依赖上述 `readArchive` 在**读取阶段**先行拦截；故一律不传 `--dir`。

### 2.7 其他未在此前报告中披露的发布阻塞项

| # | 新发现的阻塞 | 后果 | 解决 |
