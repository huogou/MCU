【2】规则定案
────────────────────────────────────────────────────────────────────
  R-1【历史数据允许空值】
    已存在于 h5/data/news.js 的历史条目（含 reported_by=[]）**允许
    保留空值**，原样保留、不做任何修改（本轮 G8 及此前各阶段均未
    修改历史 news.js）。理由：①历史条目不经管道，不受 L1 契约约束；
    ②判定层已兼容；③前端已在生产环境运行该形态，具备容忍度。
  R-2【新数据强制来源行】
    管道产出的新数据（L1 及之后各层）**强制 reported_by 非空**
    （L1-10 维持不变）。来源行的合法性来源：
    ① 已登记来源 → registry_id 命中登记表 + owner_group 权威取值；
    ② 未登记来源（如社交爆料）→ registry_id='unregistered' +
       owner_group='unknown'，**仍须有来源行**（禁止完全无来源）。
    审核环节可对 unknown 来源数据从严（见《资讯审核规范V1.0》）。
  R-3【管道消费历史数据的边界】
    任何「将历史 news.js 条目导入管道」的操作（反向验证、数据迁移）
    中，reported_by=[] 的历史条目被 L1 契约拦截属**预期行为**，
    不视为缺陷、不得为迁就历史数据而放宽 L1 契约。
  R-4【未来统一的路径（待拍板，本轮不执行）】
    若产品侧要求历史数据与新契约统一（为 007 补来源行），属
    **修改 h5/data/news.js 的数据整改**，须单独拍板执行
    （backup + SHA256 记录 + 前端回归），且同步更新 G8 整改清单。
    本轮仅立规则，不动数据。
  R-5【判定优先级不变】
    本规则不改变 8 态判定逻辑、judged_by 语义、G1–G7 任何冻结件。
