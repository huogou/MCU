【一】数据结构

  载体：`registry/source-registry.json`，**管道层数据文件**，不进 h5/data，
        **任何字段都不得渲染进 H5**。
  顶层：registry_version / built_at / note / non_official_domains /
        non_official_domains_note / entries[]

  20 字段（冻结）：registry_id、source_name、owner_group、tier、crawl_policy、
    health、note、source_type、official_or_media、discovery_role、feed_type、
    feed_url、allowed_domains、allowed_paths、excluded_paths、source_role、
    last_check_at、consecutive_failures、enabled、registry_version

  枚举：tier T1–T4｜crawl_policy 5 值（auto_allowed / manual_only /
    ai_ban_named / ai_ban_notice / blocked）｜health 3 值（ok / degraded / paused）｜
    source_type 4 值｜official_or_media 2 值｜discovery_role 4 值｜
    feed_type 4 值｜non_official_domains：disney.com / disneyplus.com

  语义澄清（本次新增，消除歧义）：
    · **health 只描述「已启用来源的抓取健康度」**；未启用来源统一记 ok。
      **不得使用 `—` / `n/a` 等枚举外取值**（这一处是本次修正的文档不一致之一）。
    · **crawl_policy 只写裸枚举值**，实测细节（402/403 等）写进 note。

  查询 API：all / byId / bySourceName / isRegistered / getTier（未登记返回 null）/
    getOwnerGroup / isEnabled / officialSources / enabledSources / validate

【四】与 G1 判定器的连接方式

  链路（单向，无循环）：
    news-judge.cjs → news-judge-rules.cjs → news-registry.cjs → source-registry.json
    · G1 的判定逻辑 **news-judge.cjs 一行未改**；改动只在 rules 模块的三个常量改为加载。
    · 对外 API 与输出契约完全不变（25/25 + 49/49 为证）。

  三处具体连接：
    ① **来源等级**：judge.tierOf() → registry.getTier()
       已登记返回登记表 tier；**未登记回落 T4**（判定器侧保守降级）。
       ★ 刻意不同：registry.getTier() 对未登记返回 **null**，判定器返回 **T4**
         —— 保持「未登记」与「登记为 T4」两种状态**可区分**。
    ② **官方来源登记**：OFFICIAL_SOURCES = officialSources()
       派生规则：「official 且 allowed_domains 非空」→ 结果 **S001 / S006 / S012**
       S010/S011 域名未登记 → 不进入 → 天然满足「官方域名未登记不得构成 official_confirmed」
       ★ 从此不会再出现「代码里的域名清单与登记表漂移」。
    ③ **不登记域名黑名单**：4 项随登记表加载，判定器 R7.4 首步即拦截。

  tier 在判定链中的作用（未变）：owner_group 决定「算几个组」，tier 决定
    「这些组算不算可靠」→ 二者都来自登记表，故登记表是判定结论的事实基础。
    T4 不构成可靠来源：B9（组数1但T4 不判 single_source）、B10（两组均T4 不判 multi_source）已证。

  数据流：登记表**只读**，判定器**不写回**登记表；判定输出**不直接落库**
    （落库权在 G6 人工审核闸门）；登记表不进交付数据、不进任何页面。
