【一】字段规范 V1.0

  交付物字段 = 前端展示字段 26 + 审计字段 7 = **33 个**（与现有 news.js 完全一致）。
  管道字段 **12 个单独建、永不进交付物**：event_key / registry_id / ingested_at /
  raw_excerpt / content_hash / crawl_evidence / ai_suggested_status / ai_model /
  pipeline_run_id / reviewed_by / reviewed_at / rule_version。

  三类要点：
  · 前端展示 26 个：id / title / summary / publish_time / first_seen_at /
    verification_status / category / reported_by / original_source(_url) /
    official_source(_url) / related_movies·series·characters·phases /
    pinned·pinned_until·pinned_order·pinned_reason /
    independent_group_count（派生，**禁写**）/ report_corrections /
    conflict_statements / supersedes_id / superseded_by_id / status_history
  · 审计 7 个：status_changed_at / status_change_reason /
    status_change_evidence_url / judged_by / chain_steps_hit /
    conflict_resolved_at / conflict_resolved_by_evidence_url
    （前三个缺一，状态变更不得入库）
  · ★ **category 是必填但当前无任何渲染位**（实测 Grep 无函数读取），且枚举未定义。

  前端 8 条硬约束（违反后果已实测）：
    ① summary 必须纯文本（走 esc）
    ② publish_time 与 first_seen_at 至少一个非空 → 否则**条目静默消失，不报错**
    ③ 日期只到日，禁时分与实时性措辞
    ④ URL 必须 http(s)，否则链接被置空
    ⑤ 不得引入图片/视频字段 → 卡片无图片区，**新增字段不会被渲染**
    ⑥ related_* 未命中真实 id 一律丢弃（不报错）
    ⑦ owner_group「待核/unknown/未确认/空」不计入独立组
    ⑧ corrected 是报道级标记，事件级须独立重算

【三】状态判定器规则 V1.0

  输入：来源证据 / owner_group 映射 / 官方声明（须过 R7.4 前 3 步机器校验）/
        **独立证据组数** / 更正记录 / 冲突记录 / 原始来源
  ★ **口径纠正**：任务书写「媒体数量」不妥 —— R3.1 已明确判定基准是
    **independent_group_count（按 owner_group 去重后的组数）**，不是站点数。
    反例：现有 003 号用例 3 家报道（Variety+Deadline+THR）同属 PMC → 独立组 = 1
    → 只能判 single_source。判定器**必须自行去重，不接受外部传入计数**。

  独立组计算：逐项取 owner_group → 丢弃「待核/未确认/unknown/空」→ 按组去重计数。
  该值**禁止人工填写，也禁止 AI 提供**。

  判定链（8 步，首个成立即输出并终止）：
    Step 1 官方确认（过 R7.4）      → official_confirmed
    Step 2 官方明确否认（须回链官方）→ officially_denied
    Step 3 全部有效报道均被更正      → corrected
    Step 4 可靠来源间互斥表述        → conflicting
    Step 5 独立组 ≥2 且表述一致      → multi_source_reported
    Step 6 独立组 = 1（可靠媒体）    → single_source
    Step 7 原始来源属爆料            → rumor
    Step 8 以上皆不成立              → unverified

  关键约束：
  · 短路口径即优先级，不得调换；Step 4 必须早于 Step 5（互斥时「表述一致」前提已破）
  · 「可靠来源」建议定义为 tier ∈ {T1,T2,T3}，**T4 一律不构成可靠来源**
  · 输出必含：status / chain_steps_hit / judged_by / status_changed_at /
    reason / evidence_url / status_history 追加项；缺一不得入库
  · 重新判定：任何状态变更**从 Step 1 重跑**；人工**不得指定目标状态**，
    只能「提供证据 + 复核结果」
  · **缺数据一律降级，绝不升格**（owner_group 缺失 → 组数 0 → unverified）

【四】15 条数据体检（实测结论）

  合格部分：33 字段 15/15 齐备｜8 态全覆盖｜派生值逐条一致｜
            更正链成对｜审计三字段齐备｜文案纪律无违规｜置顶三场景齐备

  ★ S 级（阻塞真实接入）三项：
    N1 **文章级 URL 缺失：0/15 全部符合**。现有 source_url / official_source_url
       全是 feed / 栏目页 / 站点首页（如 variety.com/feed/、marvel.com/news、
       thedirect.com/rss）→ R7.4 的 path 校验形同虚设，详情页「查看原文」偏向栏目。
    N2 **owner_group 待核**：The Direct、ComicBook 归属未证实，影响 005/008/010/014 四条
       → 独立组被强制计 0，状态停在 unverified / corrected。
    N3 **双时间语义未定义**：publish_time 应=来源发布时间（到日）；
       first_seen_at 应=系统首次见到时间（用于排序回落与延迟统计）。
       封版规范 R1–R8 全文**未定义这两者差别**。

  另有 A 级 5 项（category 枚举、每篇报道发布时间、path 口径差、rule_version、
  未来作品无法关联）与 B 级 2 项（未激活字段期望值、测试夹具迁移）。

  ★★ 本次新发现的一处规范内部口径差：
    R7.3 写 allowed_paths = `/news/*`（要求 /news/ 后有内容），
    但测试断言（test-news-rules.cjs L182）放宽为 `/\/news\/?$/`（允许 /news 无内容）。
    实测 001 / 009 的 official_source_url 均为 `https://www.marvel.com/news`
    → **规范下不命中，测试下通过**。真实接入前必须统一。
