3. 三、Candidate Schema 冻结结果
============================================================

■ 3.1 裁定：**采用禁止清单模式（B）**

  【正式定义】
    · **Candidate 层（L0/L1/L2）**：**允许增加管道字段**，**总量不设上限**。
    · **DeliveryItem 层（L3）**：**严格限制为 33 字段**（前端展示 26 + 审计 7），不增不减。

  【冻结规则】任何新增管道字段必须**同时满足以下 4 条**，缺一不得新增：
    ┌────┬──────────────────────────────┬──────────────────────────────────────┐
    │ #  │ 规则                          │ 含义                                  │
    ├────┼──────────────────────────────┼──────────────────────────────────────┤
    │ 1  │ **不进入 h5**                 │ 不得出现在 h5/ 目录下任何文件中          │
    │ 2  │ **不进入 33 字段交付物**       │ 不得出现在 h5/data/news.js            │
    │ 3  │ **不影响 8 态判定**            │ 不得参与 verification_status 计算；     │
    │    │                              │ 不得被判定器读取                       │
    │ 4  │ **不改变审核闸门逻辑**          │ 不得改变 gate_status 语义与             │
    │    │                              │ 「未审核不得入库」约束                  │
    └────┴──────────────────────────────┴──────────────────────────────────────┘

  【口径的准确表述】（已写入规范）
    Candidate Schema **不限制管道字段总量**；
    它只限制「**禁止进入 DeliveryItem 的字段集合**」。
    → 管道层的字段**数量是开放的**；交付层的字段**集合是封闭的（33）**。
