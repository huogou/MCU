【一】判定器设计

  形态：**纯函数规则引擎**。零网络、零 AI 依赖、零副作用、时间可注入、可幂等复现。
  结构：rules 模块（纯数据：8 态枚举 / tier / 爆料词表 / registry 最小子集 /
        官方登记表 / path 策略开关）+ judge 模块（判定逻辑）。规则与逻辑分离，
        便于 G2 落地 registry 时只换数据源、逻辑一行不动。

  三个关键设计决策：
  1. **判定器不读文本、不做语义判断**。官方确认 / 官方否认 / 互斥表述由第一层 AI
     建议 + 人工复核后以**结构化标记**传入（I9）。唯一例外：Step 7 对
     `original_source` 一个字段做爆料词表匹配（该字段是最小封闭字段，
     且 R8.3 Step 7 的判据本身即「原始来源是否属爆料」）。**title / summary 一律不匹配**。
  2. **双计数**：`independent_group_count`（仅按 owner_group 去重，与 components.js
     口径一致，用于输出与验收）与 `reliable_group_count`（额外要求 tier ∈ T1–T3，
     用于 Step 5/6 的「可靠来源」判据）。现有 15 条下两值逐条相同，差异只在
     B9/B10 这类边界出现。
  3. **path 策略做成开关，默认 legacy**（★E-1）：默认允许栏目/目录页，
     与现有断言一致；`article-level` 为 Q-5 冻结的严格版，**G8 数据修正后再启用**。
     若不这样处理，001/009/013 将无法通过 Step 1/2，与「黄金用例复现现状」冲突。

【二】输入输出契约

  输入 = 结构事实 + 语义标记（物理分开）：
    结构事实：reported_by[] / registry 映射 / URL / report_corrections[] /
             conflict_statements[] / original_source
    ★ 独立组数 **由判定器自算，禁止作为入参**（接口无该参数）
    语义标记 I9：{ official_confirm:{url,reviewed}, official_denial:{url,reviewed},
                  conflict_verified:{verified} }　缺省即「不成立」，一律降级

  调用：judge(item, input, opts) → result
        opts = { now, pathPolicy, previousStatus, judgedBy }

  输出契约（**7 项必填，缺一即抛错**，不静默返回默认值）：
    verification_status / chain_steps_hit / judged_by / status_changed_at /
    status_change_reason / status_change_evidence_url / status_history_entry
    另附诊断字段：rule_version / path_policy / independent_group_count / reliable_group_count

  异常：item 为空、缺 id、产出状态不在 8 态内 → 显式抛错。

【三】规则实现方案

  派生：逐项取 owner_group → 丢弃「待核/未确认/unknown/空」→ 去重计数 → 输出。
        空数组 → 0；全待核 → 0。

  R7.4 机器校验（本阶段范围，全为字符串处理）：
    URL 为 http(s) → host 不在不登记域名 → host 命中 allowed_domains →
    path 命中 allowed_paths 且不在 excluded_paths → path 策略（legacy / article-level）
    未实现：HTTP 可达性（属 G3）、「内容对应当前事件」（语义，由 I9 承载）、人工复核（由 reviewed 位承载）

  八步链（短路，顺序即优先级）：
    Step 1 官方确认（过校验 + reviewed）        → official_confirmed
    Step 2 官方明确否认（过校验 + reviewed）     → officially_denied
    Step 3 report_corrections 非空且**全部**有效报道均被更正 → corrected
    Step 4 互斥已核准 且 conflict_statements ≥2 → conflicting
    Step 5 reliable_group_count ≥ 2            → multi_source_reported
    Step 6 reliable_group_count = 1            → single_source
    Step 7 原 source 命中爆料词表 / 唯一来源 tier=T4 / 唯一来源 owner_group=unknown → rumor
    Step 8 以上皆不成立                          → unverified

  三条顺序性硬约束（均有对照测试）：
    · Step 4 早于 Step 5（互斥时「表述一致」前提已破）—— B4 vs B4b
    · Step 3 只施加于被更正的那条报道（011 即此形态）—— B8
    · Step 6 要求「可靠来源」，T4 不得判 single_source —— B9

  降级矩阵：任何缺数据 → 降级，绝不升格；来源未登记 → tier 默认 T4（保守）。
