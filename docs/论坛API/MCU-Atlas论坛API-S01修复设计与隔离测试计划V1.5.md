## 4. 目标架构与客户端 IP 可信链路

### 4.1 链路

```
公网客户端 ─HTTPS► nginx:443 (location ^~ /api/)
    proxy_set_header X-Real-IP $remote_addr;                        ← 覆盖客户端自带的同名头
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;    ← 客户端值在左、nginx 观测值在右
                        ▼
              127.0.0.1:8787（仅回环，本轮不修改）
                        ▼
    server.js: clientIp(req, {trustProxy, trustedProxies})
      信任判定：trustProxy===true 且 canonicalizeIp(peer) ∈ TRUSTED_PROXIES
      顺序：X-Real-IP → XFF 最右 → peer → 'unknown'
                        ▼
    ctx.ip → rate.registerByIp(ctx.ip) → key 'reg:<真实客户端IP>'
```

### 4.2 白名单语义

`TRUSTED_PROXIES = ['127.0.0.1','::1']` 的准确含义是：**只对 TCP 对端位于本机回环的请求采信转发头**。它不标识进程身份。

### 4.3 威胁模型与残余风险

| 威胁 | 能否成立 | 说明与缓解 |
|---|---|---|
| 公网客户端伪造 `X-Real-IP` / `X-Forwarded-For` | **不能** | nginx 无条件覆盖 `X-Real-IP`；XFF 只取最右；应用仅监听回环 |
| 本机其他进程直连 8787 并伪造转发头 | **能** | 后果仅限限流桶粒度被操纵，不影响鉴权（代币 HMAC、admin 独立、`requireUser`/`requireAdmin` 不变） |
| 本机进程伪装成 nginx | **能（无法区分）** | Node TCP socket 不提供对端进程身份，本设计不声称进程身份认证 |
| nginx 配置回归（删除 `X-Real-IP` 行） | **能** | 运维检查清单（§16.5） |
| 新增 CDN / 前置代理 | **能（架构变更）** | 须加白名单并重评威胁模型，未评估前不得上线 |

**已接受残余风险**：本机进程可操纵限流桶（影响面仅限频率限制，不触鉴权/数据）。

## 5. IP 解析算法 V3（P0-D01/D02 闭环）

### 5.1 Node 标准库能力边界（明示，不虚构）

| 能力 | 是否提供 | 用法 |
|---|---|---|
| `net.isIP()` | 仅校验 | **仅作 D7 交叉校验**，不代替规范化实现 |
| IPv6 规范化 / canonicalization | **不提供** | 自研（D6.6a/D6.6b） |
| `net.BlockList` 对 `::ffff:127.0.0.1` 与 `127.0.0.1` 的相等语义 | **未文档化** | **不依赖** |

剩余限制：不处理 zone id、前缀长度、带端口/方括号形式（一律判负）；不支持 NAT64 等非 mapped 的 IPv4 尾段（D6.5 判负）。

### 5.2 `canonicalizeIp(value)` 最终算法

```
D1  非字符串                                                  → null
D2  s = value.trim(); 空或 s.length > 45                     → null
D3  s 必须只含 [0-9a-fA-F:.]                                 → null
D4  结构分流：
      s 含 ':'   → IPv6 分支 D6
      s 含 '.'   → IPv4 分支 D5
      否则       → null
D5  IPv4 分支：
      parts = s.split('.')，长度必须 === 4
      每段必须匹配 ^(0|[1-9][0-9]{0,2})$ 且数值 ≤ 255          （拒绝前导零）
      → { kind:'v4', text:s }
D6  IPv6 分支：
    D6.1  '::' 出现次数 > 1                                  → null
    D6.2  分段：segments = s.split(':')
          ★ 任何**非最后一个** segment 含 '.'                → 立即 null
          - 若最后一个 segment 含 '.'：仅允许它作为嵌入式 IPv4 尾段，
            按 D5 规则解析为 2 个 hextet（高/低 16 位）；解析失败 → null
          - 其余每个 segment 必须匹配 ^[0-9a-fA-F]{1,4}$；
            空串只允许出现在 '::' 位置；否则 → null
    D6.3  组装：
          - 有 '::'：zeros = 8 - (左段数 + 右段数)；zeros < 0 → null；
                     hextets = 左 + [0]*zeros + 右
          - 无 '::'：hextet 总数必须 === 8，否则 → null
    D6.4  mapped 判定（严格）：
          hextets[0..4] 全为 0x0000 且 hextets[5] === 0xffff
          → { kind:'v4mapped', text: dotted(hextets[6], hextets[7]) }
    D6.5  若存在嵌入式 IPv4 尾段但不满足 D6.4                → null
    D6.6a 选择压缩段（仅当 kind==='v6'，即 D6.4/D6.5 均未命中且无非 IPv4 尾段）：
          在 8 个 hextet 中找出所有「连续零 hextet 的极大段」；
          若最大长度 < 2 → 不压缩（run=null）；
          若多个极大段长度并列最大 → 取**最左**那段；
          记其 [start,end] 索引。
    D6.6b 拼接（依据 D6.6a 的 run）：
          若 run === null            → text = hextets.join(':')（全小写十六进制，无压缩）
          若 run=[0,7]（全零）       → text = '::'
          若 run.start === 0         → text = '::' + hextets[run.end+1 .. 7].join(':')
          若 run.end === 7           → text = hextets[0 .. run.start-1].join(':') + '::'
          否则                       → text = hextets[0..run.start-1].join(':') + '::' + hextets[run.end+1..7].join(':')
D7  自守卫：net.isIP(text) !== 0，否则 null
```

### 5.3 压缩规则（明确）

- 只压缩**连续零 hextet**；长度 < 2 不压缩（含单个零、仅末尾单个零）。
- 多个最长段等长时压缩**最左侧**那段。
- 输出全部小写；IPv4 分支保持点分形式（无前导零已由 D5 保证）。

### 5.4 输出规则分类

| 规则 | 触发条件 | 输出 |
|---|---|---|
| **规则 V4（IPv4）** | D5 通过 | 点分十进制 IPv4，原样 |
| **规则 M（mapped → IPv4）** | D6.4 成立（`hextets[0..4]`=0 且 `[5]`=0xffff） | 一律点分十进制 IPv4（`dotted(hextets[6],hextets[7])`） |
| **规则 V（IPv6 规范化）** | IPv6 通过 D6.1~D6.3、不满足 D6.4、无 IPv4 尾段 | 由 D6.6a/D6.6b 压缩小写 |

## 7. 隔离测试架构与初始化时序 V3（P0-D03/D04/D05 闭环）

### 7.1 隔离实例形态

```
数据根目录：二选一，互斥
   (A) 未提供 FORUM_DATA_DIR → harness 用 fs.mkdtempSync(join(os.tmpdir(),'forum-e2e-'))
       （原子新建唯一目录，0700，保证此前不存在，清理安全）
   (B) 提供 FORUM_DATA_DIR   → 必须此前不存在；mkdirSync(recursive:false,0700) 原子创建；
       已存在/EACCES/符号链接 → 拒绝，绝不删除原有目录
端口：      FORUM_PORT=0（OS 分配随机可用端口，真实值从子进程监听行读取）
主机：      FORUM_HOST=127.0.0.1（字面量，不用 localhost）
请求目标：  由 harness 解析「自己子进程」的监听行生成，不读取任何外部 URL
```

### 7.2 初始化时序图（两分支，任何读生产密钥 / 写项目目录 / 发网络请求之前必须完成阶段 0~4）

```
═══════════ 两分支共用：阶段 0a（纯计算，零文件 IO、零网络、零子进程） ═══════════
  0a.1 读取 env：FORUM_DATA_DIR（可能为 undefined）/ FORUM_PORT / FORUM_HOST
  0a.2 FORUM_PORT 必须 === '0'                                  → 否则 exit 4
  0a.3 FORUM_HOST 必须 ∈ {'127.0.0.1','::1'} 字面量              → 否则 exit 3
  ★ 注意：0a 阶段不调用 path.resolve，也不触碰任何路径；FORUM_DATA_DIR 为 undefined 时跳过一切路径处理

═══════════ 仅当提供了 FORUM_DATA_DIR（raw 为非空字符串）才进入：阶段 0a.4 + 0b（只读 FS） ═══════════
  0a.4 原始字符串（resolve 之前）检查：
         不含 '..' 路径段                                         → 否则 exit 7
         不含 Windows 盘符/UNC 形式（X:\ 或 \\ 开头）              → 否则 exit 7
         不含 '/www/'                                            → 否则 exit 5
  0b.1 resolved = path.resolve(FORUM_DATA_DIR)                  （仅对真实字符串；undefined 永不至此）
  0b.2 parent = path.dirname(resolved)
  0b.3 fs.existsSync(parent) 必须为真                            → 否则 exit 7
  0b.4 parentReal = fs.realpathSync(parent)
  0b.5 tmpReal = fs.realpathSync(os.tmpdir())
  0b.6 parentReal 必须位于 tmpReal 之内                          → 否则 exit 7
  0b.7 dataRootReal = join(parentReal, basename(resolved))

═══════════ 分支 A（未提供 FORUM_DATA_DIR） ═══════════
  1a  root = fs.mkdtempSync(join(tmpReal,'forum-e2e-'))         （原子新建，保证不存在，0700）
      创建失败（极罕见，如 tmpdir 不可写）                        → exit 9
      harnessCreated = true（仅此新建成功后才置位）

═══════════ 分支 B（提供 FORUM_DATA_DIR，resolved=0b.1 结果） ═══════════
  1b  防御性预检（不登记、不删除）：
        若 fs.lstatSync(resolved) 是符号链接                     → exit 7（不删原有）
        （TOCTOU 说明见 §7.4；权威原子门在下一步）
      root = fs.mkdirSync(resolved, {recursive:false, mode:0o700})
        - 成功（EEXIST 未命中，目录此前不存在）→ harnessCreated = true
        - 抛 EEXIST（已存在，含被符号链接指向的已存在目录）→ exit 7（不删原有、不登记）
        - 抛 EACCES / 其他 → exit 7
      ★ 创建失败的分支中 harnessCreated 保持 false → 清理阶段绝不会删除任何目录

═══════════ 两分支共用：阶段 2（创建后复核，只读） ═══════════
  2.1 fs.lstatSync(root)：必须是目录且不是符号链接               → 否则 exit 7
  2.2 fs.realpathSync(root) === 期望 realpath（A: mkdtemp 返回值即权威；B: dataRootReal）
                                                                    → 否则 exit 7
  2.3 mode & 0o077 === 0（目录不得有 group/other 位）            → 否则 exit 5

═══════════ 两分支共用：阶段 3 启动子进程 ═══════════
  3.1 env：FORUM_DATA_DIR=root, FORUM_PORT=0, FORUM_HOST=127.0.0.1
  3.2 spawn 失败 / 立即退出                                      → kill+清理 → exit 9
  3.3 15s 内未输出监听列                                         → kill+清理 → exit 10
  3.4 解析 `[forum-api] listening on http://127.0.0.1:<port>`
        host 必须为 127.0.0.1；port 必须为 1024..65535 且 ≠ 8787  → 否则 kill+清理 → exit 4
      （端口唯一来源；禁止扫描/猜测；解析失败不得回退默认端口）

═══════════ 两分支共用：阶段 4 落盘复核 ═══════════
  4.1 secret.key / admin-token.key：lstat 存在/普通文件/非符号链接→exit 5；realpath 在 root 内→exit 5；
      mode & 0o077 === 0（应用保证 0600）→exit 5
  4.2 forum.db：lstat 存在/普通文件/非符号链接→exit 5；realpath 在 root 内→exit 5；
      **不要求 0600**（应用不设置 DB 权限，见 §7.5）；访问边界由阶段 2.3 的 0700 目录保证；记录实际 mode
  4.3 harness 不读取密钥内容（§7.6）

═══════════ 两分支共用：阶段 5 请求目标绑定 ═══════════
  5.1 BASE = `http://127.0.0.1:${actualPort}`
  5.2 每次请求前 assertTarget(url)：协议 http:、hostname '127.0.0.1'、port === actualPort → 否则 exit 8
  5.3 fetch redirect:'manual'；3xx 先检 Location：跨源 → 不请求、记 FAIL、exit 8
  5.4 实例身份关联（§7.7）

═══════════ 两分支共用：阶段 6 清理 ═══════════
  6.1 仅当 harnessCreated === true 时删除 root（A: mkdtemp 目录；B: 本回合 atomically 新建的目录）
  6.2 预存在目录（分支 B 的 EEXIST/符号链接拒绝路径）一律不删除
  6.3 kill 子进程 + rm 的超时/残留/退出码见 §7.8
```

### 7.3 路径安全检查与资源归属（P0-D04 + §四 全量一致性）

| 层 | 检查 | 失败时已存在资源 | 资源归属/清理责任 |
|---|---|---|---|
| L-A 原始串（0a.4，仅分支 B） | `..` 段 / Windows 形式 / `/www/` | 无（尚未创建任何目录，FORUM_DATA_DIR 为 undefined 时本层不执行） | 无需清理 |
| L-B resolve + 父目录（0b，仅分支 B） | parent 存在、parentReal 在 tmpReal 内 | 无 | 无需清理 |
| L-C 创建（1a/1b） | A: mkdtemp 原子成功；B: mkdirSync(recursive:false) 非 EEXIST | A: 已建新目录（harnessCreated=true）；B 失败: 无目录被建/登记 | A 可删；B 失败不删任何目录 |
| L-D 创建后复核（2） | 目录、非符号链接、realpath 一致、mode 0700 | 数据根目录（A 或 B 新建） | 仅 harnessCreated 目录可删（阶段 6） |
| L-E 落盘复核（4） | 文件存在/类型/realpath/权限 | 数据根目录 + 子进程 + 三类文件 | 先 kill 子进程，再删 harnessCreated 目录 |

> 明示：`path.resolve()` 会规范化 `..`，因此 L-A 必须在 resolve **之前**检查原始字符串；分支 A 完全不经过 L-A/L-B。

### 7.4 资源归属与路径竞争（P0-D04）

| 规则 | 说明 |
|---|---|
| R1 默认方案 | 分支 A（mkdtemp）是**首选且推荐**的隔离方案，harness 自建唯一临时目录，杜绝误删 |
| R2 外部目录前提 | 若保留分支 B（外部 `FORUM_DATA_DIR`），目标**必须不存在** |
| R3 原子门 | 用 `mkdirSync(recursive:false, 0700)`：目录已存在则抛 EEXIST（含符号链接指向已存在的目录），**原子**拒绝，不新建、不登记、不删除 |
| R4 归属登记 | `harnessCreated=true` **仅**在 1a/1b 成功新建后才置位；任何失败路径保持 false |
| R5 清理边界 | 阶段 6 只删 `harnessCreated===true` 的 root；预存在目录、EEXIST 拒绝目录、符号链接拒绝目录**永不**被删除 |
| R6 竞争说明 | `lstatSync` 符号链接预检与 `mkdirSync` 间存在理论 TOCTOU（OS 级）；`mkdirSync(recursive:false)` 是权威原子门，EEXIST 即拒；本设计**不宣称**事后复核可消除全部 TOCTOU，仅将「误删预存在目录」的概率降到由内核原子性保证（见 U-K） |

### 7.5 文件权限预期（分文件规定，有依据）

| 对象 | 应用是否保证 | 生产实测（本轮只读 `stat`） | harness 断言 |
|---|---|---|---|
| `secret.key` | **是**，0600（`writeFileSync` mode + `chmodSync`，`auth/token.js:20-21`） | `600` | `mode & 0o077 === 0` |
| `admin-token.key` | **是**，0600（同上） | `600` | `mode & 0o077 === 0` |
| `forum.db`（含 `-wal`/`-shm`） | **否**——`db/database.js:15-16` 未设 mode | `644`（服务 umask `0022`） | 仅断言：普通文件、非符号链接、realpath 在 root 内；**记录实际 mode**；**不断言 0600** |
| 数据根目录 | 应用 `mkdirSync` 未设 mode；但 harness 自建时为 0700，且已存在目录时 `mkdirSync` 为 no-op | 生产 `755` | `mode & 0o077 === 0`（0700） |

1. 不假定 umask：`mkdtempSync` 强制 0700 与 umask 无关；应用对已存在目录的 `mkdirSync` 是 no-op 不改 mode。
2. 数据库文件的「其他人不可读」由 0700 目录的遍历阻断保证，而非文件位。
3. 若要求 DB 文件本身 0600，需在 `db/database.js:init()` 增 `fs.chmodSync(DB_PATH,0o600)`——属 S-01 范围外加固，须单独立项；本设计不代为修改。
4. 权限检查失败处理（4.1/4.2）：**立即停止测试、kill 子进程、删除临时目录；若删除失败，报告路径与 errno 并以退出码 13 终止**。

| 操作 | 是否读取密钥内容 |
|---|---|
| harness 校验密钥文件 | **否**——只用 `lstatSync`/`realpathSync`/`statSync().mode` |
| 注册限流 E2E（E2E-A/B/C） | **否**——注册接口不需要任何 token |
| 管理端用例（V1.1 既有 TC-E 中涉及 admin 的断言） | **是**，但仅从 `root/admin-token.key` 读取，且仅在该用例需要时 |
| 任何情况下读取生产路径密钥 | **禁止** |

### 7.7 实例身份关联（可执行方式，限制如实说明）

应用日志 `accessLog` 输出 `[api] <METHOD> <req.url> <status> <ms>ms uid=<uid8>`，**不含请求 ID、不含毫秒级时间戳、不含对端端口**，无法用请求 ID 直接关联。方案（不修改应用）：
1. harness **串行**发请求（不用并发），避免日志行交错；
2. 每个请求 URL 附加唯一 nonce：`GET /api/topics?probe=<crypto.randomUUID()>`，应用忽略未知参数但 `req.url` 原样入日志；
3. 在**自己子进程** stdout 查找该 nonce 字符串 → 证明请求到达本实例；
4. 校验子进程 PID 仍为 spawn 返回值（排除 PID 复用误判）。

**限制**：① 仅适用串行请求，不适用于并发；② nonce 为随机 UUID（不含秘密）；③ 若未来日志不再记录完整 `req.url` 需重设计。

### 7.8 清理失败行为与退出码优先级（P1-D05）

**清理执行**：
- kill 子进程：先 `SIGTERM`，宽限 3s，仍存活则 `SIGKILL`，再等 3s；残留则记录 PID 与状态。
- 删除目录：仅 `harnessCreated===true` 的 root；`fs.rmSync(root,{recursive:true,force:true,maxRetries:3})`，超 5s 视为失败。

**三项结果分别记录**（不得丢弃）：

| 结果项 | 取值来源 | 说明 |
|---|---|---|
| 主测试结果 `R_test` | 测试/护栏判定：0 成功、2/3/4/5/7/8/9/10/11/12 各类失败、130/143 信号 | 反映「测试本身」结论 |
| 清理结果 `R_clean` | 0 清理成功、13 目录删除失败、14 子进程无法终止 | 反映「收尾」结论 |
| 信号结果 `R_sig` | 130 SIGINT / 143 SIGTERM / 0 无 | 反映「中断来源」 |

**严重度序（高→低）**：`14 > 13 > 12 > 11 > 10 > 9 > 8 > 7 > 5 > 4 > 3 > 130 > 143 > 0`

**最终退出码** = 三项中严重度最高者。例：
- 超时(11) 且 rm 失败(13) → **13**（同时记录 11）。
- SIGINT(130) 且 kill 失败(14) → **14**（同时记录 130）。
- 护栏失败(7) 且 rm 失败(13) → **13**（同时记录 7）。
- 纯 SIGINT 无清理失败 → **130**。

**不承诺 OS 无法保证的结果**：若 `SIGKILL` 后进程仍存活（如 D 状态不可中断），harness 只报告 PID 与状态，不声称已终止；若 `rmSync` 因权限/挂载问题失败，harness 只报告路径与 errno，不声称已删除。

### 12.1 systemd

| 层级 | 内容 |
|---|---|
| **原始输出** | `data`=755、`forum.db`=644、`secret.key`=600、`admin-token.key`=600；`/proc/2144097/status` `Umask: 0022` |

## 16. 失败处理与回滚方案

### 16.1 回滚触发条件（任一）

`is-active` 非 `active`；`/api/topics` 5xx 上升或新增 `[500]`；L3 探针出现伪造 IP 被采信；注册 429 异常激增；`ip=` 缺失/格式错；白名单之外文件哈希变化。

### 16.2 回滚步骤（逐文件，禁整目录覆盖）

1. `systemctl stop mcu-forum-api`（提前知会）。
2. 从备份**逐文件**恢复 `server.js`、`config.js`。
3. **删除**新增 `lib/client-ip.js`。
4. 校验：`sha256sum server.js config.js` 回到原值；`ls lib/` 与备份一致。
5. `systemctl start` → 复检 `is-active`、`ss -lntp | grep 8787`、`journalctl -n 20`。
6. 记录时间、原因、恢复后哈希。

### 16.3 配置与数据兼容性

回滚 = 恢复 config.js 默认值；无数据迁移；必须重启；**绝不触碰** `data/`、`forum.db`、`secret.key`、`admin-token.key`。

### 16.4 防覆盖他人在途改动

白名单文件操作；禁 `rsync --delete`、禁整目录覆盖、禁 `git`；发布前后各跑一次全目录 `sha256sum`。

### 16.5 运维检查清单

| 检查项 | 频率 |
|---|---|
| nginx `X-Real-IP $remote_addr` 必须存在 | 每次改 nginx 后 |
| 应用仍仅监听 `127.0.0.1:8787` | 每次改 unit 后 |
| unit 未新增 `Environment=`/`EnvironmentFile=` | 每次改 unit 后 |
| `TRUSTED_PROXIES` 与实际拓扑一致 | 架构变更时 |
