## 0. 一句话定位

**MCU 观影导航 = 陪用户探索漫威宇宙的观影助手。**

以「作品 + 关系 + 路线 + 进度」为内容核心，覆盖三端，服务「传播 → 首体验 → 长期使用」闭环。
核心用户路径：`顺序 → 路线 → 下一部 → 关系 → 地图 → 进度`。

**三端不是替代关系，而是分工**：H5 负责外部获客与首次体验；两个小程序负责长期使用与观影进度沉淀。

## 5. 已知约束与红线

### 5.1 治理铁律（不可协商）

- **恢复 > 理解 > 验证 > 修复 > 优化**——不重写、不重构、不重新设计。
- **数据单一源**：`shared/data/*.js` 是跨端唯一数据源（11 个文件，含 CONTENT 59 / RELATIONS 92 / ROUTES 11 / CHARACTERS 24）。
  禁第二套、禁编造、**不得丢入 CMS 让用户自改**。
- **角色隔离**：设计 AI **不直接改源码**，方案通过 `给设计AI同步文件.txt` 输出，由开发 AI（Work）实现。
- **不擅自增页 / 改布局 / 换组件风格**——设计可以提方案，执行需用户（项目负责人）拍板。

### 5.2 审核红线（血泪史，直接影响视觉判断）

- 抖音端曾因「文娱-资讯」类目不符个人主体资质被驳回 → 改类目 + 工具化收敛才过。
- 微信端刚因「**涉及视频服务**」被驳回（审核员盯上的就是首页 Hero 海报墙 + 金色「继续观看」CTA）。
- **结论**：你的视觉方案若强化「深黑海报墙 + 大号观看按钮」的流媒体观感，等于给下轮审核递刀。
  升级时请主动弱化「像视频 App」的联想，强化「工具/图鉴/进度」的工具属性。

### 5.3 其他

- **禁止缩小 Hero 卡片尺寸**偏离规范。
- 小程序无用 `web-view`、无 `navigateToMiniProgram`、无外部视频链接（保持现状）——这是避免触碰视频类目的事实基础。
- 图片资源 CDN：`https://mcu.yaokaixin.top`（H5 与两小程序共用；旧域保留作资源域），资源含 posters/stills/avatars/phases/hero/entries。
- H5 与小程序尚未做 token 统一——**是否统一，是需要你在升级方案里先回答的产品/设计问题**，不要默认统一。

## 6. 协作方式与产出规范

**通道**：`docs/同步/给设计AI同步文件.txt`（无空格文件名）——这是你的窄向协同通道，由开发/策划维护输入。
**约定**：

1. 交付物写**完整绝对路径 + 扩展名**；修改列表给**相对路径**。
2. 超过约 150 行时**整体覆盖重写为「当前态」**（归档后重写），而非无限追加。
3. 方案里要区分：新增元素 / 修改元素 / 删除元素，并标注影响的端（H5 / 微信 / 抖音 / 全端）。
4. 涉及 Token 变更 → 必须先改 `app.wxss`（小程序）或 `style.css`（H5）的 `:root`/`page`，再同步回 `DESIGN.md`。
5. 不要直接改动 `wechat/`、`douyin/`、`h5/`、`shared/` 下任何源码文件。

**开始前建议先读**：`DESIGN.md`（设计系统单一可信源）、`MCU项目总览.md`（AI 协作总览，含完整架构/部署/治理/待办）。
