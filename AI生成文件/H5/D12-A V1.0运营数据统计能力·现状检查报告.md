## 一、四项能力检查结论

### 1. H5 是否已有统计 SDK —— ❌ 完全没有

| 检查项 | 结果 |
|---|---|
| 第三方统计脚本签名（百度 `hm.js` / GA `gtag` `analytics` / CNZZ / 神策 `sensorsdata` / 友盟 `umeng` / 腾讯统计 `tajs` / `_hmt` / `_ga`） | 全站 0 命中 |
| 全部 6 个 HTML 页面 `<head>`/底部 `<script src>` | 仅加载本地 `data/*.js` + `assets/js/app.js`，**无任何 `http(s)://` 外部脚本** |
| 外部 `<link href="http">` | 0 命中（仅本地 `style.css`） |
| 唯一网络写请求 | 仅用户主动「吐槽」时写 CloudBase `feedback` 集合（与统计无关） |

**结论**：H5 当前**零埋点**，页面级 PV/UV/停留/点击/来源全部不可统计。首页那块「59 部 / 11 条路线 / 6 阶段」是**营销展示文案**（CSS 类 `.hero-stats`），不是统计数据。

### 2. 服务器能否查看 PV / UV / 请求日志 —— ⚠️ 控制台可得，但无渠道维度

- CloudBase **静态托管**在腾讯云控制台提供「访问统计」（PV/UV/带宽）与「访问日志」（可下载按 URL、Referer、UA、IP、状态码分析）。
- 这是**产品能力，不改代码即得**：抖音/小红书外链一旦有人打开，控制台即产生 PV/UV。
- **局限**：
  - 聚合口径，**无法区分 douyin / xiaohongshu**（除非 URL 带 `?from=` 渠道参数，而当前 H5 不读、日志里也无此维度）；
  - 抖音/小红书分享出的页面通常不携带清晰 `Referer`，控制台日志大概率只能看到托管域名、看不到具体渠道；
  - 具体数字需登录腾讯云控制台查看（本次只读审计未登录控制台，不编造数字）。

**结论**：PV/UV「总量」兜底可得；「渠道细分」必须靠 H5 改代码接 `?from=` 才能精确归因。

### 3. H5 能否读取 URL 参数 —— ✅ 能读，但渠道参数从未被消费

`app.js` 已实现参数读取能力：
- `resolveContext()`（app.js:1159）：用 `new URLSearchParams(location.search)` 读取 `page` / `movieId`( `?id=` ) / `routeId`( `?r=` ) / `exploreId`( `?focus=` ) / `name`。
- 通用 `getParam` 正则（app.js:957）存在。
- **已被消费的参数是内部导航参数**：`movie.html?id=` `routes.html?r=` `map.html?focus=` `next.html?from=<movieId>`（注意：此 `from` 是"下一部"的电影 id，非渠道）。
- **渠道参数 `?from=douyin` / `?from=xiaohongshu` / `utm_*` 完全未被任何代码读取或写入**。SEO canonical 逻辑（app.js:1024）甚至主动剔除 `?from=` `?r=` `?focus=`，只保留 `?id=`。

**结论**：技术能力具备，**缺口在"没把渠道参数接到统计/存储"**，而非"读不了"。

### 4. H5 → 小程序转化统计 —— ❌ 有入口、零归因

- H5 已存在转化入口：`mpEntry` 转化卡 + `openMpModal` 扫码面板（展示 `assets/miniprogram/qrcode.png`）。
- `openMpModal` 仅把 `movieId/routeId/exploreId` 暂存进面板 `data-mp-payload`（app.js:821），注释明确「**当前仅预留，不跳转**」。
- 小程序码是**静态图**，不带微信 `scene` 场景值 → **无法区分"谁扫的、从哪个渠道来"**。
- 小程序侧（Step3-8）已预留 `?channel=` 入参写入 `feedback` 集合，但 H5 侧未生成也不传递该值。

**结论**：转化入口在，但"从哪个渠道来、是否扫码进小程序"**完全不可归因、不可统计**。

## 二、关键缺口清单（建设必做项）

| # | 缺口 | 影响 | 建设手段 |
|---|---|---|---|
| G1 | H5 零统计 SDK | PV/UV/页面行为全盲 | 接入统计 SDK（百度统计 / GA4 / 腾讯统计 / 自采） |
| G2 | H5 不读 `?from=` 渠道参数 | 渠道细分不可归因 | 改 `resolveContext` 读取 `from/channel` 并上报 |
| G3 | 渠道参数未落库 | 无法做渠道×内容交叉分析 | H5 分享链接统一带 `?from=`；写入 SDK 自定义维度 + `feedback` 集合 `channel` 字段 |
| G4 | 小程序码无 scene 值 | H5→小程序转化不可归因 | 改用带 `scene` 的动态小程序码 或 在 mpEntry payload 带 channel |
| G5 | 控制台 PV/UV 无渠道维度 | 仅知总量不知来源 | 配合 G2/G3，SDK 上报渠道维度 |

## 三、建设方向建议（第二步要做的，待指令）

> 以下为建议，本次**未执行**，等你确认后进入第二步。

1. **统计 SDK 选型**：国内合规首选**百度统计**或**腾讯统计**（无需翻墙、国内访问快）；如需国际口径可选 GA4。H5 系静态页，SDK 仅需一行 `<script>` 注入 `index.html` 全局（或 app.js 统一初始化）。
2. **渠道参数规范**：统一约定 `?from=douyin` / `?from=xiaohongshu` / `?from=wechat` / `?from=direct`，抖音/小红书投放链接统一带参。
3. **H5 改动点（最小集）**：
   - `app.js` `resolveContext()` 增读 `from/channel`；
   - 全局初始化 SDK 并上报 `page + channel`；
   - 分享卡/CTA 链接拼 `?from=`；
   - `feedback` 提交补 `channel` 字段（与小程序 Step3-8 已对齐字段）。
4. **H5→小程序转化归因**：小程序码改用动态码带 `scene=channel_xxx`；或 mpEntry payload 透传 channel 至小程序 onLaunch 参数。
5. **不动的部分**：MCU 数据、路线、页面结构、视觉——本次仅加统计层。
