# MCU观影导航 V1.2 UI Design System

> 版本：V1.2
> 设计定位：漫威宇宙探索助手
> 视觉关键词：黑色影院 · 宇宙探索 · 档案馆 · 金色强调 · 高级感
> 产品气质：打开后像进入漫威宇宙控制中心
> 输出方：QoderWork CN（设计AI）
> 状态：待策划AI（GPT）确认

---

## 一、产品视觉定位

### 1.1 核心命题

V1.2 的视觉升级不是"换个皮肤"，而是解决一个产品气质问题：当前小程序看起来像"漫威数据库后台管理工具"，而我们需要它看起来像"陪用户探索漫威宇宙的观影助手"。

用户打开这个小程序的 30 秒内，应该感受到的是"我进入了漫威宇宙的控制中心"，而不是"我打开了一个电影列表"。

### 1.2 视觉定位语

**"深空影院中的金色叙事"**

- 深空 = 深色背景营造的沉浸感（不是纯黑，是有层次的深蓝黑）
- 影院 = 电影感的视觉体验（宽呼吸、大字号、克制的信息密度）
- 金色 = 唯一的强调色，引导视线、标记重要信息
- 叙事 = 不是平铺数据，而是引导用户一步步探索

### 1.3 三级视觉金字塔

```
        ┌─────┐
        │ 金色 │  ← 引导层：CTA按钮、选中态、品牌标识
        │ 强调 │     占比 < 5%，但决定产品气质
        ├─────┤
        │ 文字 │  ← 信息层：标题白、描述灰、辅助浅灰
        │ 层级 │     占比 ~25%，通过字号和色阶建立阅读节奏
        ├─────┤
        │ 深空 │  ← 背景层：四级深色背景，营造沉浸画布
        │ 底色 │     占比 ~70%，安静、不抢戏
        └─────┘
```

### 1.4 设计原则

原则一：**少即是多。** 如果一个元素不能帮助用户决定"下一步看什么"或"接下来探索什么"，它就不应该出现在界面上。

原则二：**呼吸感优先。** 模块之间留足空间，让页面有"段落感"。宁可让用户多滑一次，也不要让页面看起来像一块密不透风的信息墙。

原则三：**金色克制。** `--gold` 是唯一的强调色。如果一个页面中有两个以上的高饱和色在"抢"用户注意力，说明设计出了问题。

原则四：**一致性即品质。** 所有页面使用同一套色彩、字号、间距、卡片规范。用户不应该在不同页面之间跳转时感受到风格跳跃。

## 二、整体设计风格

### 2.1 色彩策略

整个产品的色彩策略是"深空底色 + 金色叙事"。大面积深色背景营造影院沉浸感，金色作为唯一的强调色贯穿全产品，承担"引导视线"和"标记重要信息"两个职责。阶段色仅用于内容分类标识（如电影属于哪个Phase），不参与 UI 框架。

### 2.2 视觉呼吸策略

V1.1 的核心问题是信息密度过高——页面倾向于平铺所有内容，缺少"视觉休息点"。V1.2 通过以下手段解决：

- 模块间距（48rpx）显著大于卡片内间距（16-24rpx），建立"段落感"
- 页面左右边距统一 32rpx，让内容不贴边
- 每个页面只有一个"视觉焦点"（Hero Card 或大号数字），其余信息退后
- 卡片之间不紧贴，至少保留 16rpx 间距

### 2.3 三级视觉层次

产品中的每个界面元素都应该能归入三个层次之一：

| 层次 | 职责 | 视觉特征 |
|------|------|---------|
| 引导层 | 吸引用户点击最重要的入口 | 金色、大字号、Hero Card |
| 信息层 | 传递核心内容 | 白色标题、灰色描述、二级卡片 |
| 背景层 | 营造沉浸氛围 | 深色背景、微弱边框、安静不抢戏 |

### 2.4 风格禁区

以下是 V1.2 明确禁止的风格方向：

- 禁止使用渐变背景作为大面积 UI 元素底色（海报占位除外）
- 禁止使用阴影（box-shadow）来建立层级——用色阶差异代替
- 禁止使用圆角超过 24rpx 的元素（除 Hero Card 外）
- 禁止使用动画时长超过 400ms 的动效
- 禁止使用弹跳（bounce）、旋转进入、闪烁等"活泼"动效

## 三、色彩系统

### 3.1 统一色板（消除双色彩体系）

V1.2 的关键决策：将首页 V1.2 的色值吸收为全局标准。首页的色值调整方向是正确的——背景更深（`#080B12`）、金色更亮（`#F2B233`），这符合"黑色影院"的定位。V1.2 让所有页面统一使用这组更优的色值，消除页面间跳转时的色温跳跃。

### 3.2 背景层

| Token | 色值 | 用途 | 说明 |
|-------|------|------|------|
| `--bg` | `#080B12` | 页面底色 | 深空黑，微蓝偏冷。所有页面的基础画布 |
| `--surface-1` | `#161D2B` | 一级卡片 / Tab栏 | 从底色中"浮起"的第一层 |
| `--surface-2` | `#1E2636` | 二级卡片 / 内容区块 | 在一级卡片之上的信息容器 |
| `--surface-3` | `#2A3447` | 边框 / 分割线 / 交互态底色 | 用于需要可辨识但不抢眼的边界 |

色阶间距说明：`#080B12` → `#161D2B` → `#1E2636` → `#2A3447`，每级亮度递增约 8-12%，层级感清晰但不过度对比。

### 3.3 品牌色

| Token | 色值 | 用途 |
|-------|------|------|
| `--gold` | `#F2B233` | 主强调色。CTA按钮、选中态、品牌标识、进度指示 |

饱和度略增，在深色背景上更醒目，更接近"档案馆金色铭牌"的质感。

### 3.4 文字层

| Token | 色值 | 用途 | 对比度（vs `#080B12`） |
|-------|------|------|----------------------|
| `--text-main` | `#E8ECF4` | 标题、核心信息 | ≈14.5:1 |
| `--text-sub` | `#8E98AA` | 描述文字、次要信息 | ≈6.2:1 |
| `--text-weak` | `#555F73` | 辅助标签、禁用态 | ≈3.2:1 |

三级文字色阶的效果：字号越大越白，字号越小越灰。用户不需要"阅读"就能感知到信息的优先级。

### 3.5 状态色

| Token | 色值 | 用途 |
|-------|------|------|
| `--success` | `#3FB98A` | 已观看、已完成 |
| `--error` | `#E5604D` | 错误、警告 |

### 3.6 阶段色（仅用于内容标识）

| Token | 色值 | 阶段 |
|-------|------|------|
| `--p1` | `#5B8DEF` | Phase 1 |
| `--p2` | `#28B487` | Phase 2 |
| `--p3` | `#F0A932` | Phase 3 |
| `--p4` | `#8B6FE8` | Phase 4 |
| `--p5` | `#E8483F` | Phase 5 |
| `--p6` | `#C25B8E` | Phase 6 |

**阶段色使用规则：** 阶段色只出现在"内容本身"上（电影卡片左侧色条、角色阵营标识、时间线节点），不出现在 UI 框架元素上（按钮、边框、图标）。这条规则是防止界面变成"彩虹"的关键。

### 3.7 透明度变体

| Token | 色值 | 用途 |
|-------|------|------|
| `--gold-a06` | `rgba(242,178,51,0.06)` | 金色微光背景（选中卡片渐变起点） |
| `--gold-a10` | `rgba(242,178,51,0.10)` | 金色淡背景（chip、标签） |
| `--gold-a15` | `rgba(242,178,51,0.15)` | 金色轻背景（hover态） |
| `--gold-a20` | `rgba(242,178,51,0.20)` | 金色边框（选中态边框） |
| `--gold-a40` | `rgba(242,178,51,0.40)` | 金色图标/装饰 |
| `--gold-a60` | `rgba(242,178,51,0.60)` | 金色次强调 |

注意：所有 `--gold-a*` 的 RGB 值统一为 `(242,178,51)` 以匹配 `--gold`。

### 3.8 色彩使用纪律

规则一：所有颜色必须引用 CSS 变量（`var(--xxx)`），禁止在页面 WXSS 中写死 hex 值。

规则二：阶段色不参与 UI 框架，只标记内容归属。

规则三：`--gold` 是唯一的强调色。如果一个页面中出现了第二种高饱和色承担"引导点击"的职责，说明设计出了问题。

规则四：`app.json` 中不能使用 CSS 变量，必须写死 hex 值，但这些值必须与对应 token 完全一致。

### 3.9 需要废弃的 Token

| Token | 原因 |
|-------|------|
| `--line`（`#202938`） | 功能与 `--surface-3` 重叠，统一到 `--surface-3` |
| 旧的 `--gold-a*` 系列（基于 `rgb(233,169,59)`） | 全部更新为基于 `rgb(242,178,51)` 的新值 |

## 四、字体系统

### 4.1 设计原则

字号层级的核心目标不是"精确到每个像素"，而是让用户在快速扫视时能清晰感知"这是标题、这是描述、这是辅助信息"三个层级。V1.2 将 15+ 种字号收敛为 5 级。

### 4.2 字族

```css
font-family: -apple-system, "PingFang SC", "Helvetica Neue", Helvetica, sans-serif;
```

系统字体栈在小程序环境中是最优选择，保持不变。

### 4.3 字号层级（5级制）

| 层级 | Token | 字号 | 字重 | 行高 | 用途 |
|------|-------|------|------|------|------|
| Display | `--fs-display` | `48rpx` (24px) | 700 | 1.3 | 页面主标题、品牌标题。每页最多1次 |
| Title | `--fs-title` | `34rpx` (17px) | 600 | 1.4 | 模块标题、卡片标题 |
| Body | `--fs-body` | `28rpx` (14px) | 400 | 1.5 | 正文、描述文字、按钮文字 |
| Caption | `--fs-caption` | `24rpx` (12px) | 400 | 1.4 | 辅助信息、标签、时间戳 |
| Mini | `--fs-mini` | `20rpx` (10px) | 500 | 1.3 | 极小标注、阶段标记、chip内文字 |

收敛规则说明：
- 原 36rpx/40rpx/44rpx/48rpx 统一收敛到 Display 48rpx。子页面（如电影详情页标题）可用 `--fs-display-sm: 40rpx` 作为变体，Tab 页面统一 48rpx
- 原 30rpx/32rpx 合并到 Title 34rpx
- 原 26rpx/28rpx 合并到 Body 28rpx
- 原 22rpx/24rpx 合并到 Caption 24rpx
- 原 18rpx/20rpx 合并到 Mini 20rpx
- 56rpx/60rpx/64rpx/72rpx 仅在"我的MCU"已观看大数字等特殊情感场景使用，不作为通用层级

### 4.4 文字颜色映射

| 场景 | 使用 Token |
|------|-----------|
| Display / Title 层级 | `--text-main` |
| Body 层级（正文描述） | `--text-sub` |
| Caption / Mini 层级 | `--text-weak` |
| 金色强调文字 | `--gold` |
| 阶段标识文字 | `--p1` ~ `--p6` |

### 4.5 字重规则

全产品只使用三个字重：400（常规）、500（中等，用于 Mini 层级和需要轻微强调的 Caption）、600（半粗，用于 Title 及以上）。700 仅用于 Display 层级。不使用 700 以上的字重。

## 五、间距规范

### 5.1 设计原则

间距是解决"信息密度过高"问题的关键手段。V1.2 引入明确的呼吸节奏：模块之间的间距大于模块内部的间距，让页面有"段落感"而不是"一整块"。

### 5.2 间距层级（7级）

| Token | 值 | 用途 |
|-------|-----|------|
| `--space-xs` | `8rpx` (4px) | 图标与文字之间、chip内部 |
| `--space-sm` | `16rpx` (8px) | 卡片内部元素间距 |
| `--space-md` | `24rpx` (12px) | 卡片内边距、列表项间距 |
| `--space-lg` | `32rpx` (16px) | 模块内部间距、分割线间距 |
| `--space-xl` | `48rpx` (24px) | 模块之间间距 |
| `--space-2xl` | `64rpx` (32px) | 页面顶部/底部安全间距 |
| `--page-x` | `32rpx` (16px) | 页面左右边距 |

### 5.3 页面布局骨架

```css
.mcu-page {
  background: var(--bg);
  padding: 0 var(--page-x) var(--space-2xl);
  min-height: 100vh;
}
```

所有 Tab 页面的内容区域左右边距统一 32rpx。模块之间间距统一 48rpx。这是建立"呼吸感"的底线。

### 5.4 间距使用规则

规则一：模块标题与上方模块的间距 = `--space-xl`（48rpx）。

规则二：模块标题与模块内容的间距 = `--space-lg`（32rpx）。

规则三：卡片与卡片的间距 = `--space-sm`（16rpx）。

规则四：卡片内部标题与描述的间距 = `--space-xs`（8rpx）。

规则五：页面底部安全间距 = `--space-2xl`（64rpx）。

## 六、卡片组件规范

### 6.1 设计原则

卡片是 MCU 导航最核心的信息容器。V1.2 将全产品的卡片收敛为三种类型，通过"层级"而非"样式变化"来区分重要性。

### 6.2 三级卡片体系

#### 一级卡片（Hero Card）

用于页面中最重要的信息入口，如首页"继续观看"、路线推荐。

```css
.card-hero {
  background: var(--surface-1);
  border: 2rpx solid var(--surface-3);
  border-radius: 24rpx;
  padding: 32rpx;
}
```

视觉特征：大圆角、宽内边距、一级底色。每页最多 1-2 个。

#### 二级卡片（Content Card）

用于常规内容展示，如电影列表项、角色卡片、路线节点。

```css
.card-content {
  background: var(--surface-2);
  border: 1rpx solid var(--surface-3);
  border-radius: 16rpx;
  padding: 24rpx;
}
```

视觉特征：中等圆角、二级底色。页面中的主要卡片类型。

#### 三级卡片（Compact Card）

用于辅助信息、横向滚动列表项等轻量场景。

```css
.card-compact {
  background: var(--surface-2);
  border-radius: 12rpx;
  padding: 16rpx 20rpx;
}
```

视觉特征：小圆角、无边框、紧凑内边距。可大量使用。

### 6.3 卡片交互态

| 状态 | 样式变化 |
|------|---------|
| 默认 | 如上定义 |
| 选中/激活 | `border-color: var(--gold-a20)` + `background: linear-gradient(135deg, var(--gold-a06), var(--surface-2))` |
| 按下 | `opacity: 0.85` |

### 6.4 卡片内容结构规范

一级卡片内部结构：
```
[图标/标识] ← 32rpx 间距 → [标题 (Title/600)] ← 8rpx → [描述 (Body/--text-sub)]
```

二级卡片内部结构：
```
[左侧：海报/图标] ← 20rpx → [右侧：标题 (Title/600) + 描述 (Caption/--text-weak)]
```

三级卡片内部结构：
```
[名称 (Body)] ← 8rpx → [辅助信息 (Mini/--text-weak)]
```

### 6.5 现有页面卡片迁移对照

| 页面 | 当前样式 | V1.2 迁移到 |
|------|---------|------------|
| 首页 `.card` | 32rpx radius, 32rpx padding | `.card-hero` |
| 路线 `.route-card` | 16rpx radius, 28rpx padding | `.card-content` |
| 电影 `.resource-module` | 24rpx radius, 28rpx padding | `.card-content` |
| 探索 `.entry-card` | 20rpx radius, 28rpx padding | `.card-content` |
| 角色 `.char-card` | 20rpx radius, 24rpx padding | `.card-content` |
| 浏览 `.film-row` | 16rpx radius, 20rpx padding | `.card-compact` |
| 全景 `.pano-node` | 12rpx radius | `.card-compact` |
| 路线详情 `.rd-node` | 16rpx radius, 24rpx padding | `.card-content` |
| 我的MCU `.work-card` | 16rpx radius, 20rpx 24rpx padding | `.card-content` |

## 七、Icon 规范

### 7.1 设计原则

当前混用 CSS 图标、Unicode 字符和 PNG 是"工具感"和"不统一感"的重要来源。V1.2 统一为一种策略：内联 SVG 组件（在小程序中通过 `<image>` 引用 SVG 文件或使用 base64 内联）。

### 7.2 图标风格

线性图标（Outlined），1.5px 描边，圆角端点。与"档案馆"气质一致——精致、克制、不花哨。

禁止使用填充图标（Filled）作为功能图标。填充风格仅用于 Tab 栏选中态。

### 7.3 图标尺寸

| 场景 | 尺寸 | 说明 |
|------|------|------|
| 模块入口图标 | `48rpx × 48rpx` | 探索页入口、首页快捷入口 |
| 卡片内图标 | `36rpx × 36rpx` | 卡片中的功能标识 |
| 行内图标 | `28rpx × 28rpx` | 与文字同行的图标 |
| 微型图标 | `24rpx × 24rpx` | chip内、标签内 |
| Tab 栏图标 | `48rpx × 48rpx` | 保持现有尺寸（81px PNG @3x） |

### 7.4 图标颜色规则

| 场景 | 颜色 |
|------|------|
| 默认态 | `--text-weak` |
| 激活/选中态 | `--gold` |
| 品牌入口装饰 | `--gold-a40` |
| 阶段标识 | 对应 `--p1` ~ `--p6` |

### 7.5 Unicode 字符替换方案

| 当前用法 | 替换为 |
|---------|--------|
| `◈`（宇宙全景） | 定制 SVG：星系/全景图标 |
| `✦`（角色图鉴） | 定制 SVG：人物/图鉴图标 |
| `◷`（关系探索） | 定制 SVG：连线/关系图标 |
| `›` / `»`（箭头） | 定制 SVG：chevron-right |
| `√`（成功） | 定制 SVG：check-circle |
| `!`（错误） | 定制 SVG：alert-circle |
| `★`（收藏） | 定制 SVG：star |

### 7.6 CSS 图标处理

现有的纯 CSS 图标（播放三角、对勾、chevron）保留，但需要统一到上述尺寸和颜色规范。CSS 图标的描边粗细和角度需要与 SVG 图标视觉一致。

## 八、按钮规范

### 8.1 设计原则

按钮是用户操作的核心入口。V1.2 将按钮收敛为三种类型，通过视觉权重区分优先级。每页最多只有 1 个 Primary 按钮。

### 8.2 三级按钮体系

#### Primary Button（金色 CTA）

页面中最重要的操作入口。

```css
.btn-primary {
  background: var(--gold);
  color: var(--gold-btn-text);  /* #1A1206，深色文字 */
  border-radius: 16rpx;
  height: 88rpx;
  font-size: var(--fs-title);   /* 34rpx */
  font-weight: 600;
  border: none;
}
```
