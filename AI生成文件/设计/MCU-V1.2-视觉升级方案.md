## 一、视觉方向重新定义

### 1.1 问题诊断

当前版本的根本问题不是字号或间距，而是**缺少视觉资产**。页面由文字和色块构成，用户感受不到漫威宇宙的存在。

具体表现：
- 电影 = 阶段色块 + 首字（没有海报）
- 角色 = 彩色圆圈 + 首字（没有头像）
- 首页 = 功能入口列表（没有氛围）
- 全景图 = 线条节点图（没有沉浸感）
- 整体 = 数据管理后台（不像 MCU 产品）

### 1.2 目标定义

用户打开小程序 30 秒内应该感受到：

**"这是漫威宇宙"** — 不是"这是一个工具"

关键词：
- **沉浸** — 打开即进入 MCU 世界
- **图片驱动** — 海报、角色照、场景图代替文字色块
- **暗黑高级** — 深色背景 + 金色点缀 + 图片质感
- **旅程感** — 用户在宇宙中探索，不是在看数据库

### 1.3 视觉参考

参考 Marvel Studios 官方视觉语言：
- Disney+ 的 MCU 浏览界面（暗底 + 大海报 + 横向滚动）
- 漫威官网的角色卡片（大图 + 阵营色 + 简洁信息）
- 电影海报的视觉质感（阶段色 + 角色群像 + 史诗感）

### 1.4 设计原则

1. **图片优先**：能用图片的地方不用文字，能用大图的地方不用小图
2. **暗色画布**：深色背景是画布，让图片成为焦点
3. **金色克制**：金色只用于强调和引导，不铺面积
4. **阶段色氛围**：6 个阶段的颜色不仅用于标识，更用于营造区域氛围
5. **优雅降级**：图片加载前/失败时有体面的占位态（阶段色渐变 + 首字）

### 2.6 图片加载策略

**为什么不能全部打包进小程序：**
- 微信主包限制 2MB，全部图片 ~4.3MB 超出限制
- 即使分包，用户首次加载也会很慢

**推荐方案：网络图片 + 本地缓存**
- 图片托管在图床/云存储（腾讯云 COS / 七牛云 / 任何可生成 URL 的服务）
- 小程序通过 URL 加载图片
- 利用微信的 `wx.getImageInfo` 缓存机制，加载过的图片自动缓存
- 图片加载期间显示阶段色渐变占位（已有 poster-pN 样式）

**降级方案（图片未就位时）：**
- 海报位：阶段色渐变 + 首字（当前实现，保留作为 fallback）
- 角色头像：阵营色渐变 + 首字（当前实现，保留作为 fallback）
- 背景图：纯色 --bg（当前实现）

## 四、图片组件规范

### 4.1 通用图片组件 `<mcu-image>`

所有图片加载统一使用一个行为模式（开发实现为 CSS + WXML）：

**加载态：**
- 显示阶段色渐变背景 + 居中首字（复用当前 poster-pN 样式）
- 保证图片未加载时页面不空白

**加载成功：**
- 渐变淡入（transition: opacity 0.3s）

**加载失败：**
- 保持阶段色渐变 + 首字（优雅降级，不显示 broken image icon）

## 五、开发实现说明

### 5.1 实施前提

图片资源需要先行就位（至少就位海报和角色头像），才能进行视觉升级。建议分两步：

**Step 1：图片资源采集**
- 开发 AI 按上述清单从百科抓取图片
- 按命名规范存放至 assets/ 目录
- 或上传至图床，生成 URL 列表

**Step 2：视觉升级实现**
- 修改 visuals.js，填充 poster/still 映射
- 修改各页面 wxml，将色块占位替换为 `<image>` 组件
- 修改各页面 wxss，调整布局以适配图片

### 5.2 visuals.js 数据对接

当前 visuals.js 已有空壳结构，开发只需填充映射：

```javascript
// visuals.js 需要填充的映射
const posters = {
  'iron-man': '/assets/posters/iron-man.jpg',
  'iron-man-2': '/assets/posters/iron-man-2.jpg',
  // ... 59 项
};

const characters = {
  'tony': '/assets/characters/tony.jpg',
  'steve': '/assets/characters/steve.jpg',
  // ... 24 位
};

const phases = {
  1: '/assets/phases/phase-1.jpg',
  2: '/assets/phases/phase-2.jpg',
  // ... 6 个阶段
};

const backgrounds = {
  'home': '/assets/bg/home-bg.jpg'
};
```

### 5.3 页面改动范围

| 页面 | wxml 改动 | wxss 改动 | js 改动 |
|------|----------|----------|--------|
| 首页 | 增加背景图区域、海报 image、头像 image | 背景图样式、图片容器 | 读取 visuals 数据 |
| 电影详情 | 海报 image 替换色块、关联海报 | 图片容器样式 | 读取 visuals 数据 |
| 角色图鉴 | 头像 image 替换色块、增加阵营色条 | 头像样式、卡片左边条 | 读取 visuals 数据 |
| 角色详情 | 头像 image + 背景图 + 海报 | 背景图样式、图片容器 | 读取 visuals 数据 |
| 全景图 | 结构重做（阶段卡片+海报横滚） | 全新样式 | 数据结构微调 |
| 探索 Tab | 头像 image 替换 | 头像样式 | 读取 visuals 数据 |
| 我的 MCU | 增加背景图、海报 | 背景图样式 | 读取 visuals 数据 |

### 5.4 约束

- 不改功能逻辑、不改跳转、不改数据模型结构
- visuals.js 作为图片数据的单一来源，页面通过它获取图片路径
- 所有图片组件必须有加载态和失败态（阶段色渐变兜底）
- 网络图片需设置合适的 placeholder 和 lazy-load

### 5.5 实施优先级

1. **最高优先**：59 张海报 + 24 张角色头像（覆盖所有页面的核心视觉）
2. **高优先**：首页背景图 + 6 张阶段代表图（氛围提升最大）
3. **中优先**：全景图结构重做（改动最大，需要更多开发时间）
4. **低优先**：功能入口图标（可用 Unicode 暂代）

## 六、验收标准

1. **图片覆盖**：所有海报位、头像位、背景位都显示真实图片（非色块首字）
2. **加载体验**：图片加载中显示阶段色渐变，不出现空白或 broken icon
3. **降级兜底**：图片加载失败时回退到阶段色渐变 + 首字
4. **视觉一致性**：所有图片圆角、边框风格统一
5. **性能**：首屏加载不卡顿，图片 lazy-load 正常
6. **层级清晰**：图片成为视觉焦点，文字信息有序退后
