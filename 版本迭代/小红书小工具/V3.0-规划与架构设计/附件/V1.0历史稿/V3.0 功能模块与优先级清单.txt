# V3.0 功能模块与优先级清单

> 版本：V1.0　日期：2026-11-10　状态：规划稿 · 待 ChatGPT 产品审查
> 配套主文档：《MCU ATLAS 小红书 V3.0 产品需求与架构设计 V1.0》
> 说明：本清单每个模块标注「开发成本 / 数据依赖 / 平台限制 / 用户价值 / 状态」。状态取值：继承(已有)、升级(已有扩展)、新增(无)、缺口(数据未就绪)。

---

## 0. 优先级总览

| 优先级 | 定位 | 模块 |
|---|---|---|
| **P0 架构基础** | 必须，先行 | 首页动态控制台、统一导航、统一用户状态 `MCU_USER`、V2.0 F1–F6 兼容继承 |
| **P1 核心联动** | 高价值 | 英雄关系探索、观影进度与路线联动、知识问答、三条完整用户路径 |
| **P2 体验增强** | 可分期 | 英雄组队器、成就系统、个人漫威档案、统一分享卡升级 |

原则：P0 不完成则 P1 无法落地；P1 不全则「三大系统并重」不成立；P2 可在 P1 上线后独立批次交付。

---

## 1. P0 · 架构基础

### 1.1 首页动态控制台
- 内容：品牌展示 + 今日探索推荐 + 我的观影进度 + 最近探索记录 + 继续上次路线 + 探索/观影/互动三区入口。
- 开发成本：中（改 `index.html` 首页区块 + `app.js` 首页渲染逻辑；复用现有 `refreshHomeProgress`）。
- 数据依赖：`MCU_USER.recentExplore`、`MCU_USER.currentRoute`、F5 统计。
- 平台限制：无新增（纯前端渲染）。
- 用户价值：高（首页从静态入口变为状态入口，契合 V3.0「综合助手」定位）。
- 状态：升级（V2.0 首页为静态 6 入口）。

### 1.2 统一导航
- 内容：探索/观影/互动三大区统一入口与返回栈。
- 开发成本：低（扩展 `showView` 与 `backBtn` 逻辑，新增互动视图切换）。
- 数据依赖：无。
- 平台限制：单页 SPA（禁 window.open，沿用现有切视图）。
- 用户价值：中（结构清晰）。
- 状态：升级。

### 1.3 统一用户状态 `MCU_USER`
- 内容：新建 `MCUUser` 存储模块（key `mcu-xhs-user-v2`，version 2），含 subscribe/emit、三级后端、v1→v2 迁移、损坏容错。
- 开发成本：中（基于 `progress.js` 的 `MCUProgress` 直接扩展字段与迁移）。
- 数据依赖：读 `mcu-xhs-progress-v1` 做迁移；写 `MCU_USER` 全量字段（见交付物③）。
- 平台限制：单 key ≤1MB / 总 ≤10MB（须设 `recentExplore`/`shareRecords`/`quiz.scores` 上限）。
- 用户价值：高（V3.0 一切联动的地基）。
- 状态：升级（F5 仅 watched/want/updatedAt）。

### 1.4 V2.0 F1–F6 兼容继承
- 内容：F1 观影顺序、F2 节点、F3 随机、F4 卡片、F5 进度、F6 复联5专题全部迁入新架构，不重写。
- 开发成本：低（迁移现有视图代码 + 数据读写切换到 `MCUUser`）。
- 数据依赖：现有 `data.js` / `MCUProgress` 逻辑。
- 平台限制：无新增。
- 用户价值：高（保护已验证资产）。
- 状态：继承。

---

## 2. P1 · 核心联动

### 2.1 英雄关系探索
- 内容：角色详情页 + 关系网络（共演推导弱关系 / 显式人物关系边）。
- 开发成本：中（前端）；**若做显式关系边则数据成本高为缺口**。
- 数据依赖：`characters.js`（已有 id/cn/en/camp/first/note）、`CONTENT.chars`（可推导共演）。
- 平台限制：无新增。
- 用户价值：高（探索系统核心差异点）。
- 状态：**缺口**（人物↔人物关系边在 `characters.js` 注释中明确为 TODO；先用共演推导，待数据补齐升级——见主文档 §8③）。

### 2.2 观影进度与路线联动
- 内容：F5 进度 + F6 路线 + `currentRoute` 在首页/路线/专题间联动。
- 开发成本：低（复用 F5 `routeProgress` + 新增 `currentRoute` 写入）。
- 数据依赖：`MCU_ROUTES`、`MCU_SPECIAL_ROUTES`、`MCU_USER.currentRoute`。
- 平台限制：无新增。
- 用户价值：高（V2.0 已具备基础，扩展成本低）。
- 状态：升级。

### 2.3 知识问答
- 内容：离线题库 + 答题 + 成绩回写 `MCU_USER.quiz`。
- 开发成本：中（前端）+ **题库数据成本中（纯事实题，禁复联5剧情推测）**。
- 数据依赖：**新增离线题库（当前任何数据源均无，见主文档 §8④）**。
- 平台限制：无新增（全离线）。
- 用户价值：高（互动系统入口，反哺探索与观影）。
- 状态：**缺口（需新建题库）**。

### 2.4 三条完整用户路径
- 内容：路径 A 英雄探索→观影计划 / B 观影计划→互动挑战 / C 知识问答→角色探索（详见交付物④）。
- 开发成本：中（编排现有模块 + 打通 `MCU_USER` 读写）。
- 数据依赖：上述各模块就绪。
- 平台限制：无新增。
- 用户价值：高（验证「三大系统并重」是否成立）。
- 状态：新增（编排层）。

## 3. P2 · 体验增强

### 3.1 英雄组队器
- 内容：基于阵营/角色选队，展示阵容与（离线定义的）协同说明。
- 开发成本：中。
- 数据依赖：`MCU_CAMPS`(8 阵营，已存在)、`characters.js`.camp(已存在)；协同规则需设计（非官方事实，须标注「玩法建议」）。
- 平台限制：无新增。
- 用户价值：中（分享钩子强）。
- 状态：新增。

### 3.2 成就系统
- 内容：由进度/挑战/问答派生成就，规则离线定义，回写 `MCU_USER.achievements`。
- 开发成本：低（规则引擎 + 派生）。
- 数据依赖：`MCU_USER` 全量；成就规则库（离线定义，小）。
- 平台限制：无新增。
- 用户价值：中（留存与分享）。
- 状态：新增。

### 3.3 个人漫威档案
- 内容：聚合偏好/已看/想看/成就/分享记录的可视化档案页。
- 开发成本：低（读 `MCU_USER` 聚合渲染）。
- 数据依赖：`MCU_USER` 全量。
- 平台限制：无新增。
- 用户价值：中（沉淀感 + 分享）。
- 状态：新增。

### 3.4 统一分享卡升级
- 内容：F4 扩展卡型——成就卡 / 档案卡 / 组队卡 / 挑战卡，统一 Canvas 模板与视觉。
- 开发成本：中（新增 draw 函数 + 类型切换）。
- 数据依赖：`MCU_USER` 各项；复用现有 `writeTempFile`→存相册/发笔记。
- 平台限制：postNote title≤20 / content≤1000 / 图 1–18 / 媒体禁 http（沿用 D-20260928-04）。
- 用户价值：高（小红书传播核心）。
- 状态：升级（F4 已有 4 卡型）。
