## 1. 平台能力核查（逐项，V1.1）

| # | 能力 | 状态 | 规则 / 约束 | 对 V3.0 影响 |
|---|---|---|---|---|
| 1 | 页面与内部导航 | ✅ | 单页 SPA、JS 切视图；禁 `window.open` / `target=_blank` | 四层架构仍为单容器多视图 |
| 2 | 工具内部状态共享 | ✅ | 同一小工具内 JS 全局 / 模块共享 | `MCUUser` 单模块共享可行 |
| 3 | 本地存储·持久化 | ⚠️ | `xhs.miniTool.setStorage/getStorage/removeStorage`（客户端 ≥9.46）；单 key ≤1MB、总 ≤10MB、JSON 串；**不保证永久** | `MCU_USER` 须 ≤1MB；进度可丢失重建 |
| 4 | 存储降级顺序 | ✅（V2.0 代码事实） | `xhs(≥9.46)` > `localStorage` > `memory`；降级仅由 API 不可用 / 版本不足 / 调用 reject 触发（`progress.js` L97–152） | 迁移与 `update()` 须沿用，不得理想化 |
| 5 | 网络请求 | ❌ | 禁 `fetch` / `XHR` / WebSocket / SSE / 外链资源 | V3.0 全离线；题库与数据均内置 |
| 6 | 外链与工具间跳转 | ❌ | 禁站外跳转；**不同小工具间无通信能力** | V3.0 不依赖跨工具 / 跨载体通信 |
| 7 | 分享卡生成 | ✅ | Canvas 2D → `writeTempFile`(base64→filePath) | F4 基础继承（P0），扩展卡型 P2 |
| 8 | 相册保存 | ✅ | `saveImageToPhotosAlbum`（9.42+） | 卡片存相册沿用；**真机未验证** |
| 9 | 发笔记 | ✅ | `postNote`：title≤20、content≤1000、图 1–18、媒体禁 http(s) | 卡片文案须遵守字数 |
| 10 | 文件读写 | ⚠️ | `writeTempFile`（卡片位图）；无通用文件系统读 | 仅用于卡片导出 |
| 11 | ZIP 包限制 | ✅ | 硬上限 10MiB，建议 <2MiB；根目录 `index.html`；脚本外置 | V2.0 产物 51KB；加题库后仍远小于上限 |
| 12 | 代码结构 / 审核 | ✅ | 禁内联脚本 / onclick / eval / WASM / Worker / iframe；经典脚本（禁 module） | 沿用外置 `<script>` 范式 |
| 13 | 评论互动 | ⚠️ | `interactionOpenApi`（9.49+），用户手势触发 | 可选增强，不在本期核心 |
| 14 | 剪贴板 | ❌ | `navigator.clipboard` 禁用 | 分享文案引导长按 / 选中复制 |
| 15 | 脚本加载 | ✅ | 仅 `<script src>` 外置；数据以 `.js` 全局变量内置（因 fetch 禁用） | 沿用 `build-data.js` |

> ⚠️ **未经最新官方文档复核的规范，继续一律标记为待复核**。项目内引用的是 2026-08-11 版《小工具容器能力清单》；本环境未检出 CodeBuddy `minitool-zip-builder` Skill 参考文档，故下表结论以项目已固化记录 + V2.0 实际代码为依据。

## 2. 技术风险清单（V1.1）

| 编号 | 风险 | 影响 | 概率 | 缓解 / 处置 |
|---|---|---|---|---|
| R-01 | 真机 Storage 不保证永久，进度 / 成就丢失 | 个性化体验断裂 | 中（平台已知） | 状态可丢失重建；不依赖云端；关键处提示「本机保存」 |
| R-02 | `MCU_USER` 超 1MB 单键上限 | 写入失败 / 数据损坏 | 低 | 全字段设上限与截断（数据结构 §2.3）；容量实测待复核 Q-06 |
| R-03 | **未知版本数据被覆盖**（V1.0 表述缺陷） | 用户数据不可逆丢失 | 中（设计缺陷已修） | V1.1：保留原始、禁止写入覆盖、不持久化、只读运行（§3.2） |
| R-04 | **xhs `getStorage` 成功但返回空时不回退 localStorage 副本**（`progress.js` L102–103 / L104） | 写失败降级到 localStorage 的当次数据，在后续 xhs 正常的会话中不被自动恢复 | 中（V2.0 代码事实） | V1.1 迁移阶段主动比对两后端；**列为未解决风险，须真机确认**，不得假设自动双副本恢复 |
| R-05 | 迁移非幂等 / 未回读校验即清旧键 | 重复迁移覆盖新数据或旧数据丢失 | 中 | V1.1 六条安全规则：幂等、写后回读校验通过才清旧键、失败保留旧键 |
| R-06 | 损坏数据被全量清空 | 合法字段一并丢失 | 中 | 逐字段校验、局部保留（沿用 V2.0 `parse` 范式）；原损坏串不覆盖 |
| R-07 | Storage 写入失败 | 当次操作丢失 / UI 状态与持久化不一致 | 中 | xhs reject → localStorage；全失败 → memory 保当次、内存不回滚、`emit(persisted:false)` + 提示 |
| R-08 | 视图绕过 `MCUUser` 直写状态 | 数据不一致、无法审计 | 中 | 唯一写入口 `update()` + 七个业务方法；禁止旁路（数据结构 §4.1） |
| R-09 | 人物↔人物关系边缺失（`characters.js` 明确 TODO） | 完整英雄关系网络无显式 why | 高（已确认） | P1 仅做共演轻量关联；完整网络移 P2，待策划 AI 补数据 |
| R-10 | 离线知识问答题库不存在 | 路径 B/C 部分不通 | 高（已确认） | V3.0 内新建纯事实题库；禁复联5剧情推测；未建前不得排期 |
| R-11 | 复联5未确认剧情 / 角色被编造 | 审核与合规风险 | 中 | 沿用 D-20261110-04：仅官方定档，推测显式标注 |
| R-12 | V2.0 提交状态冲突（指令 vs 交付报告） | V3.0 与未定稿 V2.0 冲突 | 中（待确认） | 先裁定 V2.0 真实状态再排期 |
| R-13 | 真机端能力（save / postNote）未验证 | 分享链路真机失败 | 中 | 不作已验证结论；沿用降级提示；**真机验收由用户本人执行** |
| R-14 | 官方规范更新（Storage / FileSystem / postNote 字段） | 审核退回 | 低 | 送审前复核官方在线文档最新版（⚠️ 待复核） |
| R-15 | 包体积随题库增长 | 超 2MiB 建议值 | 低 | 题库为文本，构建期统计监控（`build-report.json`） |
| R-16 | 互动模块成为互不相关小游戏 | 背离「综合助手」定位 | 中 | 强制经 `MCU_USER` 回写并关联角色/作品/进度/成就 |

## 3. 架构红线（明确禁止项，V1.1 保留并强化）

1. ❌ 引入服务器、付费 API、第三方收费服务、**外部网络请求**。
2. ❌ 运行时网络请求 / 外链资源 / 跨小工具通信。
3. ❌ 内联脚本、`eval`、WASM、Worker、iframe、`window.open`。
4. ❌ 编造复联5未确认剧情 / 角色 / 关系。
5. ❌ 把不同小工具间通信能力当 V3.0 架构基础（平台不支持）。
6. ❌ `MCU_USER` 单键写入超过 1MB。
7. ❌ 未知版本数据回退空态并覆盖原始存储（V1.1 新增）。
8. ❌ 未回读校验即清理旧键 / 迁移失败即删旧键（V1.1 新增）。
9. ❌ 业务视图绕过 `MCUUser.update()` 直接写入用户状态（V1.1 新增）。
