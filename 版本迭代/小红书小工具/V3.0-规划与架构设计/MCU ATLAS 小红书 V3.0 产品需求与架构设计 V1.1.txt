## 1. 一页结论（5 条内）

1. **V3.0 定位**：由「探索工具」升级为「探索 / 观影 / 互动三大方向并重的漫威综合助手」，四层架构；**不推翻 V2.0**，F1–F6 全部继承。
2. **V1.1 收口重点**：强化「数据迁移与异常恢复」安全边界（未知版本保留、迁移幂等、回读校验后才清旧键、失败保留旧键、逐字段校验），并把用户状态写入收敛到 `MCU_USER` 七个统一业务方法，禁止视图旁路。
3. **底座复用条件具备**：V2.0 的 7 视图 SPA、离线数据管线、`MCUProgress` 三级存储降级可直接作为基座；存储规则本轮已按 `progress.js` 实际代码精确化（含「xhs 读成功但为空不回退 localStorage」的已知边界）。
4. **两处数据缺口仍需前置立项**：人物↔人物关系边（`characters.js` 为 TODO）、离线知识问答题库（全库不存在）。V1.1 优先级已拆分应对：P1 只做「基于共同作品的轻量角色关联」与「基础离线知识问答」，完整网络/题库深度化放 P2。
5. **本文件为规划稿**，存在 1 处 V2.0 状态冲突与多项待确认（见 §8 与风险清单），须 ChatGPT 复审裁定后方可进入开发。

## 4. V3.0 产品架构（四层）

### 4.1 首页控制台
状态驱动动态首页：品牌展示、今日探索推荐、我的观影进度、最近探索记录、继续上次观影路线、探索/观影/互动三区入口。复用现有 SPA 首页区块，**不新增独立页面**。数据来自 `MCU_USER.recentExplore` / `currentRoute` / 派生进度。

### 4.2 探索系统
角色探索（F2 增强）；**基于共同作品的轻量角色关联**（P1，由 `CONTENT.chars` 共演推导，无显式 why）；**完整英雄关系网络**（P2，待人物↔人物关系边数据补齐）；MCU 宇宙时间线（`CONTENT.co`）；作品搜索与资料查询（F2 增强）；随机探索（F3 继承）。

### 4.3 观影系统
上映顺序 / 时间顺序 / 主线精选（F1）、观影进度管理（F5）、观影进度与路线联动（P1，含 `currentRoute` 定位）、个性化观影路线、复联5补课专题（F6）、下一部作品推荐。全部复用 `MCU_CONTENT` + `MCU_ROUTES` + `MCU_SPECIAL_ROUTES`。

### 4.4 互动系统
基础离线知识问答（P1，需新建离线题库）+ 问答结果关联角色/作品（P1）；英雄组队器（P2，`MCU_CAMPS`）、复杂成就系统（P2）、个人漫威档案（P2）、扩展分享卡类型（P2）。**互动结果必须经 `MCU_USER` 业务方法回写并关联角色/作品/进度/成就，不得成为互不相关的小游戏。**

## 5. 统一用户状态与数据架构（V1.1 要点）

- 模型 `MCU_USER` v2，键 `mcu-xhs-user-v2`，由 `mcu-xhs-progress-v1` 迁移；字段精化见交付物③ §2。
- **迁移安全六条**：未知版本保留原始数据且禁止写入覆盖；迁移幂等；新键写入后**重新读取并校验成功才允许清理旧键**；迁移失败保留旧键；损坏数据逐字段校验、局部保留；后端优先级/降级/恢复按 V2.0 实际代码。
- **统一写入机制**：`MCUUser.update(mutator)` 为唯一写入口；七个业务方法（`addToWant` / `removeFromWant` / `markWatched` / `setCurrentRoute` / `recordQuizResult` / `unlockAchievement` / `addRecentExplore`）封装参数校验、重复处理、失败行为与通知；**禁止任何视图绕过写入**。
- 三系统共享同一状态；内容数据（`data.js`）只读单一来源；派生数据不落库；全字段设上限与截断规则；单 key ≤1MB。

## 6. 三条完整功能联动路径（V1.1 要点）

- **路径 A 英雄探索→观影计划**：搜钢铁侠 → 相关角色/关联作品 → 加观影计划 → 更新进度。
- **路径 B 观影计划→互动挑战**：选复联5补课路线 → 看待看 → 更新进度 → 触发问答 → 记录成就。
- **路径 C 知识问答→角色探索**：参加问答 → 看涉及角色/作品 → 进资料 → 加入观影计划。
- V1.1 补充 8 类重复/异常场景：重复加入想看、重复标记已看、路线切换、路线位置失效、答题成绩重复提交、成就重复解锁、Storage 写入失败、未知版本数据。流程图数据操作与交付物③ 完全一致，详见交付物④。

## 10. 验收标准（10 项）

1. 三大系统（探索/观影/互动）能够正常运行。
2. 三系统共享统一作品与角色数据（`data.js` 单一来源）。
3. 观影进度在首页及路线中正确体现（复用 F5 派生 + `currentRoute` 定位）。
4. 三条完整联动路径通过测试，且 8 类重复/异常场景（交付物④）有明确处理。
5. 用户状态按平台能力可靠保存与恢复；**迁移六条安全规则通过专项测试**（含未知版本保留、幂等、回读校验、失败保留旧键）。
6. V2.0 现有功能合理继承（§7），F4 基础分享能力未整体推迟。
7. 分享卡内容准确、视觉统一。
8. 不存在未经授权的网络、跳转及存储调用（离线纯本地，禁跨工具通信 / 服务端 / 付费 API）。
9. 复联5未确认剧情、角色及关系不得编造（沿用 D-20261110-04）。
10. **自动化测试**（Node 单测 / 构建审计 / P0 基础兼容性测试）与**真机验收**（用户本人执行，WorkBuddy 不承担）分别列出。
