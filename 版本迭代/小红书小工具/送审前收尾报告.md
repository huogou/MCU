## 3. Storage API 核查结果及兼容方案

### 3.1 核查结论

- 项目内 `minitool-zip-builder` 1.7.0 的 `references/js-api.md` 记载：
  - Storage API 需客户端 **9.46+**；
  - 支持 `setStorage` / `getStorage` / `getStorageInfo` / `removeStorage` / `clearStorage`；
  - `removeStorage` 入参为 `key`，用于删除指定缓存；
  - 单 key 上限 1 MB，小工具总缓存上限 10 MB。
- 同时发现文档版本差异：npm 官方脚手架 `xhs-minitool-creator@1.2.2` 内置技能 1.6.0 的 `jsbridge-api.md` 仅列出 `postNote` / `saveImageToPhotosAlbum` / `openRedPage` / `writeTempFile` 4 个 JSBridge API，**未列 Storage API**。
- 因此本次不硬依赖 `removeStorage`，改为**能力探测**，避免不同客户端 / 文档版本导致功能阻断。

### 3.2 实现与降级顺序

清除进度 `clear()` 的处理顺序：

1. 客户端版本 ≥ 9.46 且存在 `xhs.miniTool.removeStorage`：调用 `removeStorage({ key: 'mcu-xhs-progress-v1' })`。
2. 接口不存在：回退 `setStorage({ key, data: '' })`。
3. `removeStorage` 调用失败（reject）：同样回退 `setStorage({ key, data: '' })`。
4. 无论小红书端结果如何，都执行 `localStorage.removeItem` 并清空内存兜底。
5. `clear()` 捕获异常后仍会触发订阅刷新，返回成功状态，不阻断页面。

返回行为处理：只关注 Promise resolve / reject，不依赖非文档化的业务返回字段。

### 3.3 归零验证

自动化测试已覆盖：

- `removeStorage` 被优先调用且缓存键被删除；
- 清除后已看数、想看数归零；
- 核心 8 部路线进度归零；
- 进度页百分比与首页统计（`shareData().percent`）归零；
- 刷新后仍为空；
- `removeStorage` 失败时降级清除仍生效；
- 无 `removeStorage` 时原兼容路径仍生效。

说明：以上为 Node 模拟容器环境测试，真机 `removeStorage` 行为仍需用户在小红书 App 内验证。

5. 平台上传、预览、审核与上线。

### 风险与说明

1. **Storage 文档版本差异**：不同版本的官方资料对 Storage API 是否列入 JSBridge 的记载不一致。当前实现为能力探测 + 多级降级，不硬依赖新接口；但真机行为未验证。
2. **极端情况下清除不彻底**：若 `removeStorage` 与 `setStorage` 同时失败，且 localStorage 也不可用，本机旧数据可能在下次启动回流；当前 UI 不会白屏或阻断其他功能，但该场景无法离线彻底解决。
3. **中文名为辅助称呼**：「复仇者联盟5」不是官方确认译名，已在专题页明示；送审文案如需官方中文名，仍应以片方公布为准。
4. **F2 / F3 仅做页面级回归**：本次未改动其业务逻辑，但未逐项复测全部搜索与随机组合。
5. **本地结果不等于平台结果**：本报告所有 PASS 均为本地自动化或本地浏览器结果，不代表真机通过或平台审核通过。
