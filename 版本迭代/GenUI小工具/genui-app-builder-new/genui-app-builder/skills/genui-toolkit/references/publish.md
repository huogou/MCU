# Publish

## CLI 参数

| 参数 | 语义 |
| --- | --- |
| `-a, --appkey` | 已有应用 AppKey；新增应用不传 |
| `-p, --project-path` | 本地 HTML 或 ZIP；新增应用必填，已有应用未传时复用线上源码 |
| `-n, --name` | 新增应用必填；最多 10 字；已有应用未传时复用线上名称 |
| `-l, --logo` | 新增应用必填；不超过 5MB，且必须为 256 × 256；已有应用未传时复用线上 Logo |
| `--poster` | 封面；新增应用必填；16:9，PNG/JPG/JPEG，不超过 2MB；已有应用未传时复用线上封面 |
| `-b, --brief` | 新增应用必填；最多 15 字；已有应用未传时复用线上简介 |
| `-d, --description` | 新增应用必填；应用摘要，最多 50 字；已有应用未传时复用线上摘要 |

新增应用必须提供除 AppKey 外的六项。已有应用必须提供 AppKey，并至少提供六个更新字段中的一项。

## 发布产物

用户明确提供 ZIP 时校验后直接使用。否则读取入口 HTML，分析 HTML 的 `src`/`href`/`srcset`、内联和本地 CSS 的 `url()`/`@import`、本地 JavaScript 的静态导入及可可靠识别的资源路径；忽略锚点、Data URL、Blob URL 和无需随包提交的协议链接。

- 没有独立本地依赖：使用入口 HTML 绝对路径。
- 存在独立本地 CSS、JS、图片、字体或 JSON：自动生成 ZIP，不询问是否打包。只包含入口及可确定的本地依赖闭包，保持相对目录，根级必须直接包含 `index.html`。
- 引用缺失、越出根目录、使用根绝对路径或依赖无法可靠确定：列出问题并停止，不生成可能不完整的 ZIP。
- 只允许 HTML、CSS、JS、PNG、JPG/JPEG、GIF、WEBP、SVG、WOFF/WOFF2、JSON；排除未引用文件、隐藏文件、`app.json`、已有 ZIP、系统文件和软链接；解压后不超过 8MB。

优先用系统 `zip` 生成标准 deflate ZIP，输出为应用目录同级的 `<应用目录名>-genui.zip`；已存在时使用不冲突的序号名，不覆盖。用 `unzip -l` 校验根入口和清单。完成后说明检测到的代表性依赖、为何直接上传 HTML 会遗漏资源、ZIP 绝对路径，并把它作为 `projectPath`。

## 选择发布类型

- 用户主动提供 AppKey：按已有应用处理。
- 未提供 AppKey：先询问“1. 新增应用；2. 已有应用”，不得根据名称、配置或列表猜测。
- 新增应用：不执行 `genui list`，删除配置中的 AppKey，进入预览、预检与六项参数的合并确认。
- 已有应用：立即执行 `genui list`，展示编号、名称、AppKey 和状态，让用户回复编号或 AppKey。选定后不逐项询问未传字段。

## 新增应用参数确认

从用户输入、配置、应用结构和 HTML 内容准备六项建议。建议必须真实有效，文字与应用内容一致并满足字数限制；Logo 必须是本地图片、不超过 5MB，且分辨率为 256 × 256；封面必须是本地图片、宽高比 16:9、格式为 PNG/JPG/JPEG、不超过 2MB。Logo 与封面都不生成、不编造，必须由用户提供真实本地图片；不符合时先让用户更换或调整，不要继续发布。无法可靠建议时要求用户填写，不要编造。

以六项建议值启动预览并执行 `genui publish --dry-run`，此时不写入 `app.json`。成功后一次展示预览地址、七项最终信息、配置草稿、正式命令和审核提示，并明确询问：“确认发布吗？确认后将立即提交审核。”用户可以确认发布，也可以指出要修改的字段。

用户明确确认发布后，写入并核对 `app.json`，立即以相同参数追加 `--yes` 提交，不再预检或确认。参数变化时更新草稿；展示效果受影响时重新预览，并重新预检、展示和确认。自动发现产物、生成 ZIP 或选择“新增应用”不构成发布确认。

## 已有应用更新

只携带用户本轮明确更新、明确要求沿用配置的字段，以及用户要求发布当前本地产物时确定的 `projectPath`。其余字段从配置中删除，由 CLI 复用线上数据，不逐项询问。没有实际更新时停止并要求用户至少指定一项。

已有应用的最终命令必须显式使用 `genui publish --appkey <选定 AppKey>`，再按需追加本次更新参数；即使 `app.json` 已包含 AppKey，也不能省略命令行的 `--appkey`。执行前核对发布类型、参数表、重新读取的 `app.json` 与精确命令：四处都必须指向同一个 AppKey。任一处缺失或不一致时停止，不得以新增应用方式继续。

## 最终信息与发布确认

使用本地产物且尚未预览时，先完成预览。随后使用完整参数执行：

```bash
genui publish <本次参数> --dry-run
```

`--dry-run` 会执行源码检查、登录和线上应用详情合并，输出实际将提交的完整信息，但不会上传文件或提交审核。已有应用必须显式携带 `--appkey <选定值>`。预检失败时停止；参数变化后必须重新预检。

根据预检结果只展示一次全部七项最终信息，顺序固定。使用 Markdown 表格，每个参数独占一行：

| 参数 | 最终值 | 来源 |
| --- | --- | --- |
| `-a, --appkey` | AppKey 或“未传（新增应用）” | 用户参数、`app.json` 或列表选择 |
| `-p, --project-path` | 实际本地文件或线上源码 | 用户参数、`app.json` 或线上复用 |
| `-n, --name` | 最终名称 | 用户参数、`app.json`、新增应用建议值或线上复用 |
| `-l, --logo` | 实际本地文件或线上 Logo | 用户参数、`app.json`、新增应用建议值或线上复用 |
| `--poster` | 实际本地文件或线上封面 | 用户参数、`app.json`、新增应用建议值或线上复用 |
| `-b, --brief` | 最终简介 | 用户参数、`app.json`、新增应用建议值或线上复用 |
| `-d, --description` | 最终摘要 | 用户参数、`app.json`、新增应用建议值或线上复用 |

最终值必须来自预检输出，不用“未传”或“见上方 `app.json`”代替已复用的线上值。路径较长时，表格内写文件名或简短相对路径，并在表格下用代码块展示完整路径。随后展示完整 `app.json` 和正式命令：移除 `--dry-run`，追加 `--yes`；已有应用必须保留显式 `--appkey <值>`。不要重复或重排参数表。

同时写明发布类型和对象，并提示“一旦发布，需要等待审核通过后才能重新发布”。询问：“确认发布吗？确认后将立即提交审核。”用户明确确认后立即执行正式命令；拒绝则停止。参数变化时重新预检、展示并确认，效果受影响时也重新预览。已有应用不得执行裸 `genui publish --yes`。

## 结果

成功时整理 CLI 实际返回的应用名称、AppKey、状态和消息，并输出“更多详情可到 [https://ziyuan.baidu.com/aitoolset/indexx](https://ziyuan.baidu.com/aitoolset/index) 查看”。失败时指出阶段与原始错误；审核中、权限、上传或提交失败均不自动重试。
