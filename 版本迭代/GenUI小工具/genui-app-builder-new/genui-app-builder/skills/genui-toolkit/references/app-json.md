# app.json

`genui publish` 和 `genui preview` 读取执行目录中的 `app.json`，再用显式 CLI 参数覆盖同名字段。正式提交前确保配置存在；新增应用在用户确认最终信息后创建。只编辑配置时不要求安装 CLI。

## 字段

规范字段为 `appkey`、`projectPath`、`name`、`logo`、`poster`、`brief`、`description`。读取兼容 `appKey`、`project-path`、`desc`，写入统一使用规范字段名；不要写入 `yes` 或 `dry-run`。

```json
{
  "appkey": "existing-appkey",
  "projectPath": "./artifact.zip",
  "name": "应用名称",
  "logo": "./logo.png",
  "poster": "./poster.png",
  "brief": "应用简介",
  "description": "应用摘要"
}
```

`preview` 未传路径时使用当前目录 `app.json` 的 `projectPath`、`name`、`description`；传入 HTML/ZIP 时，也会读取产物同目录的 `app.json` 补充 `name` 和 `description`。`name` 和 `description` 是组件外层展示的标题和描述，均为可选，未配置时 CLI 使用默认文案。

## 发现与校验

依次检查用户指定位置、当前目录、已确定应用目录、当前目录合理深度内与候选应用相邻的位置。一个明确候选自动读取；多个候选列出绝对路径让用户选择。

校验 JSON 对象、字段类型、名称不超过 10 字、简介不超过 15 字、摘要不超过 50 字，以及相对 `projectPath`/`logo`/`poster` 能否从配置目录解析。Logo 必须不超过 5MB，且分辨率必须为 256 × 256；封面必须为 16:9、格式 PNG/JPG/JPEG、不超过 2MB；不符合时先让用户更换或调整，不要继续发布。损坏配置必须停止并报告，不直接覆盖。执行发布时切换到配置所在目录。

## 合并语义

- 用户本轮显式参数覆盖配置。
- 配置中的字段是历史发布输入，不自动视为本次更新内容；最终信息中标注实际采用的来源。
- 已有应用只保留用户本轮明确更新或明确要求沿用配置的字段；其余发布字段从配置中删除，由 CLI 复用线上值。
- 选择的 AppKey 与配置不同，或从新增应用切换到已有应用时，避免跨应用污染：删除旧 AppKey，并删除用户本轮未明确保留的六个更新字段；再写入新 AppKey 和本轮实际更新。
- 选择新增应用时删除 `appkey`/`appKey`。配置中的其他值只能作为建议；本轮重新确认六项后再写入。
- 复用线上值时删除对应规范字段及兼容别名。
- 保留与发布字段无关的其他字段；写入后重新读取并校验。

## 创建时机

没有配置时不询问是否生成。

- 新增应用：最终信息确认后才一次性创建配置；未确认的建议值不得写入。写入后重新读取并核对配置与预检参数。
- 已有应用：选定 AppKey 且确定至少一项实际更新后，创建包含规范字段 `appkey` 和这些更新字段的配置；未传字段不写入，由 CLI 复用线上数据。写入后重新读取，确认 `appkey` 与用户选定值完全一致；缺失或不一致时不得发布。

配置创建后，用户再次修改参数时立即更新同一文件。写配置不等于授权发布。
