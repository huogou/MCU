# 视觉与交互规范

> 本文件定义 GenUI 作品应该达到什么样的视觉与交互质量标准。
>
> 规则强度：**【必须】** / **【禁止】** / **【限制】**。
>
> **读取规则：**
> - 产物的入口、文件类型和目录结构以 `package-format.md` 为准。
> - `assets/components/` 下的组件文件**按需读取**：用到哪个读哪个，没用到不要读。

## 1. 结构形态

作品从上到下由**表头**和**内容**两段组成。内容部分有两种形态，**【必须】** 在设计阶段先确定用哪一种：

| 形态 | 结构 | 适用 | 交互默认值 |
|---|---|---|---|
| A 画布区 + 操作区 | 表头 + 画布区 + 操作区 | 需要参数调节、切换对象的实验 | 默认不交互；需要交互时必须是轻交互 |
| B 整屏画布 | 表头 + 画布区 | 交互直接发生在画布上的实验 | 默认支持轻交互 |

- **【必须】** 形态 A 中画布区**高度占比 ≥ 50%**，操作区不得把画布区挤压到不可辨识。
- **【必须】** 交互控件集中在操作区，不散落在画布区。

骨架来源按形态区分：

- **【必须】** 形态 A 的骨架**直接照搬** `assets/layout.html`：1:1 卡片容器、表头、画布区、操作区的结构与取值都以该文件为准，不自己另起一套。
- **【必须】** 形态 B **参考** `assets/layout.html`：卡片容器与 1:1 比例的实现直接沿用，表头改为浮在画布上的浮层（配色见第 3 节）、不要操作区。该文件未覆盖的部分自行实现，但不重新定义它已经给出的取值。

## 2. 画布与响应式

- **【必须】** 作品整体为 **1:1 正方形**响应式适配，内部元素（Canvas / SVG / 面板）随容器自适应缩放。骨架用 `padding-top: 100%` 撑出比例，容器 `position: absolute; inset: 0`；容器内无滚动条，内容不得溢出容器导致撑出滚动条。
- **【限制】** body 不保留浏览器默认的 padding / margin（默认 `margin: 8px` 会把整张卡片挤偏、出现滚动条），产物里显式写 `body { margin: 0; padding: 0; }`，与 `assets/layout.html` 一致。
- **【必须】** 适配到最小 **360px** 屏宽，小屏下内容可读、交互可用。
- **【必须】** 首帧容器宽高可能为 `0`，绘制前先判断尺寸。

## 3. 表头

- **【必须】** 表头内容为 **小工具 · 项目名称**，其中项目名称不超过 10 个字；高度 **45px**，内间距左右上 15px、下 12px，底部 0.5px 描边。
- **【必须】** 形态 A 的表头**照搬** `assets/layout.html` 的 `.vc-component-header`，不自行调整高度、内间距与描边。配色沿用该文件的 token —— 背景继承卡片的 `--cos-vcard-color-bg`、文字 `--cos-color-text-minor`、底描边 `--cos-color-border-minor`；**禁止**改写成固定 hex。
- **【必须】** 形态 B 的表头浮在画布之上，`layout.html` 未提供这套实现，按**表头覆盖区域下方背景色的感知明度 `B`（0–255，`B = 0.299·R + 0.587·G + 0.114·B`；渐变 / 图像 / 多色时取主色或均值）**取配色，不分明暗两档硬套：
  - 蒙层（表头底部铺一层 10px 均匀模糊的半透明色）：底色 `B ≥ 128` 取 `#FFF`、`B < 128` 取 `#000`；透明度 `alpha = clamp(0.08 + (1 − B/255) × 0.30, 0.08, 0.38)`。
  - 文字 / icon 与底描边：`B ≥ 128` → 文字 `#848691`、底描边 `#DCDDE0` 60%；`B < 128` → 文字 `#FFF`、底描边 `#FFF` 20%。
  - 浮层配色由画布背景决定，不随 `prefers-color-scheme` 切换。
- **【必须】** 需要说明时在实验名称后放提示 icon（16×16px，与文字间距 3px），点击/悬浮弹出气泡。形态 A 的骨架里已带这套 icon + 气泡实现（内联 SVG + 卡片内避让）。
- **【必须】** 表头右侧是操作区，只能放以 icon 呈现的操作按钮；最多 **3 个**，icon 均为 18×18px，相邻 icon 间距 **18px**，整体靠右对齐且距表头右边缘 15px。形态 A **照搬** `layout.html` 的 `.vc-component-header-actions` 与 `.vc-component-control-btn`（颜色 `--cos-color-text`）；形态 B 按上面的明度取值。
- **【禁止】** 在表头右侧操作区放置操作按钮以外的任何可见文案或内容，包括标题、说明、状态、计数、单位、标签和装饰元素。按钮仍须提供不可见的无障碍名称（如 `aria-label`）。
- **【必须】** 重置按钮**必选**，每个作品都要有，框架骨架已写死、**禁止删除**。点击把动画、轨迹、临时高亮、运动状态与各项参数一并恢复到初始态；点击时 icon 旋转一圈作为反馈（`layout.html` 已带这段实现）。
- **【限制】** 表头右侧的声音按钮是**可选**的，只在作品有声音时才放；作品默认静音，无声音时**禁止**加声音按钮。
- **【必须】** 声音按钮点击后要同步切换实际声音和 icon：静音态用 `cos-icon-mute`，开启态用 `cos-icon-volume`；`layout.html` 已带这段实现。
- **【限制】** 表头右侧的播放按钮是**可选**的，只在存在可播放、暂停的持续过程时才放，默认非播放态；静态内容或短暂的一次性动画**禁止**加播放按钮。
- **【必须】** 播放按钮点击后要同步切换实际播放状态和 icon：非播放态用 `cos-icon-play-circle`，播放态用 `cos-icon-pause-circle`；播放结束或重置后恢复为播放 icon，`layout.html` 已带这段实现。

## 4. 画布区

画布区内的展示样式按场景自定义，不限制内容形态与布局。

- **【必须】** 主内容不要显小，四周不留过多无意义边距。
- **【必须】** 画布区内的文字、面板、交互控件（坐标轴粗细与颜色、坐标文字字号、公式面板等）沿用第 7 节的 token 与 `assets/components/` 的组件规格，不自成一套。

## 5. 组件

### 5.1 参考实现

`assets/components/` 下是各控件的参考实现（结构 + 样式 + 交互逻辑）。**样式规格以文件为准，本文件只写数量、位置与交互约束。**

| 组件 | 文件 | 说明 |
|---|---|---|
| 按钮 | `assets/components/button.html` | 主要 / 边框 / 禁用 / 加载态 |
| 滑动条 | `assets/components/slider.html` | 数值范围选择 |
| 复选框 | `assets/components/checkbox.html` | 选中 / 禁用 |
| 单选框 | `assets/components/radio.html` | 单选组 |
| 下拉选择 | `assets/components/select-pc.html` | 原地展开面板，支持键盘操作与前缀插槽 |
| 标签页 | `assets/components/tabs.html` | 多标签切换 |
| 开关 | `assets/components/switcher.html` | 二态切换 |
| 步骤进度条 | `assets/components/step-progress.html` | 上一步 / 下一步 / 重置 |
| 提示气泡 | `assets/components/tooltip.html` | 依附触发点的说明气泡，自动避让与翻转 |
| 图例 | `assets/components/legend.html` | 画布内容的图例说明 |

- **【必须】** 直接照搬样式，不做样式覆盖；PC 与移动端差异、贴边处理都以文件为准。
- **【禁止】** 自造上表已有组件的替代实现；表里没有的控件才自行实现。
- **【必须】** 组件文件中 // 触发震动 注释处无需实现震动

### 5.2 Tabs

- **【必须】** 整个作品只能使用一次 Tabs；需要多个说明功能应当精简。
- **【必须】** 各 Tab 下操作区高度保持一致，避免切换时布局跳动。滑动条数量不一致时，把滑动条多的那个 Tab 两两并排压缩。
- **【禁止】** 用按钮实现 Tab 切换效果；按钮只用于开始动画等操作功能。

### 5.3 滑动条

- **【必须】** 滑动时出现数据气泡（tooltip），松手后消失，气泡内数据不带单位。
- **【必须】** 每个 Tab（无 Tabs 时为整个作品）的滑动条**最多 4 个**。
- **【必须】** 排列方式按优先级判断：
  1. 有 Tabs 或有底部按钮，且滑动条 ≥ 2 个 → 两两一排
  2. 无 Tabs 无底部按钮，且滑动条 ≥ 3 个 → 两两一排
  3. 其余情况 → 每个滑动条单独一排
- **【必须】** 两两一排时，行间距 9px、列间距 22px；滑动条为奇数个时最后一个铺满整行。

### 5.4 底部操作按钮

- **【禁止】** 按钮**超过 2 个**。
- **【必须】** 只有 1 个按钮时使用 `plain` 样式，**禁止**使用 `primary`。
- **【必须】** 必须有 2 个按钮时，主操作用 `primary`，次操作用 `plain`。
- **【禁止】** 按钮内添加图标，文案为纯文字。

## 6. 交互

### 6.1 交互深度

- **【必须】** 每个控件操作都有即时、可观察的视觉反馈。
- **【必须】** 无死状态：任意操作序列之后作品仍可继续使用。

### 6.2 手势

- **【禁止】** 把上下滑动用作作品内的交互手势——上下方向要留给页面滚动。

## 7. 设计 token 与命名

组件文件里大量使用 `var(--cos-*)` 形式的设计 token（颜色、间距、圆角、字号、字重）。

- **【必须】** token 的命名与语义遵循 baidu cosui design token，不自造 `--cos-*` 名称，也不改写既有 token 的语义。
- **【禁止】** 在产物内重新定义 `--cos-*`，包括另写一份 `:root` 覆盖取值。
- **【必须】** 有对应 token 的颜色一律用 token，不改写成固定 hex。
- **【必须】** 深浅两种配色环境都要可读：颜色走 token，深浅切换由 token 负责，不自行给 `--cos-*` 加 `prefers-color-scheme` 覆盖。

## 8. 多端适配

- **【必须】** 移动端 WebView 与 PC 浏览器均正常渲染。

## 9. 信息密度

- **【必须】** 排版无重叠、无溢出、无文字截断。
- **【必须】** 文字实际渲染字号**不低于 14px**（含坐标刻度、图例、说明、参数值、tooltip；token / `calc()` 换算、缩放后的像素值也要 ≥ 14px）。**【限制】** 仅形态 B 沉浸态的非主功能文案可豁免，但 360px 屏宽下仍须可辨识。
- **【必须】** 无大面积无意义空白，也不堆砌信息。

## 10. 可访问性

- **【必须】** 深浅两种配色环境下内容均可读。
